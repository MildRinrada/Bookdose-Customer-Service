# Bookdose Customer Service

โปรแกรมเว็บภาษาไทยสำหรับดูแลลูกค้าหลายองค์กร เปิดใช้งานบนเครื่องได้ทันทีด้วย Python 3.10 ขึ้นไป ไม่ต้องติดตั้งแพ็กเกจเพิ่ม และไม่ต้องใช้อินเทอร์เน็ตระหว่างใช้งานบนเครื่อง

## เปิดใช้งาน

**macOS:** ดับเบิลคลิก `Start Bookdose.command` แล้วเปิด **http://localhost:8787** ในเบราว์เซอร์

**Windows:** ติดตั้ง Python 3.10 ขึ้นไป แล้วดับเบิลคลิก `Start Bookdose.bat`

หรือเปิด Terminal ในโฟลเดอร์โปรแกรมแล้วรัน:

```sh
python3 app.py
```

เปิดหน้าต่าง Terminal นี้ค้างไว้ระหว่างใช้งาน ปิดโปรแกรมด้วย `Ctrl+C` ข้อมูลจะยังอยู่เมื่อเปิดใหม่ ถ้าพอร์ต 8787 ถูกใช้อยู่ ให้ใช้ `python3 app.py --port 8788` แล้วเปิด http://localhost:8788

ครั้งแรกจะพบหน้าสร้างผู้ดูแล กรอกชื่อ อีเมล รหัสผ่านอย่างน้อย 10 ตัวอักษร ชื่อองค์กร และรหัสองค์กร เช่น `bookdose` บัญชีแรกเป็นทั้งผู้ดูแลแพลตฟอร์มและผู้ดูแลองค์กรแรก ไม่มีบัญชีหรือรหัสผ่านเริ่มต้นที่ฝังไว้ในโปรแกรม

เลือกเพิ่มข้อมูลตัวอย่างได้ จะมี 5 เคสและบทความภายใน 2 บทความ หากต้องการเริ่มใช้งานด้วยข้อมูลจริงทันที ให้เอาเครื่องหมายเพิ่มข้อมูลตัวอย่างออกก่อนสร้างองค์กร

## ขั้นตอนใช้งานประจำวัน

1. **ตั้งค่าองค์กร:** เพิ่มทีมและสมาชิก กำหนด SLA และข้อความต้อนรับ สมาชิกใหม่ได้รับบัญชีใช้งานทันที ผู้ดูแลแจ้งรหัสผ่านให้เจ้าตัวด้วยช่องทางที่เหมาะสม โปรแกรมไม่ส่งอีเมลเชิญ
2. **เปิดหน้าช่วยเหลือ:** ใช้ปุ่มทางซ้าย หรือเปิด `/support/bookdose` ตามรหัสองค์กร ลูกค้ากรอกชื่อ อีเมล เรื่อง และรายละเอียด
3. **รับเรื่องในกล่องข้อความ:** เลือกบทสนทนา ตอบลูกค้า หรือเพิ่มบันทึกภายใน ถ้าต้องติดตามงานให้กด **เปิดเคส** บทสนทนากับเคสเป็นข้อมูลคนละชุด คำถามที่ตอบจบได้ไม่จำเป็นต้องเปิดเคส
4. **จัดการเคส:** เลือกทีม ผู้รับผิดชอบ สถานะ และความเร่งด่วน แล้วกดบันทึก เคสที่เจ้าหน้าที่สร้างเองใช้บันทึกภายใน ส่วนเคสที่มาจาก Web Support ตอบถึงหน้าติดตามของลูกค้าได้
5. **ติดตามฝั่งลูกค้า:** หลังส่งเรื่อง ระบบให้ลิงก์เฉพาะสำหรับกลับมาอ่านคำตอบและส่งข้อความเพิ่ม เก็บลิงก์นี้ไว้ ข้อความอัปเดตทุก 10 วินาทีเมื่อเปิดหน้าอยู่
6. **ปิดงาน:** เปลี่ยนสถานะเป็นแก้ไขแล้วหรือปิดเคส ลูกค้าส่งข้อความเพิ่มในเรื่องเดิมจะเปิดเคสกลับมาเป็นกำลังดำเนินการโดยอัตโนมัติ
7. **รายงาน:** ดูสถานะ ภาระงาน เวลาตอบเฉลี่ย และส่งออก CSV สำหรับ Excel โดยรายงานใช้เคสทั้งหมดตามสิทธิ์ ไม่ได้จำกัดตามตัวกรองบนหน้าตาราง

ไฟล์แนบรองรับ PNG, JPG, PDF และ TXT สูงสุด 3 ไฟล์ต่อข้อความ รวมไม่เกิน 5 MB ไฟล์ในบันทึกภายในเปิดได้เฉพาะเจ้าหน้าที่ที่มีสิทธิ์ในบทสนทนานั้น

คลังความรู้เลือกได้ระหว่าง **ภายในองค์กร** และ **เผยแพร่ให้ลูกค้า** บทความสาธารณะจะแสดงในหน้าช่วยเหลือขององค์กร

## หลายองค์กรและสิทธิ์

| บทบาท | สิทธิ์ |
| --- | --- |
| ผู้ดูแลแพลตฟอร์ม | สร้างองค์กร เปิดหรือระงับองค์กร และดูประวัติแพลตฟอร์ม ไม่มีสิทธิ์อ่านเคสองค์กรอื่นโดยอัตโนมัติ |
| ผู้ดูแลองค์กร | จัดการงานทุกทีม สมาชิก การตั้งค่า บทความ ประวัติ และสำรองข้อมูลองค์กร |
| หัวหน้าทีม | ดูและจัดการงานทุกทีมในองค์กร แก้ไขลูกค้าและบทความ ดูประวัติ ไม่จัดการสมาชิกหรือการตั้งค่า |
| เจ้าหน้าที่ | ดูเคส บทสนทนา ไฟล์ และรายงานเฉพาะทีม ดูลูกค้าที่ตนสร้างหรือเกี่ยวข้องกับงานของทีม อ่านคลังความรู้ขององค์กร |
| ลูกค้าผ่าน Web Support | อ่านและตอบเฉพาะบทสนทนาที่มีลิงก์ติดตาม อ่านบทความสาธารณะ ไม่เห็นบันทึกภายใน |

ผู้ดูแลแพลตฟอร์มสร้างองค์กรใหม่และระบุอีเมลผู้ดูแลองค์กรได้ หากอีเมลมีบัญชีอยู่แล้ว จะเพิ่มบัญชีเดิมเป็นผู้ดูแลในองค์กรใหม่ โดยไม่เปลี่ยนรหัสผ่าน บัญชีหนึ่งจึงสลับได้หลายองค์กรผ่านเมนูซ้ายบน สมาชิกทั่วไปที่เพิ่มจากหน้าตั้งค่าต้องใช้อีเมลบัญชีใหม่ในรุ่นนี้

การเปลี่ยนสถานะสมาชิกหรือระงับองค์กรมีผลในการเรียก API ครั้งถัดไป ข้อมูลที่แสดงหรือดาวน์โหลดไปก่อนหน้านั้นไม่สามารถเรียกคืนได้ การเปลี่ยนรหัสผ่านจากเมนูบัญชีจะออกจากเซสชันอื่นทั้งหมด

## การเก็บข้อมูล

```text
data/
  control.sqlite3             บัญชี เซสชัน องค์กร และสมาชิก
  tenants/<tenant-id>.sqlite3  ฐานข้อมูลงานบริการแยกไฟล์รายองค์กร
  files/<tenant-id>/<file-id>  ไฟล์แนบส่วนตัวรายองค์กร
```

รุ่นนี้ใช้ **SQLite แยกฐานข้อมูลรายองค์กร** เพื่อเปิดใช้บนเครื่องได้ทันที จึงไม่ได้ใช้ PostgreSQL/RLS ตามสถาปัตยกรรมเป้าหมายในเอกสารต้นทาง ทุก API ตรวจสมาชิก สถานะองค์กร บทบาท และทีมที่ฝั่งเซิร์ฟเวอร์ ก่อนเลือกฐานข้อมูลและตรวจสิทธิ์ทรัพยากร ลูกค้าที่แจ้งอีเมลเหมือนกันไม่ถูกนำประวัติมารวมกันโดยอัตโนมัติ

รหัสผ่านเก็บด้วย PBKDF2-SHA256 และ salt เฉพาะบัญชี เซสชันเจ้าหน้าที่หมดอายุใน 12 ชั่วโมง ใช้คุกกี้ HttpOnly + SameSite และ CSRF token ลิงก์ติดตามลูกค้าเป็น bearer token แบบสุ่ม อยู่ใน URL fragment และส่งผ่าน header ฐานข้อมูลเก็บเฉพาะค่าแฮช ลิงก์ผู้ติดต่อไม่มีระบบหมดอายุหรือกู้ลิงก์ผ่านอีเมลในรุ่นนี้

## สำรองและกู้คืน

ผู้ดูแลองค์กรดาวน์โหลดฐานข้อมูลและไฟล์แนบขององค์กรตนเองได้จาก **ตั้งค่าองค์กร → สำรองข้อมูลองค์กร** ZIP นี้เหมาะสำหรับสำรองหรือส่งออกข้อมูลเฉพาะองค์กร ไม่มีบัญชีสมาชิกจากฐานข้อมูลแพลตฟอร์ม และไม่ใช้กับคำสั่งกู้คืนทั้งระบบด้านล่าง

สำรองทั้งระบบ: หยุดโปรแกรมด้วย `Ctrl+C` เพื่อไม่ให้เกิดการเปลี่ยนแปลงระหว่างสำรองหลายฐานข้อมูล แล้วรัน:

```sh
python3 app.py --backup backups/bookdose-2026-09-07.zip
```

คำสั่งจะไม่เขียนทับไฟล์สำรองที่มีชื่ออยู่แล้ว ให้ตั้งชื่อใหม่ในแต่ละครั้ง ไฟล์สำรองเก็บฐานข้อมูลและไฟล์แนบที่อ้างอิงจาก snapshot

กู้คืนทั้งระบบไปยังโฟลเดอร์ใหม่ที่ยังไม่มีข้อมูล:

```sh
BOOKDOSE_DATA=./restored-data python3 app.py --restore backups/bookdose-2026-09-07.zip
BOOKDOSE_DATA=./restored-data python3 app.py
```

บน Windows ใช้ `set BOOKDOSE_DATA=restored-data` ก่อนรันคำสั่ง Python ไม่มีการเขียนทับฐานข้อมูลเดิมระหว่างกู้คืน เจ้าหน้าที่ทุกบัญชีต้องล็อกอินใหม่หลังการกู้คืน เก็บ ZIP ในพื้นที่ที่จำกัดผู้เข้าถึง เพราะมีข้อมูลลูกค้าและบันทึกภายใน ไฟล์สำรองไม่ได้เข้ารหัส

## ขอบเขตของรุ่นนี้

พร้อมใช้เป็นระบบหลักบนเครื่อง: การเข้าใช้และสิทธิ์หลายองค์กร, Web Support, Inbox, เคส, มอบหมายทีมและเจ้าหน้าที่, ไฟล์แนบ, รายชื่อลูกค้า, SLA, คำตอบสำเร็จรูป, คลังความรู้, รายงาน CSV, Audit, สำรองและกู้คืนทั้งระบบ

SLA ใช้เวลาต่อเนื่อง 24 ชั่วโมง ไม่ใช้ปฏิทินวันทำการ วันหยุด หรือหยุดนับระหว่างรอลูกค้า การตั้งค่า SLA ใหม่มีผลเฉพาะเคสที่สร้างใหม่ การเปิดเคสเดิมอีกครั้งใช้กำหนดเวลาเดิม การแจ้งเตือนในรุ่นนี้แสดงผ่านเคสเกิน SLA และหน้าภาพรวม

**ยังไม่รวม:** LINE และ Email จริง, outbound worker / outbox, SSO, AI, การส่งแจ้งเตือนภายนอก, สแกนไวรัสไฟล์แนบ, กฎ workflow แบบกำหนดเอง, แพ็กเกจและโควตารายองค์กร, support access grant แบบหมดอายุ, การลบองค์กรและ retention, การกู้คืนเฉพาะองค์กรผ่านหน้าจอ, PostgreSQL/RLS และระบบสำรองอัตโนมัติ รายการเหล่านี้ไม่ได้แสดงว่าเชื่อมต่อสำเร็จบนหน้าจอ

โปรแกรมเริ่มที่ `127.0.0.1` จึงใช้ได้เฉพาะเครื่องนี้ ลิงก์ `localhost` ที่ส่งให้ผู้อื่นจะไม่ชี้มาที่เครื่องของคุณ การเปิดให้ทีม/ลูกค้าภายนอกใช้งานต้องมีโฮสต์หรือโดเมน HTTPS และการตั้งค่า deployment เพิ่ม รุ่นนี้ยังไม่ได้ตั้งค่าขึ้นระบบออนไลน์ `--host 0.0.0.0` ใช้เปิดรับในเครือข่ายที่ตั้งใจอนุญาตเท่านั้น ส่วน `--secure-cookies` ใช้เมื่อมี HTTPS reverse proxy แล้ว เซิร์ฟเวอร์ Python ที่ให้มาเหมาะกับการใช้งานภายในขนาดเล็ก ไม่ได้ผ่านการทดสอบรับโหลดระดับแพลตฟอร์มสาธารณะ

## ทดสอบ

```sh
python3 -m unittest discover -s tests -v
node --check static/app.js
```

การทดสอบใช้โฟลเดอร์ชั่วคราว ไม่แตะข้อมูลจริง ครอบคลุมการรับเรื่องและตอบกลับ, บันทึกภายใน/ไฟล์, ขอบเขตองค์กรและทีม, ถอนสิทธิ์, ระงับองค์กร, CSRF, ลิงก์ลูกค้า, บทความสาธารณะ, รหัสผ่าน, CSV, การสร้างเคสพร้อมกัน และสำรอง/กู้คืน
