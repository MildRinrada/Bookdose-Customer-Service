# Bookdose Customer Service

โปรแกรมเว็บภาษาไทยสำหรับดูแลลูกค้าหลายองค์กร เปิดใช้งานบนเครื่องได้ทันทีด้วย Python 3.10 ขึ้นไป ไม่ต้องติดตั้งแพ็กเกจเพิ่ม ระบบหลักใช้งานออฟไลน์ได้ ส่วน AI, LINE และ Email ต้องใช้อินเทอร์เน็ตและบัญชีบริการขององค์กร

## เปิดใช้งาน

**macOS:** ดับเบิลคลิก `Start Bookdose.command` แล้วเปิด **http://localhost:8787** ในเบราว์เซอร์

**Windows:** ติดตั้ง Python 3.10 ขึ้นไป แล้วดับเบิลคลิก `Start Bookdose.bat`

หรือเปิด Terminal ในโฟลเดอร์โปรแกรมแล้วรัน:

```sh
python3 app.py
```

เปิดหน้าต่าง Terminal นี้ค้างไว้ระหว่างใช้งาน ปิดโปรแกรมด้วย `Ctrl+C` ข้อมูลจะยังอยู่เมื่อเปิดใหม่ ถ้าพอร์ต 8787 ถูกใช้อยู่ ให้ใช้ `python3 app.py --port 8788` แล้วเปิด http://localhost:8788

ครั้งแรกจะพบหน้าสร้างผู้ดูแล กรอกชื่อ อีเมล รหัสผ่านอย่างน้อย 10 ตัวอักษร ชื่อองค์กร และรหัสองค์กร เช่น `bookdose` บัญชีแรกเป็นทั้งผู้ดูแลแพลตฟอร์มและผู้ดูแลองค์กรแรก ไม่มีบัญชีหรือรหัสผ่านเริ่มต้นที่ฝังไว้ในโปรแกรม

เลือกเพิ่มข้อมูลตัวอย่างได้ จะมี 5 เคสและบทความภายใน 2 บทความ หากต้องการเริ่มใช้งานด้วยข้อมูลจริงทันที ให้เอาเครื่องหมายเพิ่มข้อมูลตัวอย่างออกก่อนสร้างองค์กร

## ขั้นตอนใช้งานประจำวัน

1. **ตั้งค่าองค์กร:** เพิ่มทีมและสมาชิก กำหนด SLA และข้อความต้อนรับ สมาชิกใหม่ได้รับบัญชีใช้งานทันที ผู้ดูแลแจ้งรหัสผ่านให้เจ้าตัวด้วยช่องทางที่เหมาะสม โปรแกรมไม่ส่งอีเมลเชิญ
2. **เปิดหน้าช่วยเหลือ:** ใช้ปุ่มทางซ้าย หรือเปิด `/support/bookdose` ตามรหัสองค์กร ลูกค้ากรอกชื่อ อีเมล เรื่อง และรายละเอียด
3. **รับเรื่องในกล่องข้อความ:** เลือกบทสนทนา ตอบลูกค้า หรือเพิ่มบันทึกภายใน ถ้าต้องติดตามงานให้กด **เปิดเคส** บทสนทนากับเคสเป็นข้อมูลคนละชุด คำถามที่ตอบจบได้ไม่จำเป็นต้องเปิดเคส
4. **จัดการเคส:** เลือกทีม ผู้รับผิดชอบ สถานะ และความเร่งด่วน แล้วกดบันทึก เคสที่เจ้าหน้าที่สร้างเองใช้บันทึกภายใน ส่วนเคสที่มาจาก Web Support ตอบถึงหน้าติดตามของลูกค้าได้
5. **ติดตามฝั่งลูกค้า:** หลังส่งเรื่อง ระบบให้ลิงก์เฉพาะสำหรับกลับมาอ่านคำตอบและส่งข้อความเพิ่ม เก็บลิงก์นี้ไว้ ข้อความอัปเดตทุก 10 วินาทีเมื่อเปิดหน้าอยู่
6. **ปิดงาน:** เปลี่ยนสถานะเป็นแก้ไขแล้วหรือปิดเคส ลูกค้าส่งข้อความเพิ่มในเรื่องเดิมจะเปิดเคสกลับมาเป็นกำลังดำเนินการโดยอัตโนมัติ
7. **รายงาน:** ดูสถานะ ภาระงาน เวลาตอบเฉลี่ย และส่งออก CSV สำหรับ Excel โดยรายงานใช้เคสทั้งหมดตามสิทธิ์ ไม่ได้จำกัดตามตัวกรองบนหน้าตาราง

ไฟล์แนบรองรับ PNG, JPG, PDF และ TXT สูงสุด 3 ไฟล์ต่อข้อความ รวมไม่เกิน 5 MB ไฟล์ในบันทึกภายในเปิดได้เฉพาะเจ้าหน้าที่ที่มีสิทธิ์ในบทสนทนานั้น

คลังความรู้เลือกได้ระหว่าง **ภายในองค์กร** และ **เผยแพร่ให้ลูกค้า** บทความสาธารณะจะแสดงในหน้าช่วยเหลือขององค์กร

## หลายองค์กรและสิทธิ์

| บทบาท | สิทธิ์ |
| --- | --- |
| ผู้ดูแลแพลตฟอร์ม | สร้างองค์กร เปิดหรือระงับองค์กร และดูประวัติแพลตฟอร์ม ไม่มีสิทธิ์อ่านเคสองค์กรอื่นโดยอัตโนมัติ |
| ผู้ดูแลองค์กร | จัดการงานทุกทีม สมาชิก การตั้งค่า บทความ ประวัติ และสำรองข้อมูลองค์กร |
| หัวหน้าทีม | ดูและจัดการงานทุกทีมในองค์กร แก้ไขลูกค้าและบทความ ดูประวัติ ไม่จัดการสมาชิกหรือการตั้งค่า |
| เจ้าหน้าที่ | ดูเคส บทสนทนา ไฟล์ และรายงานเฉพาะทีม ดูลูกค้าที่ตนสร้างหรือเกี่ยวข้องกับงานของทีม อ่านคลังความรู้ขององค์กร |
| ลูกค้าผ่าน Web Support | อ่านและตอบเฉพาะบทสนทนาที่มีลิงก์ติดตาม อ่านบทความสาธารณะ ไม่เห็นบันทึกภายใน |

ผู้ดูแลแพลตฟอร์มสร้างองค์กรใหม่และระบุอีเมลผู้ดูแลองค์กรได้ หากอีเมลมีบัญชีอยู่แล้ว จะเพิ่มบัญชีเดิมเป็นผู้ดูแลในองค์กรใหม่ โดยไม่เปลี่ยนรหัสผ่าน บัญชีหนึ่งจึงสลับได้หลายองค์กรผ่านเมนูซ้ายบน สมาชิกทั่วไปที่เพิ่มจากหน้าตั้งค่าต้องใช้อีเมลบัญชีใหม่ในรุ่นนี้

การเปลี่ยนสถานะสมาชิกหรือระงับองค์กรมีผลในการเรียก API ครั้งถัดไป ข้อมูลที่แสดงหรือดาวน์โหลดไปก่อนหน้านั้นไม่สามารถเรียกคืนได้ การเปลี่ยนรหัสผ่านจากเมนูบัญชีจะออกจากเซสชันอื่นทั้งหมด

## การเก็บข้อมูล

```text
data/
  control.sqlite3             บัญชี เซสชัน องค์กร และสมาชิก
  tenants/<tenant-id>.sqlite3  ฐานข้อมูลงานบริการแยกไฟล์รายองค์กร
  files/<tenant-id>/<file-id>  ไฟล์แนบส่วนตัวรายองค์กร
  secrets/<tenant-id>.openai-key  API Key รายองค์กร ไม่รวมใน Git หรือไฟล์สำรอง
```

รุ่นนี้ใช้ **SQLite แยกฐานข้อมูลรายองค์กร** เพื่อเปิดใช้บนเครื่องได้ทันที จึงไม่ได้ใช้ PostgreSQL/RLS ตามสถาปัตยกรรมเป้าหมายในเอกสารต้นทาง ทุก API ตรวจสมาชิก สถานะองค์กร บทบาท และทีมที่ฝั่งเซิร์ฟเวอร์ ก่อนเลือกฐานข้อมูลและตรวจสิทธิ์ทรัพยากร ลูกค้าที่แจ้งอีเมลเหมือนกันไม่ถูกนำประวัติมารวมกันโดยอัตโนมัติ

รหัสผ่านเก็บด้วย PBKDF2-SHA256 และ salt เฉพาะบัญชี เซสชันเจ้าหน้าที่หมดอายุใน 12 ชั่วโมง ใช้คุกกี้ HttpOnly + SameSite และ CSRF token ลิงก์ติดตามลูกค้าเป็น bearer token แบบสุ่ม อยู่ใน URL fragment และส่งผ่าน header ฐานข้อมูลเก็บเฉพาะค่าแฮช ลิงก์ผู้ติดต่อไม่มีระบบหมดอายุหรือกู้ลิงก์ผ่านอีเมลในรุ่นนี้

## สำรองและกู้คืน

ผู้ดูแลองค์กรดาวน์โหลดฐานข้อมูลและไฟล์แนบขององค์กรตนเองได้จาก **ตั้งค่าองค์กร → สำรองข้อมูลองค์กร** ZIP นี้เหมาะสำหรับสำรองหรือส่งออกข้อมูลเฉพาะองค์กร ไม่มีบัญชีสมาชิกจากฐานข้อมูลแพลตฟอร์ม และไม่ใช้กับคำสั่งกู้คืนทั้งระบบด้านล่าง

สำรองทั้งระบบ: หยุดโปรแกรมด้วย `Ctrl+C` เพื่อไม่ให้เกิดการเปลี่ยนแปลงระหว่างสำรองหลายฐานข้อมูล แล้วรัน:

```sh
python3 app.py --backup backups/bookdose-2026-09-07.zip
```

คำสั่งจะไม่เขียนทับไฟล์สำรองที่มีชื่ออยู่แล้ว ให้ตั้งชื่อใหม่ในแต่ละครั้ง ไฟล์สำรองเก็บฐานข้อมูลและไฟล์แนบที่อ้างอิงจาก snapshot

กู้คืนทั้งระบบไปยังโฟลเดอร์ใหม่ที่ยังไม่มีข้อมูล:

```sh
BOOKDOSE_DATA=./restored-data python3 app.py --restore backups/bookdose-2026-09-07.zip
BOOKDOSE_DATA=./restored-data python3 app.py
```

บน Windows ใช้ `set BOOKDOSE_DATA=restored-data` ก่อนรันคำสั่ง Python ไม่มีการเขียนทับฐานข้อมูลเดิมระหว่างกู้คืน เจ้าหน้าที่ทุกบัญชีต้องล็อกอินใหม่หลังการกู้คืน เก็บ ZIP ในพื้นที่ที่จำกัดผู้เข้าถึง เพราะมีข้อมูลลูกค้าและบันทึกภายใน ไฟล์สำรองไม่ได้เข้ารหัส

## ขอบเขตของรุ่นนี้

พร้อมใช้เป็นระบบหลักบนเครื่อง: การเข้าใช้และสิทธิ์หลายองค์กร, Web Support, Inbox, เคส, มอบหมายทีมและเจ้าหน้าที่, ไฟล์แนบ, รายชื่อลูกค้า, SLA, คำตอบสำเร็จรูป, คลังความรู้, รายงาน CSV, Audit, สำรองและกู้คืนทั้งระบบ รวมถึง LINE OA, IMAP/SMTP Email พร้อมคิวส่ง และ AI ช่วยร่างคำตอบกับ Chatbot บน Web Support เมื่อตั้งค่าบัญชีบริการแล้ว

SLA ใช้เวลาต่อเนื่อง 24 ชั่วโมง ไม่ใช้ปฏิทินวันทำการ วันหยุด หรือหยุดนับระหว่างรอลูกค้า การตั้งค่า SLA ใหม่มีผลเฉพาะเคสที่สร้างใหม่ การเปิดเคสเดิมอีกครั้งใช้กำหนดเวลาเดิม การแจ้งเตือนในรุ่นนี้แสดงผ่านเคสเกิน SLA และหน้าภาพรวม

**ยังไม่รวม:** Email OAuth, LINE group chat และการส่งไฟล์ออก LINE, Chatbot อัตโนมัติบน LINE/Email, SSO, การส่งแจ้งเตือนภายนอก, สแกนไวรัสไฟล์แนบ, กฎ workflow แบบกำหนดเอง, แพ็กเกจและโควตาทรัพยากรทั่วไป, support access grant แบบหมดอายุ, การลบองค์กรและ retention, การกู้คืนเฉพาะองค์กรผ่านหน้าจอ, PostgreSQL/RLS และระบบสำรองอัตโนมัติ รายการเหล่านี้ไม่ได้แสดงว่าเชื่อมต่อสำเร็จบนหน้าจอ

โปรแกรมเริ่มที่ `127.0.0.1` จึงใช้ได้เฉพาะเครื่องนี้ ลิงก์ `localhost` ที่ส่งให้ผู้อื่นจะไม่ชี้มาที่เครื่องของคุณ การเปิดให้ทีม/ลูกค้าภายนอกใช้งานต้องมีโฮสต์หรือโดเมน HTTPS และการตั้งค่า deployment เพิ่ม รุ่นนี้ยังไม่ได้ตั้งค่าขึ้นระบบออนไลน์ `--host 0.0.0.0` ใช้เปิดรับในเครือข่ายที่ตั้งใจอนุญาตเท่านั้น ส่วน `--secure-cookies` ใช้เมื่อมี HTTPS reverse proxy แล้ว เซิร์ฟเวอร์ Python ที่ให้มาเหมาะกับการใช้งานภายในขนาดเล็ก ไม่ได้ผ่านการทดสอบรับโหลดระดับแพลตฟอร์มสาธารณะ

## เปิดใช้ AI ทั้งสองแบบ

1. หยุดโปรแกรมเดิมแล้วเปิดใหม่ เพื่ออัปเดตโครงสร้างข้อมูลอัตโนมัติ การอัปเดตเพิ่มตารางใหม่โดยไม่ลบเคสเดิม
2. เข้า **ตั้งค่าองค์กร → AI Assistant & Chatbot** ด้วยบัญชีผู้ดูแลองค์กร
3. ใส่ **OpenAI API Key** ขององค์กร กำหนดโมเดล และเพดานคำขอต่อวัน ค่าเริ่มต้นคือ `gpt-4.1-mini`, 100 คำขอต่อวัน UTC, Chatbot สูงสุด 20 คำขอต่อบทสนทนา และ output สูงสุด 1,000 tokens ต่อคำขอ เปลี่ยนโมเดลได้ โดยต้องรองรับ Responses API และ Structured Outputs
4. เลือกเปิด **AI ช่วยร่างคำตอบให้เจ้าหน้าที่** และ/หรือ **Chatbot ตอบลูกค้าผ่าน Web Support** แล้วบันทึก
5. กด **ทดสอบการเชื่อมต่อ** เพื่อส่งข้อความทดสอบที่ไม่มีข้อมูลลูกค้าไปยังบริการจริง การทดสอบนี้ใช้โควตาและอาจมีค่าใช้บริการ API
6. เพิ่มบทความที่ถูกต้องในคลังความรู้ สำหรับ Chatbot ต้องเลือก **เผยแพร่ให้ลูกค้า** ถ้าใช้ข้อมูลตัวอย่าง บทความตัวอย่างเป็นบทความภายในทั้งหมด จึงยังไม่ใช่แหล่งตอบอัตโนมัติ

**AI ช่วยเจ้าหน้าที่:** เปิดบทสนทนาหรือเคสแล้วกด **AI ช่วยร่างคำตอบ** ระบบแสดงสรุป ร่างคำตอบ และข้อความอ้างอิงจากบทความ เจ้าหน้าที่ตรวจเนื้อหาแล้วกด **นำร่างใส่ช่องข้อความ** จากนั้นกดส่งเอง ร่างและสรุปไม่ถูกส่งให้ลูกค้าอัตโนมัติ การขอร่างจะให้เจ้าหน้าที่รับช่วงบทสนทนานั้น และหากมีข้อความ/ความรู้/สิทธิ์/การตั้งค่าเปลี่ยนระหว่างร่าง ระบบจะยกเลิกผลเก่าให้ร่างใหม่

**Chatbot:** เริ่มทำงานในบทสนทนาเว็บใหม่หลังเปิดใช้ ตอบด้วยชื่อ **Bookdose AI · AI Chatbot** พร้อมแหล่งอ้างอิง ใช้เฉพาะบทความสาธารณะขององค์กรนั้น ไม่อ่านบันทึกภายใน ข้อมูลผู้ติดต่อ หรือประวัติองค์กรอื่น ลูกค้ากด **คุยกับเจ้าหน้าที่** ได้เสมอ การขอคน การร้องขอคืนเงิน การส่งไฟล์แนบ ความรู้ไม่พอ คำตอบตรวจอ้างอิงไม่ได้ บริการล้มเหลว หรือเกินเพดาน จะหยุด AI และเปิด/เชื่อมเคสให้ทีมงาน

เจ้าหน้าที่กด **รับช่วงดูแล** หรือส่งคำตอบเอง จะหยุด Chatbot ของบทสนทนานั้นทันที ผล AI ที่กำลังประมวลผลจะไม่ส่งแทรกภายหลัง หากต้องการให้ AI ดูแลต่อ ให้กด **ให้ AI ดูแลข้อความถัดไป** ซึ่งเริ่มกับข้อความใหม่จากลูกค้า ไม่ตอบข้อความเก่าซ้ำ การเปิดหรือปิด Chatbot จากหน้าตั้งค่าไม่เปิด AI ให้บทสนทนาเก่าโดยอัตโนมัติ

**ขอบเขตข้อมูลและการประมวลผล:** ส่งหัวเรื่องและข้อความล่าสุดสูงสุด 14 ข้อความ (ตัดข้อความยาวที่ 2,500 ตัวอักษร) กับส่วนบทความที่เกี่ยวข้องสูงสุด 5 ส่วนไปยัง OpenAI ไม่มีการส่งไฟล์แนบหรือรายการข้อมูลลูกค้า แต่ข้อความที่ผู้ใช้พิมพ์อาจมีข้อมูลส่วนบุคคลอยู่ด้วย ร่างสำหรับเจ้าหน้าที่อาจมีบันทึกภายในและใช้บทความภายใน จึงต้องตรวจทานก่อนส่งลูกค้า ไม่มีเครื่องมือให้โมเดลแก้บัญชี คืนเงิน หรือเรียก API ธุรกิจ

การค้นความรู้ใช้คำภาษาอังกฤษและกลุ่มอักขระภาษาไทยภายในฐานข้อมูลขององค์กร ไม่ใช้ vector database ภายนอก ตรวจว่ารหัสบทความและข้อความอ้างอิงมาจากข้อมูลที่คัดให้โมเดลจริง พร้อมตรวจสิทธิ์ซ้ำก่อนเผยแพร่ อย่างไรก็ตาม การอ้างอิงถูกต้องไม่ได้รับประกันว่าคำตอบทุกประโยคถูกต้อง ควรทดลองกับคำถามจริงและปรับคลังความรู้ก่อนเปิดตอบอัตโนมัติให้ลูกค้าจำนวนมาก

**การทำงานเบื้องหลังและค่าใช้บริการ:** คิว AI อยู่ในฐานข้อมูลองค์กร บันทึกพร้อมข้อความรับเข้า Worker เริ่มพร้อมโปรแกรม มี provider call ที่ทำงานอยู่ได้หนึ่งงานต่อองค์กร และประมวลผลแต่ละองค์กรตามรอบ หน้ารับเรื่องไม่รอ AI ก่อนบันทึกข้อมูล จำกัดเวลาติดต่อบริการ 25 วินาที งานที่ค้างจากการปิดโปรแกรมเกิน 120 วินาทีจะส่งต่อเจ้าหน้าที่โดยไม่เรียกโมเดลซ้ำอัตโนมัติ ระบบไม่นับ AI และข้อความส่งต่อเป็นการตอบครั้งแรกของเจ้าหน้าที่ใน SLA เพดานคำขอนับงานที่รับเข้าคิว รวมงานทดสอบ งานล้มเหลว และงานยกเลิก ไม่ใช่การจำกัดวงเงินเป็นบาท จำนวน tokens เป็นค่าที่บริการส่งกลับและอาจไม่ครบหากเครือข่ายขาดก่อนรับผล

**API Key:** บันทึกในไฟล์ส่วนตัว `data/secrets/` โดยตั้งสิทธิ์ไฟล์เป็น `0600` บนระบบที่รองรับ ไม่บันทึกในฐานข้อมูล ไม่ส่งคีย์กลับไปหน้าเว็บ ไม่ใส่ใน prompt/log และไม่รวมใน ZIP สำรอง ไฟล์คีย์ไม่ได้เข้ารหัสบนดิสก์ หลังย้ายเครื่องหรือกู้คืนข้อมูลต้องใส่คีย์ใหม่ บน Windows ให้จำกัดสิทธิ์โฟลเดอร์ข้อมูลด้วยสิทธิ์บัญชีระบบปฏิบัติการ บัญชีแต่ละองค์กรใช้คีย์แยกกัน

เชื่อมด้วย [OpenAI Responses API](https://developers.openai.com/api/docs/guides/text) โดยกำหนด `store: false` และใช้ [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) สำหรับรูปแบบคำตอบ อ้างอิงความสามารถโมเดลเริ่มต้นจาก [GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini) การกำหนด `store: false` ไม่ใช่การรับประกันว่าไม่มีการเก็บข้อมูลทุกประเภทโดยผู้ให้บริการ

## ทดสอบ

```sh
python3 -m unittest discover -s tests -v
node --check static/app.js
node --check static/ai.js
```

การทดสอบใช้โฟลเดอร์ชั่วคราว ไม่แตะข้อมูลจริง ครอบคลุมระบบเดิม รวมถึงร่าง AI ที่ยังไม่ส่ง, Chatbot, ขอบเขตความรู้และคีย์รายองค์กร, ถอนสิทธิ์ระหว่างประมวลผล, ส่งต่อเจ้าหน้าที่, งานซ้ำ/ล้าสมัย, โควตา, ความล้มเหลวของบริการ และรูปแบบ HTTP สำหรับ Responses API โดยใช้ผู้ให้บริการจำลอง ไม่ใช้ API Key หรือคิดค่าบริการจริง ต้องทดสอบการเชื่อมต่อกับบัญชีจริงจากหน้าตั้งค่าอีกครั้งก่อนใช้งาน AI จริง

การทดสอบเบราว์เซอร์เพิ่มเติมใช้ Playwright และ Chrome ที่ติดตั้งอยู่ (`PLAYWRIGHT_MODULE` และ `CHROME_PATH` ระบุพาธได้): `node tests/browser.cjs` สำหรับระบบหลัก และ `node tests/browser-ai.cjs` สำหรับ AI ตัวทดสอบ AI เปิดเซิร์ฟเวอร์จำลองเฉพาะในโฟลเดอร์ข้อมูลชั่วคราว ไม่ใช่โหมดให้ผู้ใช้เลือกในโปรแกรมจริง

## โครงสร้างซอร์สโค้ด

```text
app.py           HTTP server, API, access checks, uploads, backup / restore
database.py      Schema, password hashing, tenant storage, seed examples
ai_service.py    Responses API, retrieval, private credentials, durable jobs, handoff
static/          หน้าจอ HTML / CSS / JavaScript ไม่มี build step
tests/           HTTP integration tests
```


## LINE และ Email จริง

เพิ่มการรับเรื่องและตอบกลับผ่าน LINE OA และ IMAP/SMTP Email แล้ว ตั้งค่าได้จาก **ตั้งค่าองค์กร** อ่านขั้นตอน ข้อจำกัด และสถานะการส่งใน [คู่มือเชื่อม LINE และ Email](CHANNELS.md)

AI ช่วยร่างคำตอบใช้ได้ทั้งสองช่องทาง โดยเจ้าหน้าที่ตรวจแล้วกดส่งเอง ส่วน Chatbot ตอบอัตโนมัติยังทำงานเฉพาะ Web Support
