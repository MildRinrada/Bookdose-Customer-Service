# การแยกข้อมูลและความลับ

ส่วนหนึ่งของ [ความปลอดภัย](README.md)

## ฐานข้อมูลแยกต่อองค์กร

- แต่ละองค์กรมีไฟล์ฐานข้อมูลของตัวเอง `data/tenants/<tenant_id>.sqlite3` ไม่ใช่ตารางเดียวกันแล้วกรองด้วย `WHERE tenant_id=?` (`backend/database/db.py`) คิวรีใดจึงเห็นข้อมูลข้ามองค์กรไม่ได้ตั้งแต่แรก การลืมใส่เงื่อนไขจึงไม่กลายเป็นข้อมูลรั่วข้ามองค์กร
- ชื่อไฟล์ถูกตรวจว่าเป็นเลขฐานสิบหก 32 ตัวเท่านั้นก่อนประกอบเป็น path จึงใช้ `../` ไม่ได้
- ฐานข้อมูลกลาง (`control.sqlite3`) เก็บเฉพาะบัญชี ความเป็นสมาชิก เซสชัน และข้อมูลระดับแพลตฟอร์ม
- ไฟล์แนบอยู่แยกโฟลเดอร์ต่อองค์กร `data/files/<tenant_id>/` และเปิดได้ผ่าน API ที่ตรวจสิทธิ์เท่านั้น

## การเลือกองค์กรในแต่ละคำขอ

- แท็บที่เลือกองค์กรไว้ส่ง `X-Tenant-ID` ทุกคำขอ ถ้าไม่ตรงกับเซสชัน API ตอบ 409 กันการเขียนผิดองค์กรเมื่อสลับองค์กรในอีกแท็บ
- การพยายามเข้าองค์กรที่ไม่ได้เป็นสมาชิกบันทึกเป็นเหตุการณ์ `cross_tenant_denied`

## สิทธิ์ภายในองค์กร

- ทุก route ประกาศระดับสิทธิ์ และ dispatcher เรียก middleware ตามระดับนั้นก่อนถึง controller เสมอ (`backend/http/dispatch.py`)
- งานของเจ้าขององค์กรกั้นเพิ่มด้วย `@require_role('admin')` ที่ controller (`backend/middleware/auth.py`)
- เจ้าหน้าที่เห็นเฉพาะงานของทีมตัวเอง โดยกรองที่ชั้นฐานข้อมูล ไม่ใช่ที่หน้าจอ (`backend/middleware/access.py`)
- ข้อมูลที่ไม่มีสิทธิ์เห็นตอบ **404** ไม่ใช่ 403 จึงไม่บอกว่ามีอยู่จริง
- ลูกค้าและผู้เยี่ยมชมถึงได้เฉพาะบทสนทนาของตัวเอง บทสนทนาที่ทำงานอยู่ระบุด้วย header `X-Conversation-ID` และต้องเป็นของผู้เรียกเท่านั้น

รายละเอียดบทบาทอยู่ใน [บทบาทและสิทธิ์](../roles-and-permissions.md)

## ผู้ดูแลแพลตฟอร์มกับข้อมูลขององค์กร

`backend/modules/support_access/`

- ผู้ดูแลแพลตฟอร์มเข้าดูองค์กรไม่ได้เอง ต้องขอสิทธิ์และให้เจ้าขององค์กรอนุมัติ
- สิทธิ์ที่ได้อ่านได้อย่างเดียว `middleware/auth.select_workspace` ปฏิเสธทุกคำขอที่ไม่ใช่ GET
- สิทธิ์ผูกกับ `memberships.expires_at` ทุกการตรวจความเป็นสมาชิกไม่นับแถวที่เลยเวลาแล้ว สิทธิ์จึงหมดตรงนาทีแม้งานเก็บกวาดยังไม่ทำงาน
- ความเป็นสมาชิกถาวรไม่ถูกแตะโดยการขอสิทธิ์

## การเข้ารหัสความลับ

ความลับที่เก็บไว้ทั้งหมดเข้ารหัสด้วย **AES-256-GCM** ก่อนเขียนลงดิสก์ (`backend/utils/secret_box.py`) ได้แก่

- token ของ LINE, Facebook และ Instagram
- รหัสผ่านอีเมลและ token OAuth ของช่องทางอีเมล
- API key ของ OpenAI หรือ Gemini และรหัสลับของ n8n Webhook
- รหัสผ่าน SMTP ของแพลตฟอร์ม ข้อมูลผู้ให้บริการ SMS และ Secret Key ของ Turnstile
- ความลับของแอปยืนยันตัวตน (TOTP) ของทีมงานและลูกค้า

### จุดที่ออกแบบไว้และต้องรักษาไว้

- **ค่าที่เข้ารหัสผูกกับบริบท** เช่น ชื่อไฟล์ `<tenant>.line.json` หรือรหัสบัญชี ค่าที่ถูกคัดลอกไปวางในไฟล์ขององค์กรอื่นหรือแถวของบัญชีอื่นจะเปิดไม่ออก
- **รูปแบบ** `bdsec1.<รหัสกุญแจ>.<ข้อมูล>` รหัสกุญแจคือส่วนต้นของ SHA-256 ของกุญแจ จึงเลือกกุญแจที่ถูกได้โดยไม่ต้องลองทุกดอก
- **เปลี่ยนกุญแจได้โดยไม่หยุดระบบ** ด้วย `BOOKDOSE_SECRET_KEY_OLD` ค่าที่อ่านด้วยกุญแจเก่าจะถูกเข้ารหัสใหม่ด้วยกุญแจปัจจุบัน
- **ไฟล์ความลับเขียนแบบ atomic** และตั้งสิทธิ์ `0600` (`backend/utils/files.py`)
- **ค่าที่เปิดไม่ออกถูกอ่านเป็น "ยังไม่ได้ตั้งค่า"** และบันทึกไว้ แทนที่จะทำให้ทุกคำขอล้ม
- **ความลับไม่ถูกส่งกลับหน้าเว็บ** ช่องรหัสผ่านในหน้าตั้งค่าเริ่มว่างเสมอ การเว้นว่างหมายถึงใช้ค่าเดิม

บนเซิร์ฟเวอร์จริงต้องตั้ง `BOOKDOSE_SECRET_KEY` ถ้าไม่ตั้ง กุญแจจะเป็นไฟล์ `data/keys/secret.key` ซึ่งอยู่ในโฟลเดอร์เดียวกับข้อมูลที่มันปกป้อง ใช้ได้กับเครื่องเดียวเท่านั้น

## ไฟล์สำรอง

- **ไฟล์สำรองทั้งระบบไม่มีกุญแจอยู่ข้างใน** มีเฉพาะค่าที่เข้ารหัสแล้วและรหัสประจำกุญแจ ไฟล์สำรองที่หลุดออกไปจึงไม่ให้ token ของใคร (`backend/database/backup.py`)
- ไฟล์สำรองขององค์กรที่เจ้าขององค์กรดาวน์โหลดเอง ไม่มีความลับใดเลย
- ไฟล์สำรองมีข้อมูลลูกค้าและบันทึกภายในที่ไม่ได้เข้ารหัส ต้องเก็บในที่ที่จำกัดผู้เข้าถึง

ขั้นตอนสำรองและกู้คืนอยู่ใน [ดูแลระบบ](../operations.md)

## การลบข้อมูลบุคคล

- **เครื่องมือ PDPA** ในคอนโซลระบบกลาง ค้นหาบุคคลในทุกองค์กรด้วยอีเมล เบอร์โทร (เขียนแบบใดก็ได้) หรือชื่อ ผลการค้นหาแสดงเพียงจำนวน ไม่แสดงบทสนทนา จากนั้นส่งออกเป็นไฟล์ ZIP หรือลบ ทุกครั้งบันทึกว่าใครทำ เมื่อไร และทำไม บันทึกเก็บบุคคลเป็นเพียงป้ายที่ปิดบังแล้วและค่า hash
- **การลบ** ลบบัญชีลูกค้า ส่วนในแต่ละองค์กร แถวของลูกค้ายังอยู่ (เคสและรายงานจึงยังรวมยอดถูก) แต่ไม่เหลืออะไรที่บอกว่าเป็นใคร เนื้อความทุกข้อความถูกล้าง ค่าในช่องข้อมูลเพิ่มเติมของเคสและระดับอารมณ์ของแต่ละข้อความถูกลบ ไฟล์ถูกลบ และสำเนาในถังขยะถูกทิ้ง ไฟล์สำรองที่ทำก่อนหน้ายังมีข้อมูลอยู่จนกว่าจะหมดอายุ
- **ระยะเวลาเก็บข้อมูล** องค์กรตั้งให้ล้างเนื้อหาของบทสนทนาที่เงียบนานเกินกำหนดได้ ดู [ตั้งค่าองค์กร](../features/organization-settings.md)

## ประวัติการทำงาน

`audit_logs` มีทั้งในฐานข้อมูลกลางและในฐานข้อมูลของทุกองค์กร บันทึกว่าใครทำอะไรกับข้อมูลไหน ไม่ลบ และไม่บันทึกรหัสผ่าน token หรือเนื้อความ ดู [ประวัติการทำงานและถังขยะ](../features/audit-and-trash.md)
