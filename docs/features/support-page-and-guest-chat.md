# หน้าช่วยเหลือและแชทผู้เยี่ยมชม

แต่ละองค์กรมีหน้าช่วยเหลือของตัวเองที่ `/support/<รหัสองค์กร>` ลูกค้าเริ่มแชทได้ทันทีโดยไม่ต้องสมัคร อ่านคำถามที่พบบ่อย และติดตามเคสได้ หน้านี้ฝังบนเว็บไซต์ขององค์กรเป็นปุ่มแชทได้ด้วย

ลูกค้าเข้ามาทางลิงก์ขององค์กร เช่น เว็บไซต์ ปุ่มแชท QR หรืออีเมล แชทจึงไปถึงองค์กรนั้นเสมอ และไม่มีใครดูรายชื่อองค์กรอื่นที่ใช้ระบบได้

## หน้าของผู้เยี่ยมชม

| ที่อยู่ | หน้า |
|---|---|
| `/support/<org>/tickets/new` | เริ่มแชท ลิงก์หลักที่องค์กรแจก |
| `/support/<org>/tickets` | แชทของเบราว์เซอร์นี้กับองค์กร (เปิดแชทล่าสุด) หรือฟอร์มเริ่มแชทถ้ายังไม่มี |
| `/support/<org>/tickets/<id>` | แชทหนึ่งเรื่อง |
| `/support/<org>/faq` และ `/faq/<id>` | คำถามที่พบบ่อยขององค์กร และบทความหนึ่งเรื่อง |
| `/support/<org>/cases/<id>` | ติดตามเคสที่เปิดจากแชทของเบราว์เซอร์นี้ พร้อม [เส้นทางเคส](customer-portal.md#เส้นทางเคส) |
| `/support/<org>/resume#t=<token>` | ลิงก์ติดตามแชทจากอีเมลหรือ SMS |
| `/support/<org>/embed` | แชทในกรอบบนเว็บไซต์ขององค์กร |
| `/support/tickets/new` | ไม่มีลิงก์ขององค์กร ให้พิมพ์รหัสองค์กร |

ลิงก์เก่าแบบ `/chat/<org>` พาไปที่อยู่ใหม่เอง ส่วน `/chat/<org>/embed` ยังใช้ได้ตรง ๆ เพราะโค้ดฝังที่อยู่บนเว็บไซต์แล้วอาจยังชี้ที่อยู่นี้ และการพาไปที่อื่นใส่ในกรอบไม่ได้

## แบนเนอร์ขององค์กร

บนสุดของทุกหน้าใน `/support/<org>` มีแบนเนอร์ขององค์กร ลูกค้าจึงรู้ทันทีว่ากำลังติดต่อใคร

- โลโก้ขององค์กร ถ้ายังไม่มีโลโก้ใช้ 2 ตัวอักษรแรกของชื่อแทน
- ชื่อองค์กรเป็นหัวเรื่องหลัก
- ข้อความใต้ชื่อที่องค์กรเขียนเอง (ไม่เกิน 80 ตัวอักษร เว้นว่างได้)
- สีพื้นเลือกจากชุดสี 8 สีที่ตัวหนังสืออ่านชัดทุกสี และเปลี่ยนเป็นโทนเข้มเองในธีมมืด
- ปุ่มแชทกับทีมงาน คำถามที่พบบ่อย เข้าสู่ระบบ และขนาดตัวอักษร อยู่ในแบนเนอร์
- ชื่อ Bookdose อยู่ท้ายหน้าเป็นบรรทัดเล็ก "ให้บริการโดย Bookdose"

องค์กรตั้งข้อความและสีที่ **ตั้งค่าองค์กร → ข้อมูลองค์กร → แบนเนอร์หน้าช่วยเหลือ** ส่วนโลโก้และชื่อแก้ที่ **แก้ไขชื่อและโลโก้** หน้าใส่รหัสองค์กรยังใช้หัว Bookdose เพราะยังไม่ใช่หน้าขององค์กรใด

## เริ่มแชท

หน้าเริ่มแชทมีหัวบอกคำสัญญาเวลาตอบของทีม ข้อความต้อนรับ และบทความยอดนิยมให้ลองหาคำตอบก่อน ฟอร์มมี 3 ขั้น

1. **เรื่องที่ต้องการติดต่อ** หมวดเรื่องขององค์กรเป็นช่องให้เลือก หมวดส่งเรื่องเข้าทีมที่องค์กรกำหนด
2. **เล่าเรื่องให้ทีมงานฟัง** ช่องข้อมูลที่องค์กรให้ลูกค้ากรอกของหมวดที่เลือก (ไม่บังคับ ดู [แบบฟอร์มตามหมวดเรื่อง](customer-portal.md#แบบฟอร์มตามหมวดเรื่อง)) หัวข้อ (ไม่บังคับ) ข้อความจัดรูปแบบได้ และไฟล์แนบ ระหว่างพิมพ์ระบบแนะนำบทความที่อาจตอบได้
3. **ติดตามคำตอบอย่างไร** จำในเบราว์เซอร์นี้ ลิงก์ทางอีเมล หรือ SMS ชื่อ และเลขอ้างอิงให้ทีม

ผู้เยี่ยมชมใหม่ที่ไม่ให้เบราว์เซอร์จำ ต้องให้อีเมลหรือเบอร์โทร ไม่อย่างนั้นแชทจะหาย

### กันสแปม

- ช่องซ่อนต้องว่าง และต้องเปิดฟอร์มไว้อย่างน้อย 2 วินาทีก่อนส่ง
- เริ่มแชทใหม่ได้ 5 เรื่องต่อชั่วโมงต่อ IP และ 10 เรื่องต่อวันต่อผู้เยี่ยมชม
- เริ่มแชทใหม่ได้ไม่เกิน 20 เรื่องใน 24 ชั่วโมงต่อ IP ต่อองค์กร นับจากฐานข้อมูล จึงไม่เริ่มนับใหม่เมื่อรีสตาร์ทเซิร์ฟเวอร์ และคนที่ล้างคุกกี้แล้วเริ่มใหม่ไปเรื่อย ๆ ก็ยังติดเพดานนี้
- เมื่อเปิด [ฐานข้อมูล IP](../security/monitoring-and-traps.md#ข้อมูล-ip-และการตรวจการปลอมตัว) IP ของเครือข่ายคลาวด์หรือ VPN ได้เพดาน 5 เรื่องแทน 20 เพราะหลัง IP แบบนี้มีคนจริงน้อย แต่ไม่ถูกบล็อก
- เมื่อแพลตฟอร์มเปิด Cloudflare Turnstile ฟอร์มแสดงตัวตรวจว่าเป็นคนจริง
- ทุกคำขอที่เปลี่ยนข้อมูลต้องมี `X-Guest-CSRF`
- เจ้าขององค์กรบล็อกผู้เยี่ยมชมที่ก่อกวนได้ (หัวข้อถัดไป)

### บล็อกผู้ก่อกวน

เจ้าขององค์กรกดปุ่ม **บล็อก** ที่หัวแชทของผู้เยี่ยมชมในกล่องข้อความ ระบบถามยืนยันก่อน แล้วจึงทำ 3 อย่าง

1. ปิดแชทที่ยังเปิดอยู่ทั้งหมดของผู้เยี่ยมชมคนนั้น แชทจึงออกจากคิวและรายการที่รอตอบ การแจ้งเตือนที่รอส่งถึงเขาถูกยกเลิก
2. ผู้เยี่ยมชมคนนั้นยังอ่านแชทเดิมได้ แต่ส่งข้อความ เริ่มแชทใหม่ เปลี่ยนชื่อ ขอลิงก์ติดตาม หรือขอรหัส LINE ไม่ได้ จนกว่าจะปลดบล็อก ทุกเบราว์เซอร์และลิงก์ติดตามของเขาโดนเหมือนกัน สิ่งเดียวที่ยังทำได้คือให้เบราว์เซอร์ลืมแชท
3. IP ที่เขาเคยใช้เริ่มแชทหรือเปิดเบราว์เซอร์ เริ่มแชทใหม่ในองค์กรนี้ไม่ได้ 7 วัน ทุกคนที่ใช้ IP เดียวกันโดนด้วย เพราะคนในบ้าน ที่ทำงาน หรือเครือข่ายมือถือเดียวกันใช้ IP ร่วมกันได้ จึงกันไว้เป็นวัน ไม่กันถาวร และข้อความที่เขาเห็นแนะให้เข้าสู่ระบบด้วยบัญชีลูกค้าแทน

- **ลูกค้าที่เข้าสู่ระบบ:** ไม่ได้รับผลกระทบเลย และบล็อกได้เฉพาะแชทของผู้เยี่ยมชม
- **IP ของเครื่องเซิร์ฟเวอร์เอง (loopback):** ไม่ถูกกัน เพราะถ้าพร็อกซีไม่ส่ง IP จริงมา ทุกคนจะดูเป็น IP นี้หมด
- **หลังบล็อก:** หัวแชทขึ้น **บล็อกแล้ว** ให้ทุกคนในทีมเห็น และปุ่มเปลี่ยนเป็น **ปลดบล็อก**
- **รายการที่บล็อกไว้:** อยู่ที่ **ตั้งค่าองค์กร → แชทบนเว็บไซต์** บอกชื่อ แชทที่บล็อก ใครบล็อก เมื่อไร และกัน IP ถึงเมื่อไร ปลดบล็อกจากตรงนั้นได้
- **ปลดบล็อก:** แชทที่ปิดไปยังปิดอยู่จนกว่าทีมหรือผู้เยี่ยมชมจะเขียนมาอีก
- **ประวัติ:** ทั้งการบล็อกและการปลดบล็อกบันทึกในประวัติการทำงานขององค์กร
- **เจ้าหน้าที่:** บล็อกหรือปลดบล็อกไม่ได้ และไม่เห็นปุ่ม

## ระหว่างแชท

- ใช้ส่วนประกอบเดียวกับแชทของลูกค้าที่เข้าสู่ระบบ: ข้อความ การ์ดขอบคุณ (เมื่อองค์กรเปิด) แบบประเมินในแชท สถานะ AI พร้อมปุ่ม **คุยกับเจ้าหน้าที่** และช่องพิมพ์
- รีแอคข้อความของทีมด้วยอีโมจิได้ และกดหัวใจบนการ์ดขอบคุณได้ เหมือนหน้าลูกค้า ดู [รีแอคข้อความ](customer-portal.md#รีแอคข้อความ)
- ผู้เยี่ยมชมที่มีหลายแชทเห็นรายการให้สลับ
- บทความในรายการข้างแชทอ่านได้โดยไม่ออกจากแชท ทั้งการวางเมาส์และการลากบทความมาวางบนแชท
- ประกาศปัญหาที่องค์กรแจ้งอยู่แสดงก่อนลูกค้าถาม ดู [ประกาศปัญหาและหน้าสถานะ](known-issues-and-status.md)
- ลูกค้าที่รอทีมเห็น **ลำดับคิวและเวลารอโดยประมาณ** (หัวข้อถัดไป) และกด **ไม่รีบ ตอบพรุ่งนี้ก็ได้** ได้ ดู [ไม่รีบ](customer-portal.md#ไม่รีบ)
- ผู้เยี่ยมชมที่เบราว์เซอร์จำไว้และมีเคสที่เสร็จภายใน 30 วัน ขอให้เจ้าหน้าที่คนเดิมดูแลเรื่องใหม่ได้จากฟอร์มเริ่มแชท ดู [ขอคนเดิม](customer-portal.md#ขอคนเดิม)
- กด **ฉันก็เจอ** บนประกาศปัญหาได้ ดู [ประกาศปัญหาและหน้าสถานะ](known-issues-and-status.md#ฉันก็เจอ)
- ย้ายแชทไปคุยต่อใน LINE ขององค์กรได้ ดู [หน้าลูกค้า](customer-portal.md#คุยต่อใน-line)
- ขอให้ทีมโทรหรือส่ง LINE กลับในเวลาที่สะดวก จากเมนูของแชท ดู [ขอให้ติดต่อกลับ](customer-portal.md#ขอให้ติดต่อกลับ)
- บรรทัดท้ายหน้า (ข้อความส่งถึงทีมงานโดยตรงและให้บริการโดย Bookdose) อยู่ท้ายคอลัมน์ขวาเมื่อมีคอลัมน์ขวา บนมือถือเหลือเฉพาะให้บริการโดย Bookdose แชทจึงได้พื้นที่เพิ่ม
- เตือนก่อนส่งข้อมูลที่ไม่ควรส่ง เบลอหรือวงกลมบนภาพก่อนแนบ และอัดหน้าจอส่งให้ทีม เหมือนหน้าลูกค้า ดู [ส่งข้อมูลอย่างปลอดภัยและเห็นภาพ](customer-portal.md#ส่งข้อมูลอย่างปลอดภัยและเห็นภาพ)

## ลำดับคิวและเวลารอโดยประมาณ

ลูกค้าที่รอทีมเห็นใต้ข้อความล่าสุดว่าอยู่ลำดับที่เท่าไร และต้องรอประมาณเท่าไร จะได้ไม่ต้องเขียนมาถามซ้ำ

- **ลำดับ** คือจำนวนลูกค้าของทีมเดียวกันที่รอนานกว่า ทุกช่องทาง บวกหนึ่ง ทีมอาจรับลูกค้าที่ไม่พอใจหรือเคสที่ใกล้ครบกำหนดก่อน หน้าจอจึงเขียนว่า "ประมาณ" ลูกค้าที่กดไม่รีบอยู่หลังทุกคนที่ไม่ได้กด และเห็นเวลาที่ทีมจะตอบแทนเวลารอโดยประมาณ
- **เวลารอ** ใช้ค่าที่มากกว่าระหว่าง เวลารอปกติของทีมลบด้วยเวลาที่ลูกค้ารอไปแล้ว กับจำนวนคนข้างหน้าหารด้วยความเร็วที่ทีมตอบจริง จากข้อมูล 7 วันล่าสุด
- ถ้าไม่มีการตอบเลยใน 7 วัน แสดงเฉพาะลำดับ ไม่เดาเวลา
- ถ้าไม่มีใครที่ตอบได้พร้อมรับงานตอนนี้ (ตามสถานะ เวลาทำงาน หรือวันลา) หน้าจอบอกตามจริงแทนเวลาที่ทีมทำไม่ได้
- คำนวณทั้งองค์กรไม่เกินนาทีละครั้ง

## ติดตามแชท 4 ทาง

การ์ด **ติดตามแชทนี้** อยู่ท้ายแชท พับเก็บได้ และเปิดจากเมนูของหัวแชทได้

| วิธี | รายละเอียด |
|---|---|
| จำในเบราว์เซอร์นี้ | คุกกี้ `g_<org>` แบบ HttpOnly อายุ 400 วัน ต่ออายุเองเมื่อใช้งาน ปิดได้สำหรับเครื่องสาธารณะ (ลืมเมื่อปิดเบราว์เซอร์) |
| ลิงก์ทางอีเมล | ลิงก์ `/support/<org>/resume#t=<token>` |
| ลิงก์ทาง SMS | ลิงก์แบบเดียวกัน แสดงเมื่อแพลตฟอร์มตั้งผู้ให้บริการ SMS แล้ว |
| แจ้งเตือนทาง LINE | เมื่อองค์กรเชื่อม LINE แล้ว ส่งรหัส 6 หลักในแชท 1:1 กับบัญชี LINE ขององค์กร |

**กติกาของลิงก์ติดตาม**

- token อยู่หลังเครื่องหมาย `#` จึงไม่ถูกส่งถึงเซิร์ฟเวอร์และไม่อยู่ใน log หน้าเปิดลิงก์อ่าน token ครั้งเดียว แล้วลบออกจากแถบที่อยู่
- ใช้ได้ 30 วัน สูงสุด 20 ครั้ง ลิงก์ใหม่ทางเดียวกันยกเลิกลิงก์เก่า
- เปิดลิงก์แล้วถือว่ายืนยันอีเมลหรือเบอร์นั้น และเบราว์เซอร์ที่เปิดได้คุกกี้ใหม่
- ขอลิงก์ได้ 3 ครั้งต่อชั่วโมงต่อผู้เยี่ยมชมและต่อปลายทาง และ 10 ครั้งต่อชั่วโมงต่อ IP
- อีเมลและ SMS มีชื่อองค์กรกับลิงก์เท่านั้น ไม่มีเนื้อความแชท
- เบอร์ไทยแปลงเป็นรูปแบบสากล `+66`

ในการ์ดยังมีลิงก์สมัครสมาชิกเพื่อเก็บประวัติถาวร และ **ลืมแชทในเบราว์เซอร์นี้**

### คุยต่อบนมือถือ

ผู้เยี่ยมชมที่คุยบนคอมอยู่ เลือก **คุยต่อบนมือถือ (สแกน QR)** จากเมนูของแชท แล้วสแกน QR ด้วยกล้องมือถือ แชทเดิมเปิดบนมือถือทันทีโดยไม่ต้องเข้าสู่ระบบ ถ่ายรูปสินค้าหรือหน้าจอแล้วส่งเข้าแชทเดิมได้เลย

- QR เป็นลิงก์ติดตามแบบเดียวกับที่ส่งทางอีเมล แต่เปิดแชทที่อยู่บนจอตอนนั้น ใช้ได้ครั้งเดียวภายใน 10 นาที และ QR ใหม่ยกเลิกอันเก่า เพราะอยู่บนหน้าจอที่คนอื่นอาจเห็น
- เปิดแล้วไม่ถือว่ายืนยันอีเมลหรือเบอร์โทร แชทยังเปิดอยู่บนคอมเหมือนเดิม
- สร้าง QR ได้ไม่เกิน 10 ครั้งต่อ 15 นาทีต่อผู้เยี่ยมชม เก็บเฉพาะค่าแฮชของ token

## เสียงและป๊อปอัปขณะเปิดหน้าแชท

- ทีมงานหรือ Chatbot ตอบในแชทที่เปิดอยู่ มีเสียงเตือนสั้น ๆ ได้ยินแม้สลับไปแท็บอื่น เพราะตอนรอคำตอบคือตอนที่ลูกค้ามักทำอย่างอื่นอยู่
- ตอบในแชทอื่นของเบราว์เซอร์นี้ มุมขวาล่างขึ้นป๊อปอัปแบบเดียวกับลูกค้าที่มีบัญชีพร้อมเสียง กดแล้วเปิดแชทนั้นในหน้าเดิม (เฉพาะตอนอยู่หน้านี้)
- ในกรอบบนเว็บไซต์ขององค์กร มีแค่เสียง และดังเฉพาะตอนเปิดหน้าต่างแชทอยู่
- ปิดเสียงได้จากเมนูของแชท (**ปิดเสียงเมื่อทีมงานตอบ**) เบราว์เซอร์จำไว้ให้
- บอกเฉพาะคำตอบที่มาหลังเปิดหน้า

## แจ้งเตือนเมื่อทีมตอบ

- เมื่อทีมตอบ Chatbot ตอบ หรือ Chatbot ส่งต่อให้เจ้าหน้าที่โดยผู้เยี่ยมชมไม่ได้ขอเอง และยังไม่มีใครอ่านภายใน 2 นาที
- ส่งหนึ่งครั้งต่อแชทต่อช่วงที่ยังไม่ได้อ่าน ต่อช่องทางที่ยืนยันแล้ว
- ส่งเฉพาะช่องทางที่ยืนยันแล้ว คืออีเมลหรือเบอร์ที่เปิดลิงก์แล้ว และ LINE ที่ผูกแล้ว ไม่ส่งถึงที่อยู่ที่ยังไม่ยืนยันเด็ดขาด
- อีเมลและ SMS แนบลิงก์ติดตามใหม่ ไม่มีเนื้อความ
- ส่งซ้ำเมื่อล้มเหลวได้ 3 ครั้ง

## ย้ายแชทเข้าบัญชี

- เมื่อลูกค้าเข้าสู่ระบบในเบราว์เซอร์ที่เคยแชทไว้ หน้าลูกค้าเสนอ **ย้ายเข้าบัญชีนี้** ต้องกดยืนยันเอง เพื่อไม่ให้เครื่องที่ใช้ร่วมกันส่งแชทของคนหนึ่งให้คนถัดไป
- แชทที่ยืนยันอีเมลเดียวกับบัญชีที่ยืนยันแล้ว ย้ายให้เองเมื่อยืนยันอีเมลหรือเข้าสู่ระบบ
- หลังย้าย คุกกี้และลิงก์เดิมใช้ไม่ได้

## ปุ่มแชทบนเว็บไซต์ขององค์กร

1. ไปที่ **ตั้งค่าองค์กร → แชทบนเว็บไซต์** เปิด **ปุ่มแชทบนเว็บไซต์**
2. ใส่เว็บไซต์ที่อนุญาตไม่เกิน 10 รายการ รูปแบบ `https://โดเมน[:พอร์ต]` หรือ `http://localhost...` สำหรับทดสอบ
3. เลือกตำแหน่ง (ขวาหรือซ้าย) สี (ชุดสีที่เตรียมไว้ ค่าเริ่มต้นสีดำ) และหัวข้อ
4. วางโค้ดนี้ก่อนปิด `</body>` ของเว็บไซต์

```html
<script src="https://<โดเมนของระบบ>/widget.js" data-org="<รหัสองค์กร>" async></script>
```

- สคริปต์เพิ่มปุ่มลอย แล้วเปิดหน้าแชทในกรอบ มีตัวเลขข้อความใหม่ ปิดด้วย Escape ได้ และเต็มจอบนมือถือ
- หน้าแชทในกรอบยอมให้ฝังได้เฉพาะเว็บไซต์ที่อนุญาต และคุยกับหน้าเว็บด้านนอกด้วย `postMessage` เฉพาะ origin ที่อนุญาต
- คุกกี้ในกรอบบนเว็บไซต์อื่นต้องใช้ HTTPS (`--secure-cookies`) จึงจะจำแชทได้
- Safari อาจบล็อกคุกกี้ในกรอบ ผู้เยี่ยมชมจึงถูกนับเป็นคนใหม่ทุกครั้ง หน้าเต็มไม่มีปัญหานี้
- ค่าที่สคริปต์อ่านอยู่ที่ `GET /api/public/<org>/widget`

## ตั้งค่าของเจ้าขององค์กร

**ตั้งค่าองค์กร → แชทบนเว็บไซต์**

| ตั้งค่า | ค่าเริ่มต้น |
|---|---|
| ให้ลูกค้าเริ่มแชทได้โดยไม่ต้องเข้าสู่ระบบ | เปิด |
| ลิงก์แชทสาธารณะพร้อม QR | แสดงให้คัดลอก |
| ปุ่มแชทบนเว็บไซต์ | ปิด |
| คิวก่อนสำหรับสมาชิก (ลูกค้าที่เข้าสู่ระบบได้คิวก่อนผู้เยี่ยมชม) | ปิด |
| ผู้เยี่ยมชมที่บล็อกไว้ พร้อมปุ่มปลดบล็อก | ว่าง |

เมื่อปิดแชทผู้เยี่ยมชม API ของผู้เยี่ยมชมตอบ 403 และเริ่มแชทได้เฉพาะลูกค้าที่เข้าสู่ระบบ

## ฝั่งทีมงาน

- ผู้เยี่ยมชมเป็นรายชื่อลูกค้าที่สร้างโดยระบบ บทสนทนามีป้าย **ผู้เยี่ยมชม** พร้อมบอกว่าติดต่อกลับทางไหนได้
- การรวมรายชื่อซ้ำยังใช้ได้ แต่ผู้เยี่ยมชมยังเห็นเฉพาะแชทที่ตัวเองเริ่ม
- เจ้าขององค์กรบล็อกผู้เยี่ยมชมที่ก่อกวนได้จากหัวแชท ดู [บล็อกผู้ก่อกวน](#บล็อกผู้ก่อกวน)
- อุปกรณ์ที่ไม่ได้ใช้ 400 วัน ลิงก์หรือรหัสที่หมดอายุ IP ที่กันไว้เมื่อครบ 7 วัน และ IP ของแชทที่เริ่มเกิน 30 วัน ถูกลบเอง

## ข้อมูล

ทุกอย่างของผู้เยี่ยมชมอยู่ในฐานข้อมูลขององค์กร

| ตาราง | เก็บอะไร |
|---|---|
| `guest_visitors` | ผู้เยี่ยมชม ชื่อ อีเมลและเบอร์ที่ยืนยันแล้ว และบัญชีที่ย้ายเข้าไป |
| `guest_devices` | เบราว์เซอร์ที่ถือคุกกี้ (token เป็นค่า hash) |
| `guest_conversations` | บทสนทนาที่ผู้เยี่ยมชมเริ่ม และ IP ตอนเริ่ม (เก็บ 30 วัน) |
| `guest_blocks`, `guest_block_ips` | ผู้เยี่ยมชมที่ถูกบล็อก และ IP ที่กันไว้ 7 วัน |
| `guest_links` | ลิงก์ติดตาม (ค่า hash) |
| `guest_line_codes`, `guest_line_links` | รหัสผูก LINE และ LINE ที่ผูกแล้ว |
| `guest_notifications` | การแจ้งเตือนที่รอส่ง |

ฐานข้อมูลกลางมีเพียง `guest_verified_emails` บอกว่าองค์กรไหนมีผู้เยี่ยมชมที่ยืนยันอีเมลนั้นแล้ว เพื่อย้ายแชทเข้าบัญชีโดยไม่ต้องเปิดทุกองค์กร
