# คอนโซลระบบกลาง

หน้าของผู้ดูแลแพลตฟอร์ม (`/platform/*`) ดูแลเซิร์ฟเวอร์และองค์กรทั้งหมด ไม่ใช่งานบริการขององค์กรใด ผู้ดูแลแพลตฟอร์มเข้าสู่ระบบแล้วมาที่หน้านี้เสมอ

## เมนู

| เมนู | ที่อยู่ | ทำอะไร |
|---|---|---|
| ภาพรวมระบบ | `/platform/system` | สิ่งที่ต้องจัดการ สุขภาพเซิร์ฟเวอร์ การสำรอง ช่องทางของทุกองค์กร การใช้งาน และข้อผิดพลาดล่าสุด |
| จัดการองค์กร | `/platform/organizations` | สร้าง ดู ระงับ เปิด และปิดองค์กรถาวร รีเซ็ตการยืนยันสองขั้นตอนของทีมงาน ประวัติของแพลตฟอร์ม |
| สุขภาพองค์กร | `/platform/org-health` | คะแนนสุขภาพของทุกองค์กร แย่สุดก่อน |
| บัญชีผู้ใช้ | `/platform/accounts` | ค้นบัญชีทีมงานหรือลูกค้าด้วยอีเมล ระงับทั้งระบบ หรือบังคับตั้งรหัสผ่านใหม่ |
| FAQ กลาง | `/platform/faq` | บทความที่ทุกองค์กรหรือลูกค้าทุกองค์กรเห็น |
| คลังบทความแม่แบบ | `/platform/templates` | บทความสำเร็จรูปให้องค์กรคัดลอกไปใช้ |
| ประกาศ | `/platform/announcements` | ประกาศสถานะระบบ และประกาศถึงทุกองค์กร |
| รายงานปัญหา | `/platform/reports` | สิ่งที่ทีมงานขององค์กรแจ้งมาจากปุ่ม ? |
| เครื่องมือ PDPA | `/platform/pdpa` | ค้นหา ส่งออก และลบข้อมูลบุคคล |
| ทีมผู้ดูแลระบบ | `/platform/team` | ผู้ดูแลแพลตฟอร์ม |
| ความปลอดภัย | `/platform/security` | ดู [การเฝ้าระวังและกับดัก](../security/monitoring-and-traps.md) |
| ตั้งค่าระบบ | `/platform/settings` | อีเมลของแพลตฟอร์ม SMS และ Turnstile |

กระดิ่งของคอนโซลแสดงสิ่งที่เซิร์ฟเวอร์ต้องการจากผู้ดูแล และคำตอบขององค์กรต่อคำขอเข้าช่วยเหลือ

## เรื่องด่วนของระบบ

เรื่องที่รอไม่ได้จะเด้งป๊อปอัปมุมขวาล่าง หน้าตาเดียวกับการ์ดฉลองของทีมงาน ขึ้นทุกหน้าที่ผู้ดูแลเปิดอยู่ รวมถึงตอนเข้าดูองค์กรด้วยสิทธิ์เข้าช่วยเหลือ ถ้าอยู่แท็บอื่นจะใช้การแจ้งเตือนของเบราว์เซอร์แทน

| เตือนเมื่อ | กดแล้วไปที่ |
| --- | --- |
| เรื่องใน "ต้องจัดการ" ระดับวิกฤต ได้แก่ งานเบื้องหลังหยุด ดิสก์เหลือน้อยกว่า 10% สำรองข้อมูลไม่สำเร็จ ไลบรารีมีช่องโหว่ระดับสูง องค์กรใช้พื้นที่เต็มโควตา และองค์กรไม่เหลือผู้ดูแล | ที่แก้ของเรื่องนั้น |
| การแจ้งเตือนความปลอดภัยใหม่ ระดับเฝ้าระวังหรือวิกฤต | หน้าความปลอดภัย |

- เรื่องใน "ต้องจัดการ" เตือนตอนเริ่มเกิด ถ้าแก้แล้วกลับมาเกิดอีกจะเตือนใหม่
- การแจ้งเตือนความปลอดภัยเตือนครั้งเดียวต่อรายการ การโจมตีที่ยังต่อเนื่องจะนับรวมในรายการเดิม
- เรื่องที่มีอยู่แล้วตอนเปิดหน้าไม่เตือนซ้ำ ดูได้ที่กระดิ่ง
- เรื่องระดับรองลงมา เช่น ยังไม่ได้ตั้งอีเมลหรือยังไม่ได้กำหนดโควตา อยู่ในกระดิ่งอย่างเดียว

ผู้ดูแลเลือกได้ที่ ตั้งค่าบัญชี → การแจ้งเตือน ว่าจะรับทางป๊อปอัป (เปิดไว้ตั้งแต่แรก) เบราว์เซอร์ และเสียง โดยเสียงเรื่องวิกฤตจะเร่งกว่าเสียงระดับเฝ้าระวัง ส่วนรายการที่เตือนกำหนดไว้ตายตัว เลือกปิดทีละเรื่องไม่ได้

## ภาพรวมระบบ

| ส่วน | บอกอะไร |
|---|---|
| ต้องจัดการ | สิ่งที่ขาดหรือเสียตอนนี้ ด่วนสุดก่อน พร้อมที่ที่ต้องไปแก้ |
| เซิร์ฟเวอร์ | เวลาทำงาน รุ่นของ Python ขนาดฐานข้อมูลและไฟล์แนบ พื้นที่ดิสก์ (เตือนเมื่อเหลือน้อยกว่า 10%) และงานเบื้องหลังพร้อมคิวที่รอ |
| การสำรองข้อมูล | สำรองตอนนี้ สำรองอัตโนมัติ และกู้คืน ดู [ดูแลระบบ](../operations.md) |
| ช่องทางของทุกองค์กร | LINE อีเมล Facebook ที่ล้มเหลวและสาเหตุ สั่งส่งข้อความที่ล้มเหลวซ้ำได้ |
| การใช้งานขององค์กร | คะแนนสุขภาพ เคสที่เปิด ข้อความใน 7 วัน พื้นที่เทียบเพดาน และการใช้งานล่าสุด |
| ความปลอดภัยโดยย่อ | เข้าสู่ระบบล้มเหลว บัญชีที่ถูกล็อก IP ที่บล็อก กับดัก และการแจ้งเตือนที่เปิดอยู่ |
| การใช้ API | จำนวนคำขอรายชั่วโมงใน 24 ชั่วโมงล่าสุด แยกตามส่วนของระบบและองค์กร |
| ข้อผิดพลาดล่าสุด | ข้อผิดพลาดและเหตุการณ์ของแพลตฟอร์ม |

- ตัวเลขการใช้งานและข้อผิดพลาดเก็บในหน่วยความจำ เริ่มนับใหม่เมื่อเปิด API ใหม่
- บันทึกเส้นทาง API เฉพาะคำขอที่ผิดพลาด และไม่เก็บ query string
- หน้าอัปเดตเองทุก 30 วินาที ส่วนที่ดูข้ามองค์กรทุกนาที
- ภาพรวมไม่อ่านเนื้อหาของเคสหรือบทสนทนาใด

## จัดการองค์กร

- **รายการ** ค้นหาชื่อหรือรหัส กรองสถานะ แบ่งหน้า แสดงเฉพาะสิ่งที่ใช้หาและคัดกรอง ได้แก่ ชื่อ ผู้ดูแล จำนวนสมาชิก สถานะ และสิทธิ์เข้าช่วยเหลือ ที่เหลืออยู่ในหน้าขององค์กร
- **สร้างองค์กร** ใส่ชื่อ รหัส (a-z ตัวเลข และขีดกลาง ไม่เกิน 60 ตัว ห้ามซ้ำ) และผู้ดูแลคนแรก ระบบสร้างไฟล์ฐานข้อมูลของตัวเองให้
- **หน้าขององค์กร** รวมทุกอย่างขององค์กรเดียว: ข้อมูล สวิตช์ฟีเจอร์ เพดานพื้นที่ รหัสองค์กร ผู้ดูแล สิทธิ์เข้าช่วยเหลือ และการระงับ
- **เชิญผู้ดูแลองค์กร** ทางอีเมล หรือสร้างบัญชีพร้อมรหัสผ่านแรกเมื่อยังไม่มีอีเมลของแพลตฟอร์ม ระบบเตือนเมื่อองค์กรยังไม่มีผู้ดูแล
- **ขอสิทธิ์เข้าช่วยเหลือ** ดู [บทบาทและสิทธิ์](../roles-and-permissions.md#สิทธิ์เข้าช่วยเหลือ)
- **ระงับองค์กร** ต้องพิมพ์ CONFIRM หรือชื่อองค์กร ระงับองค์กรของแพลตฟอร์มเองไม่ได้ มีผลในคำขอถัดไป ข้อมูลที่แสดงหรือดาวน์โหลดไปก่อนหน้านั้นเรียกคืนไม่ได้
- **เพดานพื้นที่** ตั้งต่อองค์กร 0 หมายถึงไม่จำกัด ถึงเพดานแล้วปฏิเสธเฉพาะการอัปโหลดใหม่
- **การยืนยันสองขั้นตอนของทีมงาน** รายชื่อทีมงานขององค์กรพร้อมวิธีที่แต่ละคนใช้ยืนยันตัวตน รีเซ็ตให้คนที่ทำโทรศัพท์และรหัสสำรองหายได้ ระบบถามรหัสผ่านซ้ำ ลบแอปยืนยันตัวตน รหัสสำรอง และ Passkey ทั้งหมด ออกจากระบบทุกอุปกรณ์ บันทึกในประวัติแพลตฟอร์มและประวัติของบัญชี แล้วส่งอีเมลแจ้งเจ้าของบัญชี

## บัญชีผู้ใช้

ระงับองค์กรหยุดทุกคนในองค์กร ส่วนการตัดการเข้าสู่ระบบอยู่ได้แค่จนกว่าจะเข้าใหม่ คนที่รู้รหัสผ่านจึงกลับเข้ามาได้ทันที หน้านี้จัดการที่ตัวบัญชี

- **ค้นหา** พิมพ์อีเมลอย่างน้อย 3 ตัวอักษร ได้ทั้งบัญชีทีมงานและบัญชีลูกค้า พร้อมองค์กรที่แต่ละบัญชีอยู่ บทบาท และสถานะระงับ
- **ระงับบัญชี** ออกจากระบบทุกอุปกรณ์ทันที และเข้าสู่ระบบไม่ได้ทุกวิธี ทั้งรหัสผ่าน ยืนยันสองขั้นตอน Passkey และตั้งรหัสผ่านใหม่จากลิงก์ มีผลทุกองค์กรจนกว่าผู้ดูแลแพลตฟอร์มจะยกเลิก
- **บังคับตั้งรหัสผ่านใหม่** ใช้เมื่อรหัสผ่านรั่วแต่อีเมลยังเป็นของเจ้าของ รหัสผ่านเดิมใช้ไม่ได้ทันที ออกจากระบบทุกอุปกรณ์ ลบ Passkey ทั้งหมด แล้วส่งลิงก์ตั้งรหัสผ่านใหม่ทางอีเมล ต้องตั้งอีเมลของระบบก่อน ถ้าอีเมลก็ถูกยึดไปด้วยให้ระงับแทน
- ทั้งสองอย่างถามรหัสผ่านซ้ำ ใส่เหตุผลได้ และบันทึกในประวัติแพลตฟอร์มและประวัติของบัญชี
- บัญชีผู้ดูแลแพลตฟอร์มแสดงในผลค้นหา แต่จัดการที่ ทีมผู้ดูแลระบบ

### ปิดองค์กรถาวร

สำหรับองค์กรที่เลิกใช้แล้ว เพื่อไม่ให้ข้อมูลลูกค้าค้างอยู่ตลอด (PDPA) และคืนพื้นที่ดิสก์ ทำที่หน้าขององค์กรตามลำดับ แต่ละขั้นทำได้เมื่อขั้นก่อนเสร็จ

1. ระงับองค์กร
2. ส่งออกข้อมูลทั้งองค์กรเป็นไฟล์ ZIP (ฐานข้อมูลและไฟล์แนบ รูปแบบเดียวกับที่เจ้าขององค์กรสำรองเอง) แล้วส่งให้เจ้าขององค์กร หน้าองค์กรบอกวันที่ส่งออกล่าสุด
3. กด "ปิดถาวร" พิมพ์รหัสองค์กรให้ตรง และยืนยันรหัสผ่าน ต้องส่งออกภายใน 30 วันก่อนหน้า

สิ่งที่ถูกลบ ได้แก่ ฐานข้อมูลและไฟล์แนบขององค์กร Token ของช่องทางและคีย์ AI ข้อมูลขององค์กรในฐานข้อมูลแพลตฟอร์ม (สมาชิก คำเชิญ ลิงก์เชิญ การเชื่อมช่องทาง ความเชื่อมโยงกับบัญชีลูกค้า คำขอเข้าช่วยเหลือ รายงานปัญหา สวิตช์ฟีเจอร์) และบัญชีทีมงานที่ไม่ได้อยู่องค์กรอื่น

สิ่งที่ยังอยู่

- รหัสองค์กร ถูกจองไว้ ลิงก์เดิมของลูกค้าจึงขึ้นว่าไม่พบ แทนที่จะพาไปองค์กรอื่น
- ประวัติแพลตฟอร์มและบันทึกความปลอดภัย ซึ่งเก็บเพียงรหัสอ้างอิง
- บัญชีลูกค้า เพราะเป็นของลูกค้าเองและอาจอยู่หลายองค์กร ลบได้จากบัญชีลูกค้าหรือเครื่องมือ PDPA
- ไฟล์สำรองทั้งแพลตฟอร์มที่ทำไว้ก่อนหน้า จนกว่าจะถูกลบตามรอบ

ปิดองค์กรหลักของแพลตฟอร์มไม่ได้

### องค์กรที่หลับ

องค์กรที่ไม่มีทีมงานคนใดเปิดแอปและไม่มีเคสใหม่ 90 วัน ยังกินพื้นที่ และเป็นบัญชีที่ถูกทิ้งไว้ (รหัสผ่านของผู้ดูแลที่ลืมไปแล้วยังเปิดทุกอย่างได้)

- เรียงตามหลับนานสุดก่อน พร้อมสิ่งที่ยังเก็บอยู่ และใครดูแล
- ติดต่อเจ้าของทางอีเมลของแพลตฟอร์ม หรือระงับ
- องค์กรที่อายุไม่ถึง 90 วัน และองค์กรของแพลตฟอร์มเอง ไม่ถูกนับว่าหลับ
- ถ้าลูกค้ายังเขียนเข้ามา ระบบแสดงไว้ข้างกัน เพราะอาจเป็นเหตุผลให้ปลุกทีมแทนการระงับ

## สุขภาพองค์กร

คะแนนเดียวต่อองค์กร ตอบว่าองค์กรไหนปกติ องค์กรไหนมีปัญหา รวมจาก 4 เรื่องที่องค์กรมักพลาด

| เรื่อง | วัดอะไร |
|---|---|
| ตอบในเวลา | เคสที่ตอบภายในเวลาที่องค์กรสัญญาเอง |
| ความพอใจ | คะแนนที่ลูกค้าให้ 1 ถึง 5 |
| งานค้าง | เคสที่เปิดอยู่และเกินกำหนดแก้ไขแล้ว เทียบกับเคสที่เปิดทั้งหมด |
| ช่องทาง | LINE อีเมล Facebook ที่ล้มเหลวหรือค้าง |

- เรื่องที่ไม่มีข้อมูลไม่ถูกนับในค่าเฉลี่ย แทนการนับเป็นศูนย์ องค์กรใหม่ที่ยังไม่มีเคสจึงเป็น "ใหม่" ไม่ใช่ "มีปัญหา"
- ทุกคะแนนแสดงตัวเลขดิบข้างกัน เช่น "ตอบในเวลา 22 จาก 50" คะแนนที่แยกดูไม่ได้ไม่มีใครลงมือแก้
- หนึ่งแถวต่อองค์กร แย่สุดก่อน กรอง "มีปัญหา" ได้ในคลิกเดียว

## FAQ กลาง

เขียนบทความครั้งเดียว แล้วเลือกผู้อ่าน

| ผู้อ่าน | แสดงที่ |
|---|---|
| เฉพาะผู้ดูแลแพลตฟอร์ม | ในคอนโซลนี้ |
| เจ้าขององค์กรและทีมงาน | เมนู **คู่มือจาก Bookdose** ของทุกองค์กร |
| ลูกค้าปลายทาง | ต่อท้ายบทความสาธารณะขององค์กร ในคำถามที่พบบ่อยของลูกค้าทุกองค์กร |

- บทความใหม่เป็นร่าง ยังไม่มีใครเห็น จนกว่าจะกดเผยแพร่ เพราะความผิดพลาดจะแสดงในทุกองค์กรพร้อมกัน
- การแก้บทความที่เผยแพร่แล้วรอเป็นร่างคู่กัน ผู้อ่านยังเห็นรุ่นที่เผยแพร่ จนกว่าจะเผยแพร่การแก้ไข หรือทิ้งการแก้ไข
- ระบบใส่บทความเริ่มต้นให้ครั้งเดียว ลบแล้วไม่ถูกเพิ่มกลับ

## คลังบทความแม่แบบ

คำถามที่ทุกองค์กรถูกถาม เขียนครั้งเดียวที่นี่ องค์กรคัดลอกไปแก้เป็นคำของตัวเองได้ในคลิกเดียว สำเนาเป็นขององค์กรทันที การแก้หรือลบแม่แบบภายหลังไม่กระทบสำเนา ดู [คลังความรู้](knowledge-base.md#คลังบทความแม่แบบ)

## ประกาศ

- **ประกาศสถานะระบบ** สำหรับเหตุที่เกิดตอนนี้ แสดงบนหน้าสถานะสาธารณะ `/status`
- **ประกาศถึงทุกองค์กร** สำหรับเรื่องที่วางแผนไว้ แสดงเป็นแถบในแอปของทุกองค์กร และลูกค้าเมื่อเลือก

### ปิดปรับปรุง

เมื่อประกาศสถานะระบบเป็น "ปิดปรับปรุงตามแผน" ระบบหยุดรับการแก้ไขข้อมูลจริง จนกว่าจะกด "เอาประกาศออก"

- เจ้าหน้าที่ ลูกค้า และผู้เยี่ยมชมยังดูข้อมูลได้ แต่บันทึก ส่งข้อความ หรือแก้ไขอะไรไม่ได้ ระบบตอบว่าปิดปรับปรุงอยู่
- ทุกหน้าในแอปของเจ้าหน้าที่และลูกค้ามีแถบบอกว่าปิดปรับปรุงพร้อมข้อความที่ประกาศไว้ แทนประกาศถึงทุกองค์กรชั่วคราว
- ยังทำได้ตามปกติ ได้แก่ คอนโซลระบบกลาง การเข้าและออกจากระบบ และการเลิกใช้งานอุปกรณ์อื่น
- ข้อความที่ลูกค้าส่งทาง LINE และ Facebook ยังเข้ามาตามปกติ ไม่สูญหาย ข้อความตอบที่อยู่ในคิวก่อนปิดปรับปรุงยังส่งออกไป
- สถานะอื่น (กำลังตรวจสอบ ใช้งานได้บางส่วน ขัดข้อง) เป็นเพียงข้อความบนหน้าสถานะ ไม่ปิดการแก้ไข

ดู [ประกาศปัญหาและหน้าสถานะ](known-issues-and-status.md)

## รายงานปัญหา

ทีมงานขององค์กรแจ้งปัญหาของตัวระบบจากปุ่ม **?** บนแถบด้านบน ลูกค้าที่เข้าสู่ระบบก็แจ้งได้ (ระบุว่าเป็นของลูกค้า) รายงานมาที่แพลตฟอร์ม ไม่ผ่านเจ้าขององค์กร เพราะคนในองค์กรแก้ตัวระบบไม่ได้

- แนบหน้าที่ผู้แจ้งอยู่และเบราว์เซอร์ที่ใช้ เพื่อทำซ้ำได้ ไม่แนบบทสนทนากับลูกค้า
- หน้านี้อ่านและทำเครื่องหมายว่าจัดการแล้วเท่านั้น ติดต่อผู้แจ้งทางอีเมลที่แสดงในแถว
- แจ้งได้ไม่เกิน 5 ครั้งต่อ 10 นาทีต่อคน

## เครื่องมือ PDPA

บุคคลขอดูข้อมูลของตัวเอง หรือขอให้ลบ

1. ค้นหาครั้งเดียวด้วยอีเมล เบอร์โทร (เขียนแบบใดก็ได้) หรือชื่อ ทุกองค์กรตอบพร้อมกัน ผลแสดงเพียงจำนวน ไม่แสดงบทสนทนา
2. ติ๊กรายการที่เป็นของบุคคลนั้น และระบุว่าคำขอมาจากไหน
3. **ส่งออก** เป็น ZIP มีบัญชีและประวัติการเข้าสู่ระบบ และต่อองค์กร: ข้อมูลลูกค้า ข้อมูลผู้เยี่ยมชม บทสนทนาแบบที่ลูกค้าเห็น (ไม่มีบันทึกภายใน) พร้อมไฟล์ และเคสพร้อมคะแนนและช่องข้อมูลเพิ่มเติมที่ทีมกรอก
4. หรือ **ลบ** ต้องพิมพ์ยืนยัน รายละเอียดสิ่งที่ถูกลบอยู่ใน [การแยกข้อมูลและความลับ](../security/data-isolation-and-secrets.md#การลบข้อมูลบุคคล)

ทุกครั้งบันทึกทั้งที่นี่และในประวัติของแต่ละองค์กร ข้างกันมีรายการคำขอลบข้อมูลที่องค์กรบันทึกไว้ในข้อมูลลูกค้า ไฟล์สำรองที่ทำไว้ก่อนยังมีข้อมูลอยู่จนกว่าจะหมดอายุ หน้าจอบอกเรื่องนี้

## ทีมผู้ดูแลระบบ

- ผู้ดูแลทุกคนเห็นรายชื่อ
- เฉพาะเจ้าของแพลตฟอร์มเพิ่มสิทธิ์ให้บัญชีที่มีอยู่ สร้างบัญชีใหม่ หรือถอดสิทธิ์ได้
- ถอดเจ้าของไม่ได้
- สิทธิ์มีผลตั้งแต่คำขอถัดไป และบันทึกในประวัติของแพลตฟอร์ม

## ความปลอดภัยของบัญชีผู้ดูแล

- บนเซิร์ฟเวอร์จริง ผู้ดูแลทุกคนต้องเปิดการยืนยันสองขั้นตอนหรือเพิ่ม Passkey ก่อน จึงจะใช้คอนโซลได้ (ปิดเปิดด้วย `BOOKDOSE_PLATFORM_2FA` บนเครื่องพัฒนาไม่บังคับ) ผู้ดูแลใหม่เข้าสู่ระบบแล้วจะเห็นปุ่มไปตั้งค่าแทนหน้าคอนโซล รายการ **ต้องจัดการ** ของภาพรวมระบบบอกผู้ดูแลที่ยังไม่ได้ตั้ง
- รายการอันตราย เช่น กู้คืนข้อมูล เครื่องมือ PDPA ระงับองค์กร และแก้ตั้งค่าอีเมล ถามรหัสผ่านซ้ำถ้ายืนยันไว้นานกว่า 5 นาที
- เข้าสู่ระบบจาก IP หรืออุปกรณ์ใหม่ ระบบส่งอีเมลพร้อมลิงก์ **ไม่ใช่ฉัน** ที่ยุติการเข้าสู่ระบบนั้นได้ทันที
- รายละเอียดอยู่ใน [การยืนยันตัวตน](../security/authentication.md#บัญชีผู้ดูแลแพลตฟอร์ม)

## ฐานข้อมูล IP

**ความปลอดภัย → ตั้งค่า → ฐานข้อมูล IP** กดดาวน์โหลดครั้งเดียว แล้วระบบอัปเดตเองทุกเดือน หน้าความปลอดภัยจะบอกประเทศและผู้ให้บริการข้าง IP พร้อมป้าย **คลาวด์หรือ VPN** และการเข้าสู่ระบบของผู้ดูแลถูกตรวจละเอียดขึ้น ดู [ข้อมูล IP](../security/monitoring-and-traps.md#ข้อมูล-ip-และการตรวจการปลอมตัว)

## ตั้งค่าระบบ

| ส่วน | ใช้ทำอะไร |
|---|---|
| อีเมล | SMTP ของแพลตฟอร์ม ส่งอีเมลยืนยันการสมัคร คำเชิญ ลืมรหัสผ่าน แจ้งเตือนลูกค้า และแจ้งเตือนผู้ดูแล พร้อมโดเมนเว็บไซต์ที่ใช้ในลิงก์ |
| SMS | ผู้ให้บริการส่งลิงก์ติดตามแชทของผู้เยี่ยมชม |
| Turnstile | ตัวตรวจว่าเป็นคนจริงในฟอร์มเริ่มแชทสาธารณะ |

### อีเมลของแพลตฟอร์ม

- กรอกโดเมนเว็บไซต์ (เช่น `https://support.example.com`) อีเมลผู้ส่ง เซิร์ฟเวอร์ SMTP พอร์ต 465 (TLS) หรือ 587 (STARTTLS) ชื่อผู้ใช้ และรหัสผ่านหรือ App Password
- โดเมนต้องเป็นที่อยู่ของหน้าเว็บที่ลูกค้าเปิดได้ ลิงก์ในอีเมลใช้ค่านี้ ไม่ใช้ Host จากคำขอ
- เปิด **รับสมัครองค์กรใหม่พร้อมยืนยันอีเมล** ได้เมื่อตั้งอีเมลแล้ว ถ้ายังไม่ตั้ง ระบบปิดรับสมัครองค์กรใหม่
- การบันทึกตรวจรูปแบบค่า แต่ไม่ได้ลองส่งจริง ตรวจด้วยการสมัครด้วยอีเมลของตัวเอง
- ใช้ SMTP แบบรหัสผ่านเท่านั้น ยังไม่รองรับ OAuth สำหรับอีเมลของแพลตฟอร์ม
- ถ้า SMTP ตอบผลไม่แน่นอน ระบบไม่ส่งซ้ำเอง

### SMS

| ผู้ให้บริการ | ใช้กับ |
|---|---|
| ปิด (ค่าเริ่มต้น) | ซ่อนตัวเลือก SMS จากหน้าแชท |
| ทดสอบใน log | เขียนข้อความลง log ของเซิร์ฟเวอร์แทนการส่ง ห้ามใช้กับลูกค้าจริง |
| ThaiBulkSMS | เบอร์ไทย ต้องลงทะเบียนชื่อผู้ส่งกับ ThaiBulkSMS ก่อน |
| Twilio | ทุกประเทศ จากเบอร์ Twilio หรือ Messaging Service |

- ข้อมูลลับของผู้ให้บริการเข้ารหัสเก็บ ช่องว่างหมายถึงใช้ค่าเดิม แต่ละผู้ให้บริการเก็บของตัวเอง สลับไปมาไม่หาย
- ปุ่มส่งทดสอบถึงเบอร์จริง (5 ครั้งต่อชั่วโมง)
- หมดเวลารอถือว่าอาจส่งแล้ว และไม่ส่งซ้ำ เครดิตหมด ข้อมูลลับผิด หรือเบอร์ผิด ถือว่าจบ

### Turnstile

ใส่ Site Key (สาธารณะ) และ Secret Key (เข้ารหัสเก็บ ไม่แสดงอีก) แล้วเปิดใช้ ขณะปิด ฟอร์มเริ่มแชททำงานเหมือนเดิม
