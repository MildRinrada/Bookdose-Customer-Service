# วิธีรันโค้ด

เอกสารนี้พาตั้งแต่ติดตั้งจนเปิดระบบได้บนเครื่องตัวเอง ถ้าจะนำขึ้นเซิร์ฟเวอร์จริง อ่านต่อที่ [นำขึ้นเซิร์ฟเวอร์](deployment.md)

## สิ่งที่ต้องมี

| โปรแกรม | รุ่น | ใช้ทำอะไร |
|---|---|---|
| Python | 3.10 ขึ้นไป | API และฐานข้อมูล |
| Node.js | 20 ขึ้นไป | หน้าเว็บ Next.js |

แพ็กเกจ Python อยู่ใน `requirements.txt` ตรึงรุ่นไว้ทุกตัว ส่วนแพ็กเกจของหน้าเว็บอยู่ใน `frontend/package.json`

## เปิดระบบแบบง่าย

ใช้สคริปต์ที่เตรียมไว้ เหมาะกับการเปิดใช้งานบนเครื่องเดียว

| ระบบปฏิบัติการ | ไฟล์ |
|---|---|
| Windows | `Start Bookdose.bat` |
| macOS | `Start Bookdose.command` |

ดับเบิลคลิกแล้วเปิด http://localhost:3000

สคริปต์ทำสิ่งเหล่านี้ให้

1. ติดตั้งแพ็กเกจ Python ถ้ายังไม่มี
2. ติดตั้งแพ็กเกจของหน้าเว็บ ถ้ายังไม่มีโฟลเดอร์ `frontend/node_modules`
3. build หน้าเว็บครั้งแรก
4. เปิด API ที่พอร์ต 8787 และหน้าเว็บที่พอร์ต 3000 ในหน้าต่างเดียวกัน

ปิดระบบด้วย `Ctrl+C` ข้อมูลยังอยู่เมื่อเปิดใหม่

หลังอัปเดตโค้ด ให้ลบโฟลเดอร์ `frontend/.next` ก่อน สคริปต์จะ build หน้าเว็บใหม่ให้

## เปิดระบบแบบโหมดพัฒนา

แก้โค้ดแล้วเห็นผลทันที เปิด Terminal 2 หน้าต่างที่โฟลเดอร์โปรเจกต์

**หน้าต่างที่ 1: API**

```sh
python -m pip install -r requirements.txt
python app.py
```

ติดตั้งแพ็กเกจครั้งแรก และทุกครั้งที่ `requirements.txt` เปลี่ยน

**หน้าต่างที่ 2: หน้าเว็บ**

```sh
cd frontend
npm install
npm run dev
```

เปิด http://localhost:3000

API ไม่โหลดโค้ดใหม่เอง ถ้าแก้โค้ด Python ต้องหยุดแล้วเปิด `python app.py` ใหม่ ส่วนหน้าเว็บในโหมด `npm run dev` โหลดใหม่เอง

## ตัวเลือกของ app.py

| ตัวเลือก | ความหมาย |
|---|---|
| `--host` | ที่อยู่ที่เปิดรับ ค่าเริ่มต้น `127.0.0.1` ใช้ได้เฉพาะเครื่องนี้ |
| `--port` | พอร์ตของ API ค่าเริ่มต้น `8787` |
| `--secure-cookies` | ใส่ `Secure` ให้คุกกี้ ใช้เมื่อมี HTTPS อยู่ด้านหน้าแล้วเท่านั้น |
| `--backup ZIP` | สำรองข้อมูลทั้งระบบแล้วจบ ดู [ดูแลระบบ](operations.md) |
| `--restore ZIP` | กู้คืนไปยังโฟลเดอร์ข้อมูลที่ยังว่างแล้วจบ |
| `--new-key` | ใช้คู่กับ `--restore` เมื่อกุญแจเข้ารหัสของไฟล์สำรองหายไป |
| `--demo-users` | สร้างบัญชีทดสอบในโฟลเดอร์ข้อมูลที่ยังว่างแล้วจบ ดู [บัญชีทดสอบ](#บัญชีทดสอบ) |

API ทำงานแบบ worker เดียวเสมอ เพราะการจำกัดคำขอ ฐานข้อมูล SQLite และงานเบื้องหลังอยู่ใน process เดียวกัน

## ตั้งค่าครั้งแรก

เมื่อเปิดระบบครั้งแรก หน้าเข้าสู่ระบบจะเป็นหน้าสร้างผู้ดูแลแพลตฟอร์ม

1. กรอกชื่อ อีเมล และรหัสผ่าน 10 ถึง 200 ตัวอักษร
2. กรอกชื่อองค์กรแรกและรหัสองค์กร เช่น `bookdose` รหัสใช้ตัว a-z ตัวเลข และขีดกลาง
3. เลือกว่าจะใส่ข้อมูลตัวอย่างหรือไม่ ข้อมูลตัวอย่างมีลูกค้า เคส บทความ และ Macro ให้ลองใช้
4. กดสร้าง
5. บนเซิร์ฟเวอร์จริง หน้าคอนโซลจะมีปุ่ม **ไปตั้งค่าความปลอดภัย** ให้เปิดการยืนยันสองขั้นตอนหรือเพิ่ม Passkey ก่อน จึงจะใช้คอนโซลระบบกลางได้ บนเครื่องพัฒนาไม่บังคับ ดู [บัญชีผู้ดูแลแพลตฟอร์ม](security/authentication.md#บัญชีผู้ดูแลแพลตฟอร์ม)

บัญชีนี้เป็น **เจ้าของแพลตฟอร์ม** ดูแลระบบอย่างเดียว ไม่ได้เป็นทีมงานขององค์กรแรก ถ้าจะให้มีคนรับเรื่องขององค์กรแรก ให้เข้า **คอนโซลระบบกลาง → จัดการองค์กร** แล้วเชิญผู้ดูแลองค์กร เหตุผลอยู่ใน [บทบาทและสิทธิ์](roles-and-permissions.md)

ระบบไม่มีบัญชีหรือรหัสผ่านเริ่มต้นฝังไว้ในโค้ด ยกเว้นบัญชีทดสอบด้านล่าง ซึ่งสร้างเมื่อสั่งเองเท่านั้น

## บัญชีทดสอบ

ใช้แทนการตั้งค่าครั้งแรก เมื่อต้องการให้คนอื่นลองระบบด้วยบัญชีชุดเดียวกัน รันครั้งเดียวก่อนเปิดระบบครั้งแรก

```sh
python app.py --demo-users
python app.py
```

| บทบาท | อีเมล | รหัสผ่าน |
|---|---|---|
| เจ้าของแพลตฟอร์ม | `teerawat@bookdose.com` | `Platform-owner-123` |
| ผู้ดูแลแพลตฟอร์ม | `mildppgd@gmail.com` | `Platform-admin-123` |
| ผู้ดูแลองค์กร (องค์กรทดสอบ) | `org.admin@example.com` | `Org-admin-123` |
| เจ้าหน้าที่องค์กร | `org.agent@example.com` | `Org-agent-123` |
| ลูกค้า | `customer.test@example.com` | `Customer-test-123` |

คำสั่งนี้สร้างให้

1. องค์กรหลักของแพลตฟอร์ม `bookdose` ไม่มีสมาชิก เหมือนตั้งค่าครั้งแรก
2. องค์กรทดสอบ `test-org` พร้อมข้อมูลตัวอย่าง (เคส 5 เคส บทความ และ Macro) มีผู้ดูแลองค์กรและเจ้าหน้าที่ข้างบน
3. บัญชีลูกค้าที่ยืนยันอีเมลแล้ว และเชื่อมกับองค์กรทดสอบ

ข้อควรรู้

- ใช้ได้เฉพาะโฟลเดอร์ข้อมูลที่ยังไม่มีบัญชี ถ้ามีแล้วคำสั่งจะหยุดโดยไม่แก้อะไร อยากเริ่มใหม่ให้ตั้ง `BOOKDOSE_DATA` เป็นโฟลเดอร์ว่าง
- รหัสผ่านเหล่านี้อยู่ในโค้ด ทุกคนที่เห็น repo รู้ ใช้กับเครื่องทดสอบเท่านั้น ห้ามใช้กับเซิร์ฟเวอร์ที่มีลูกค้าจริง
- รหัสผ่านของบัญชีผู้ดูแลแพลตฟอร์มเป็นรหัสทดสอบ ไม่ใช่รหัสจริงของอีเมลนั้น
- ยังไม่มีการตั้งค่า OpenAI, LINE, Facebook หรืออีเมล ใครจะลองฟีเจอร์เหล่านี้ต้องใส่ค่าของตัวเอง
- เข้าสู่ระบบผิดหรือถูกรวมกันเกิน 15 ครั้งใน 15 นาทีจากเครื่องเดียว ระบบจะให้รอ ถ้ารีบให้ปิดแล้วเปิด `python app.py` ใหม่

รายชื่อบัญชีแก้ได้ที่ `backend/database/demo_users.py`

## ตัวแปรแวดล้อม

ทุกตัวไม่บังคับเมื่อใช้บนเครื่องเดียว

### ฝั่ง API

ตั้งเป็นตัวแปรแวดล้อม หรือเขียนในไฟล์ `.env` ที่โฟลเดอร์โปรเจกต์ (ตัวอย่างใน `.env.example`) ค่าจากตัวแปรแวดล้อมจริงชนะค่าใน `.env`

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `BOOKDOSE_DATA` | `data/` | โฟลเดอร์เก็บฐานข้อมูล ไฟล์แนบ และความลับ |
| `BOOKDOSE_HOST` | `127.0.0.1` | ค่าเริ่มต้นของ `--host` |
| `BOOKDOSE_PORT` | `8787` | ค่าเริ่มต้นของ `--port` |
| `BOOKDOSE_SECURE_COOKIES` | ปิด | ค่าเริ่มต้นของ `--secure-cookies` |
| `BOOKDOSE_SERVER` | `fastapi` | `legacy` เปิดเซิร์ฟเวอร์รุ่นเก่า (`http.server`) ไว้ย้อนกลับเท่านั้น |
| `BOOKDOSE_SETUP_TOKEN` | ว่าง | รหัสที่ต้องกรอกตอนตั้งค่าครั้งแรก บน Render ต้องยาว 32 ตัวอักษรขึ้นไป |
| `BOOKDOSE_PLATFORM_2FA` | ว่าง | `on` บังคับให้ผู้ดูแลแพลตฟอร์มเปิดการยืนยันสองขั้นตอนหรือ Passkey ก่อนใช้คอนโซล `off` ไม่บังคับ ถ้าว่าง บังคับเมื่อรันแบบ production (เปิด `--secure-cookies` หรืออยู่บน Render) และไม่บังคับบนเครื่องพัฒนา |
| `BOOKDOSE_PROXY_SECRET` | ว่าง | ความลับร่วมกับหน้าเว็บ ต้องตั้งเมื่อหน้าเว็บอยู่คนละเครื่อง |
| `BOOKDOSE_SECRET_KEY` | ไฟล์ `data/keys/secret.key` | กุญแจเข้ารหัสความลับ ควรตั้งบนเซิร์ฟเวอร์จริง |
| `BOOKDOSE_SECRET_KEY_OLD` | ว่าง | กุญแจเก่า คั่นด้วยจุลภาค ใช้ตอนเปลี่ยนกุญแจ |
| `BOOKDOSE_BACKUP_DIR` | โฟลเดอร์ `backups` ข้างโฟลเดอร์ข้อมูล | ที่เก็บไฟล์สำรองที่สร้างจากคอนโซล |

สร้างกุญแจใหม่ได้ด้วย `python -m backend.utils.secret_box new-key`

### ฝั่งหน้าเว็บ

เขียนในไฟล์ `frontend/.env.local` (ตัวอย่างใน `frontend/.env.example`)

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `BOOKDOSE_API_URL` | `http://127.0.0.1:8787` | ที่อยู่ของ API |
| `BOOKDOSE_PROXY_SECRET` | ว่าง | ค่าเดียวกับฝั่ง API |
| `BOOKDOSE_TRUST_FORWARDED_FOR` | ว่าง | ตั้งเป็น `1` เมื่อมี load balancer ที่ใส่ `X-Forwarded-For` อยู่ด้านหน้า |
| `PORT` | `3000` | พอร์ตของหน้าเว็บ |

## เมื่อพอร์ตถูกใช้อยู่

**พอร์ต 8787 ไม่ว่าง:** เปิด API ที่พอร์ตอื่น แล้วบอกหน้าเว็บให้ตามไป

```sh
python app.py --port 8788
```

แล้วตั้ง `BOOKDOSE_API_URL=http://127.0.0.1:8788` ใน `frontend/.env.local`

**พอร์ต 3000 ไม่ว่าง:** ตั้ง `PORT=3001` ก่อน `npm run dev` หรือ `npm start`

## ข้อมูลเก็บที่ไหน

```text
data/
  control.sqlite3              ฐานข้อมูลกลาง: บัญชี เซสชัน องค์กร สมาชิก การตั้งค่าแพลตฟอร์ม
  tenants/<tenant-id>.sqlite3  ฐานข้อมูลของแต่ละองค์กร แยกไฟล์กัน
  files/<tenant-id>/           ไฟล์แนบของแต่ละองค์กร
  secrets/                     ความลับที่เข้ารหัสแล้ว เช่น token ของ LINE และรหัสผ่านอีเมล
  keys/secret.key              กุญแจเข้ารหัส เมื่อไม่ได้ตั้ง BOOKDOSE_SECRET_KEY
```

โฟลเดอร์ `data/` ไม่อยู่ใน Git ห้ามนำขึ้น Git เด็ดขาด

## การทดสอบ

**ตรวจทั้งหมดในคำสั่งเดียว**

```sh
python scripts/check.py
```

ตรวจ syntax ของ Python, ตรวจ type และ lint ของหน้าเว็บ (ถ้าติดตั้ง `frontend/node_modules` แล้ว) แล้วรันชุดทดสอบทั้งหมด

**รันเฉพาะชุดทดสอบของ API**

```sh
python -m unittest discover -s tests
```

รันเฉพาะไฟล์เดียวได้ เช่น `cd tests` แล้ว `python -m unittest test_automation`

ชุดทดสอบใช้โฟลเดอร์ข้อมูลชั่วคราว ไม่แตะข้อมูลจริง บริการภายนอก เช่น OpenAI, LINE, Meta และ SMTP ใช้ตัวจำลองใน `tests/*_fixture_server.py` จึงไม่ส่งข้อความจริงและไม่เสียค่าใช้บริการ

บน Windows มีเทสต์ที่ตรวจสิทธิ์ไฟล์แบบ POSIX (`0600`) ไม่ผ่าน เพราะ Windows ไม่ใช้สิทธิ์แบบนั้น เป็นข้อจำกัดของระบบปฏิบัติการ ไม่ใช่ข้อผิดพลาดของโค้ด ดู [ความปลอดภัย](security/README.md)

**ตรวจหน้าเว็บ**

```sh
cd frontend
npm run typecheck
npm run lint
npm run build
```

ยังไม่มีชุดทดสอบเบราว์เซอร์อัตโนมัติสำหรับหน้าเว็บ

**ทดสอบกับเซิร์ฟเวอร์รุ่นเก่า**

```sh
BOOKDOSE_SERVER=legacy python -m unittest discover -s tests
```

เทสต์ของ WebSocket จะถูกข้าม เพราะเซิร์ฟเวอร์รุ่นเก่าไม่มี WebSocket
