# การเข้าสู่ระบบและเซสชัน

ส่วนหนึ่งของ [ความปลอดภัย](README.md)

## รหัสผ่าน

- เก็บเป็น PBKDF2-HMAC-SHA256 600,000 รอบ พร้อม salt สุ่ม 16 ไบต์ต่อบัญชี เทียบด้วย `hmac.compare_digest` (`backend/utils/security.py`)
- รูปแบบที่เก็บคือ `pbkdf2_sha256$600000$<salt>$<digest>` จำนวนรอบอยู่ในข้อความ จึงเพิ่มรอบในอนาคตได้โดยรหัสผ่านเดิมยังใช้ได้
- รหัสผ่านต้องยาว 10 ถึง 200 ตัวอักษร

## หน้าเข้าสู่ระบบเดียวสำหรับทุกคน

หน้า `/login` ใช้ `POST /api/sign-in` ครั้งเดียว ตรวจทั้งบัญชีทีมงานและบัญชีลูกค้าของอีเมลนั้น

- ตรวจ hash ทั้งสองแบบเสมอ บัญชีที่ไม่มีอยู่ใช้ hash หลอก เวลาตอบจึงไม่บอกว่ามีบัญชีหรือไม่
- รหัสไม่ตรงกับบัญชีใดเลย นับผิด 1 ครั้ง
- ตรงทั้งสองแบบ เข้าเป็นทีมงาน
- `/api/login` (ทีมงาน) และ `/api/customer/login` (ลูกค้า) ยังใช้ได้

## ล็อกบัญชีแบบเพิ่มเวลา

`backend/modules/security/lockout.py`

- นับตาม **อีเมลที่พิมพ์** ไม่ว่ามีบัญชีจริงหรือไม่ คำตอบจึงไม่บอกว่าอีเมลไหนมีอยู่ในระบบ
- ผิด 5 ครั้งใน 15 นาที ถูกล็อก

| ระดับ | ล็อกนาน |
|---|---|
| 1 | 5 นาที |
| 2 | 15 นาที |
| 3 | 1 ชั่วโมง |
| 4 ขึ้นไป | 24 ชั่วโมง |

- ระดับลดลง 1 ขั้นทุก 24 ชั่วโมงที่ไม่ถูกล็อกซ้ำ เข้าสู่ระบบสำเร็จล้างจำนวนครั้งที่ผิด แต่ไม่ล้างระดับ
- ระหว่างล็อก ทุกครั้งที่ลองตอบ **429** พร้อม `retry_after` เท่ากันไม่ว่ารหัสจะถูกหรือผิด และไม่ต่อเวลาล็อก หน้าเว็บแสดงนับถอยหลัง
- คีย์ `signin:`, `staff:` และ `customer:` ของอีเมลเดียวกันผูกกัน ล็อกที่คีย์หนึ่งปิดทั้งสามทาง จึงเดาต่อด้วยการสลับ endpoint ไม่ได้
- สำหรับลูกค้า รหัสยืนยันสองขั้นตอน รหัสสำรอง และ Passkey ที่ถูกปฏิเสธ นับรวมด้วย
- ปลดล็อกได้ 3 ทาง คือ รอครบเวลา ตั้งรหัสผ่านใหม่จากลิงก์ในอีเมล หรือให้ผู้ดูแลแพลตฟอร์มปลด
- เมื่อถูกล็อก เจ้าของบัญชีได้อีเมลแจ้ง (IP ถูกปิดบางส่วน) ไม่เกินวันละครั้ง และเฉพาะอีเมลที่ยืนยันแล้ว
- ช่องซ่อนกันบอตที่ถูกกรอก ไม่นับเข้าการล็อก บอตจึงล็อกบัญชีของคนจริงไม่ได้

## การยืนยันสองขั้นตอนและ Passkey

ทีมงาน (`backend/modules/staff_security/`) และลูกค้า (`backend/modules/customer_security/`) ใช้กติกาเดียวกัน

| วิธี | กติกา |
|---|---|
| แอปยืนยันตัวตน (TOTP) | รหัส 6 หลัก เปลี่ยนทุก 30 วินาที ความลับเข้ารหัสก่อนเก็บ รหัสของช่วงเวลาหนึ่งใช้ได้ครั้งเดียว |
| รหัสสำรอง | 10 รหัส เก็บเป็นค่า hash ใช้ได้รหัสละครั้ง แสดงให้เห็นครั้งเดียวตอนสร้าง |
| Passkey (WebAuthn) | challenge สุ่มทุกครั้ง เก็บเป็นค่า hash อายุ 5 นาที ลบทันทีที่ใช้ ตัวนับลายเซ็นที่ไม่เดินหน้าถือว่าเป็นของที่ถูกคัดลอกและถูกปฏิเสธ Passkey ที่ยืนยันผู้ใช้แล้วนับเป็นทั้งสองขั้น |

- ตรวจ WebAuthn และ CBOR ด้วย standard library ของ Python รองรับลายเซ็นแบบ ES256 และ RS256 (Windows Hello)
- การเพิ่มหรือถอดวิธีเข้าสู่ระบบทุกแบบต้องใส่รหัสผ่านก่อน หน้าจอที่ถูกยืมไปจึงล็อกเจ้าของไม่ได้ และทิ้งกุญแจไว้ให้ตัวเองไม่ได้
- รหัสผ่านถูกต้องบนบัญชีที่เปิดสองขั้นตอน ได้เพียงคุกกี้ HttpOnly อายุสั้นสำหรับขั้นที่สอง ลองได้ 5 ครั้ง ยังไม่ได้เซสชัน
- ลิงก์ตั้งรหัสผ่านใหม่ข้ามขั้นที่สองไม่ได้
- ตั้งรหัสผ่านใหม่จากลิงก์ ลบ Passkey เดิมทั้งหมด
- ปุ่ม Passkey เดียวในหน้าเข้าสู่ระบบรู้เองว่าเป็นบัญชีทีมงานหรือลูกค้า
- ทีมงานที่ทำโทรศัพท์และรหัสสำรองหาย ให้ผู้ดูแลเซิร์ฟเวอร์รีเซ็ต ดู [ดูแลระบบ](../operations.md#รีเซ็ตการยืนยันสองขั้นตอนของทีมงาน)
- เจ้าขององค์กรบังคับให้ทีมงานทุกคนเปิดได้ ดู [ตั้งค่าองค์กร](../features/organization-settings.md)

## ลืมรหัสผ่าน

ทั้งทีมงานและลูกค้าขอลิงก์ทางอีเมลได้เอง เมื่อแพลตฟอร์มตั้งอีเมลแล้ว

- ตอบเหมือนกันทั้งอีเมลที่มีและไม่มีบัญชี
- ลิงก์อายุ 1 ชั่วโมง ใช้ได้ครั้งเดียว เก็บเป็นค่า hash
- ตั้งรหัสผ่านใหม่แล้วออกจากระบบทุกเครื่อง ลบ Passkey และปลดล็อกบัญชี
- ลิงก์ของทีมงานไม่พาเข้าสู่ระบบเอง ต้องเข้าด้วยรหัสผ่านใหม่ และขั้นที่สองถ้าเปิดไว้

## คำเชิญเพื่อนร่วมงาน

เจ้าขององค์กรเชิญเพื่อนร่วมงานทางอีเมล เพื่อนร่วมงานตั้งรหัสผ่านเอง ผู้ดูแลจึงไม่เคยรู้รหัสผ่านของใคร

- ลิงก์อายุ 7 วัน ใช้ได้ครั้งเดียว เก็บเป็นค่า hash
- คนที่มีบัญชีอยู่แล้วเข้าร่วมโดยไม่เปลี่ยนรหัสผ่าน และไม่ได้เซสชันจากลิงก์ ต้องเข้าสู่ระบบตามปกติ
- ถ้าแพลตฟอร์มยังไม่ได้ตั้งอีเมล ผู้ดูแลยังตั้งรหัสผ่านแรกให้ได้แบบเดิม

## เซสชัน

- token ของเซสชันเก็บในฐานข้อมูลเป็นค่า SHA-256 ไม่ใช่ค่าจริง
- เซสชันมีอายุ 2 แบบ คือ ไม่ได้ใช้งานนานเกิน (idle) และอายุสูงสุด (absolute) ผู้ดูแลแพลตฟอร์มปรับได้ที่ **คอนโซลระบบกลาง → ความปลอดภัย → ตั้งค่า**

| ผู้ใช้ | ไม่ใช้งานนานเกิน | อายุสูงสุด |
|---|---|---|
| ทีมงาน | 60 นาที | 12 ชั่วโมง |
| ผู้ดูแลแพลตฟอร์ม | 30 นาที | 8 ชั่วโมง |
| ลูกค้า | 7 วัน | 30 วัน |

- **การดึงข้อมูลเบื้องหลังและ WebSocket ไม่ต่ออายุเซสชัน** เวลาใช้งานขยับเฉพาะคำขอที่เปลี่ยนข้อมูล หรือเมื่อหน้าเว็บส่ง `POST /api/session/activity` (ทีมงาน) หรือ `POST /api/customer/activity` (ลูกค้า) ไม่เกินนาทีละครั้งขณะผู้ใช้กดหรือพิมพ์จริง เปิดหน้าจอทิ้งไว้จึงไม่ทำให้เซสชันอยู่ตลอดไป
- 2 นาทีก่อนหมดเวลา หน้าเว็บถามว่ายังใช้งานอยู่ไหม พร้อมนับถอยหลัง
- เซสชันที่หมดตอบ 401 `{error, reason: "idle" | "absolute"}` และถูกลบ WebSocket ของเซสชันนั้นปิดด้วย 4401 ในรอบตรวจถัดไป
- เปลี่ยนรหัสผ่านจากเมนูบัญชีแล้วออกจากเซสชันอื่นทั้งหมด
- ผู้ใช้เห็นรายการอุปกรณ์ที่เข้าสู่ระบบ สั่งออกทีละเครื่องหรือทุกเครื่องได้ ผู้ดูแลแพลตฟอร์มยุติเซสชันทั้งหมดของบัญชีใดก็ได้

### หลายบัญชีในเบราว์เซอร์เดียว

ทีมงานเพิ่มบัญชีอื่นในเบราว์เซอร์เดียวกันได้จากเมนูรูปโปรไฟล์ แล้วสลับบัญชีได้ในคลิกเดียว การเพิ่มบัญชีต้องใส่รหัสผ่านและรหัสขั้นที่สองของบัญชีนั้น การสลับโหลดหน้าใหม่ทั้งหน้า ข้อมูลของบัญชีหนึ่งจึงไม่ค้างบนจอของอีกบัญชี

## คุกกี้

| คุกกี้ | ของใคร | แบบ |
|---|---|---|
| เซสชันทีมงาน | ทีมงาน | `HttpOnly; SameSite=Strict` |
| เซสชันลูกค้า | ลูกค้า | `HttpOnly; SameSite=Strict` |
| `g_<org>` | ผู้เยี่ยมชม | `HttpOnly; SameSite=Lax; Path=/api/` และเป็น `SameSite=None; Secure; Partitioned` เฉพาะในหน้าแชทที่ฝังบนเว็บไซต์ขององค์กร |

ทุกตัวได้ `Secure` เมื่อเปิด API ด้วย `--secure-cookies`

## CSRF

คำขอที่ไม่ใช่ GET ต้องแนบ token ของเซสชัน เทียบด้วย `hmac.compare_digest` (`backend/middleware/auth.py`) คำขอที่ไม่ผ่านบันทึกเป็นเหตุการณ์ `csrf_rejected`

| ผู้ใช้ | header |
|---|---|
| ทีมงาน | `X-CSRF-Token` |
| ลูกค้า | `X-Customer-CSRF` |
| ผู้เยี่ยมชม | `X-Guest-CSRF` |

หน้าเว็บอ่าน token จาก `/api/bootstrap`, `/api/customer/account` และ `/api/public/<org>/guest` แล้วใส่ให้ทุกคำขอเอง (`frontend/src/lib/api/client.ts`)
