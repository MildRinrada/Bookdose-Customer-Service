# บทบาทและสิทธิ์

ระบบมีผู้ใช้ 6 แบบ แบ่งเป็น 3 กลุ่ม คือ ผู้ดูแลแพลตฟอร์ม ทีมงานขององค์กร และลูกค้า สิทธิ์ทุกอย่างตรวจที่ API หน้าเว็บซ่อนเมนูตามบทบาทเพื่อความสะดวกเท่านั้น

## ภาพรวม

| บทบาท | คือใคร | ใช้หน้าไหน |
|---|---|---|
| เจ้าของแพลตฟอร์ม | บัญชีที่สร้างตอนตั้งค่าครั้งแรก | คอนโซลระบบกลาง |
| ผู้ดูแลแพลตฟอร์ม | ทีมที่ดูแลเซิร์ฟเวอร์ | คอนโซลระบบกลาง |
| เจ้าขององค์กร (`admin`) | ผู้บริหารงานบริการขององค์กร | พื้นที่ทำงานขององค์กร ทุกเมนู |
| เจ้าหน้าที่ (`agent`) | ผู้ตอบลูกค้า | พื้นที่ทำงานขององค์กร เฉพาะงานของทีมตัวเอง |
| ลูกค้าที่มีบัญชี | ลูกค้าขององค์กร | หน้าลูกค้า (`/customer`) |
| ผู้เยี่ยมชม | ลูกค้าที่แชทโดยไม่มีบัญชี | หน้าช่วยเหลือขององค์กร (`/support/<code>`) |

## ผู้ดูแลแพลตฟอร์ม

### เจ้าของแพลตฟอร์ม

- ทำได้ทุกอย่างที่ผู้ดูแลแพลตฟอร์มทำได้
- เป็นคนเดียวที่เพิ่มหรือถอดผู้ดูแลแพลตฟอร์มได้
- ถอดเจ้าของไม่ได้ ระบบจึงมีผู้ดูแลอย่างน้อยหนึ่งคนเสมอ

### ผู้ดูแลแพลตฟอร์ม

- ใช้คอนโซลระบบกลาง: สร้างและระงับองค์กร เชิญเจ้าขององค์กร ดูสุขภาพระบบ เขียน FAQ กลาง ดูแลความปลอดภัย สำรองและกู้คืน ใช้เครื่องมือ PDPA
- **ไม่รับเคสและไม่ตอบลูกค้า** ไม่เป็นสมาชิกขององค์กรใด ไม่อยู่ในรายชื่อผู้รับผิดชอบ กฎรับเรื่อง การยกระดับ หรือการ @แท็ก
- **เข้าดูข้อมูลขององค์กรไม่ได้เอง** ต้องขอสิทธิ์เข้าช่วยเหลือ (หัวข้อถัดไป)
- บัญชีที่ยังไม่เปิดการยืนยันสองขั้นตอนหรือ Passkey จะถูกเตือนในคอนโซล

## สิทธิ์เข้าช่วยเหลือ

ผู้ดูแลแพลตฟอร์มเข้าดูองค์กรได้ทางเดียวคือขอสิทธิ์ และให้เจ้าขององค์กรอนุมัติ

1. ผู้ดูแลแพลตฟอร์มยื่นคำขอพร้อมเหตุผลและระยะเวลา 1, 4, 8, 24 หรือ 72 ชั่วโมง
2. เจ้าขององค์กรได้อีเมลและเห็นแถบแจ้งบนทุกหน้า คำขอที่ไม่มีใครตัดสินภายใน 24 ชั่วโมงหมดอายุเอง
3. เจ้าขององค์กรอนุมัติได้ไม่เกินเวลาที่ขอ หรือปฏิเสธ
4. ระหว่างมีสิทธิ์ ผู้ดูแลแพลตฟอร์ม **อ่านได้อย่างเดียว** API ปฏิเสธทุกคำขอที่ไม่ใช่ GET
5. สิทธิ์หมดตรงเวลา เจ้าขององค์กรหยุดได้ทุกเมื่อ และผู้ดูแลแพลตฟอร์มออกก่อนเวลาได้

ทุกขั้นบันทึกทั้งในประวัติของแพลตฟอร์มและประวัติขององค์กร

## ทีมงานขององค์กร

องค์กรหนึ่งมี 2 บทบาท

### เจ้าขององค์กร (`admin`)

- ดูงานทุกทีม จัดการสมาชิก ทีม การตั้งค่า ช่องทาง ระบบอัตโนมัติ ประวัติการทำงาน ถังขยะ และสำรองข้อมูลขององค์กร
- เขียนและแก้บทความในคลังความรู้ ลบเคส
- จัดการรายการป้ายเคส และดูว่าแต่ละวันข้างหน้าคนพอหรือไม่ (หน้ารายงาน)
- องค์กรมีเจ้าของได้หลายคน แต่ต้องเหลืออย่างน้อย 1 คนเสมอ ลดบทบาทหรือปิดบัญชีเจ้าของคนสุดท้ายไม่ได้

### เจ้าหน้าที่ (`agent`)

- เห็นเคส บทสนทนา ไฟล์ และรายงานเฉพาะทีมของตัวเอง ข้อมูลของทีมอื่นตอบ 404 เหมือนไม่มีอยู่
- เห็นลูกค้าที่ตัวเองสร้าง หรือที่มีงานอยู่ในทีม
- อ่านคลังความรู้ขององค์กร ปักหมุดและให้คะแนนบทความได้ แต่เขียนหรือแก้ไม่ได้
- ติดป้ายให้เคสที่เห็นได้ แต่เพิ่มหรือแก้รายการป้ายไม่ได้

บทบาทหัวหน้าทีม (`manager`) เลิกใช้แล้ว ตอนเปิดระบบ บัญชีที่เคยเป็นหัวหน้าทีมจะกลายเป็นเจ้าหน้าที่ ถ้าต้องการให้ใครจัดการได้ ให้ตั้งเป็นเจ้าขององค์กรอีกคน

### เมนูที่แต่ละบทบาทเห็น

| เมนู | เจ้าขององค์กร | เจ้าหน้าที่ |
|---|---|---|
| ภาพรวม กล่องข้อความ เคสบริการ ข้อมูลลูกค้า คลังความรู้ รายงาน คู่มือจาก Bookdose | เห็น | เห็น |
| การแจ้งเตือน ตั้งค่าบัญชี | เห็น | เห็น |
| ทีมและสมาชิก ระบบอัตโนมัติ ประวัติการทำงาน ถังขยะ ตั้งค่าองค์กร | เห็น | ไม่เห็น |

### บังคับยืนยันตัวตนสองขั้นตอน

เจ้าขององค์กรบังคับให้สมาชิกทุกคนใช้การยืนยันสองขั้นตอนหรือ Passkey ได้ สมาชิกที่ยังไม่มีจะเข้าได้เฉพาะหน้าตั้งค่าบัญชีของตัวเองจนกว่าจะเปิด ดู [ตั้งค่าองค์กร](features/organization-settings.md)

### บัญชีเดียวหลายองค์กร

บัญชีทีมงานหนึ่งเป็นสมาชิกได้หลายองค์กร สลับได้จากกล่องเลือกองค์กรมุมซ้ายบน แต่ละแท็บส่ง `X-Tenant-ID` ขององค์กรที่เลือก ถ้าไม่ตรงกับเซสชัน API ตอบ 409 เพื่อกันการเขียนผิดองค์กรเมื่อสลับองค์กรในอีกแท็บ

บัญชีเดียวเป็นทั้งผู้ดูแลแพลตฟอร์มและทีมงานขององค์กรไม่ได้ ระบบไม่ให้เชิญผู้ดูแลแพลตฟอร์มเข้าองค์กร และไม่ให้ตั้งทีมงานขององค์กรเป็นผู้ดูแลแพลตฟอร์ม

## ลูกค้า

### ลูกค้าที่มีบัญชี

- บัญชีเดียวใช้ได้กับทุกองค์กรบนระบบ องค์กรของแพลตฟอร์มเองอยู่ในรายการเสมอ
- อ่านและตอบเฉพาะแชทของบัญชีตัวเอง ดูสถานะและกำหนดเวลาของเคสตัวเอง อ่านบทความสาธารณะ
- **ไม่เห็น** บันทึกภายใน ความเร่งด่วน ทีม หรือผู้รับผิดชอบ

### ผู้เยี่ยมชม

- เป็นของทีละองค์กร รู้จักจากคุกกี้ในเบราว์เซอร์
- เห็นเฉพาะบทสนทนาที่ตัวเองเริ่ม บทสนทนาอื่นตอบ 404
- ย้ายประวัติเข้าบัญชีลูกค้าได้ภายหลัง

รายละเอียดอยู่ใน [หน้าลูกค้า](features/customer-portal.md) และ [หน้าช่วยเหลือและแชทผู้เยี่ยมชม](features/support-page-and-guest-chat.md)

## ลำดับการตรวจสิทธิ์

ทุกคำขอผ่านการตรวจตามระดับของ route ก่อนถึงโค้ดของฟีเจอร์ ดูตารางระดับใน [สถาปัตยกรรม](architecture.md#ระดับสิทธิ์ของ-route) รายละเอียดด้านความปลอดภัยอยู่ใน [การแยกข้อมูลและความลับ](security/data-isolation-and-secrets.md)
