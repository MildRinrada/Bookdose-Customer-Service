# ความปลอดภัย

เอกสารชุดนี้บอกว่าระบบป้องกันอะไรไว้แล้ว ป้องกันด้วยวิธีไหน และยังมีข้อจำกัดอะไร เขียนสำหรับคนที่รับช่วงดูแลระบบ ตรวจรับงาน หรือประเมินความเสี่ยงก่อนนำขึ้นใช้งานจริง ทุกหัวข้ออ้างไฟล์จริงในโค้ด

## เอกสารในชุดนี้

| เอกสาร | เนื้อหา |
|---|---|
| [การเข้าสู่ระบบและเซสชัน](authentication.md) | รหัสผ่าน ล็อกบัญชี การยืนยันสองขั้นตอน Passkey เซสชัน คุกกี้ และ CSRF |
| [การแยกข้อมูลและความลับ](data-isolation-and-secrets.md) | ฐานข้อมูลแยกต่อองค์กร สิทธิ์ภายในองค์กร การเข้าช่วยเหลือ การเข้ารหัสความลับ และไฟล์สำรอง |
| [การป้องกันระดับคำขอ](request-protection.md) | security header CSP Host/Origin การจำกัดคำขอ Webhook ไฟล์อัปโหลด และ Turnstile |
| [การเฝ้าระวังและกับดัก](monitoring-and-traps.md) | เหตุการณ์ความปลอดภัย การแจ้งเตือน บล็อก IP Honeypot Honeytoken และการตรวจช่องโหว่ |

## ขอบเขตความเชื่อใจ

ระบบมี 2 process แยกกัน

| ส่วน | หน้าที่ |
|---|---|
| หน้าเว็บ (Next.js) | แสดงหน้าจอ และส่งต่อคำขอ `/api/*` |
| API (Python) | ตรรกะ สิทธิ์ และข้อมูลทั้งหมด |

- เบราว์เซอร์ไม่เคยคุยกับ API โดยตรง และ API ไม่ให้บริการไฟล์หน้าเว็บ
- สิทธิ์ทุกอย่างตรวจที่ API หน้าเว็บซ่อนปุ่มได้ แต่ไม่ใช่ด่านป้องกัน
- หน้าเว็บบอก API ว่าเบราว์เซอร์ใช้โฮสต์อะไร (`X-Forwarded-Host`) และมาจาก IP ไหน (`X-Bookdose-Client-IP`) API เชื่อสองค่านี้เฉพาะเมื่อคำขอถือความลับร่วม `BOOKDOSE_PROXY_SECRET` หรือมาจากเครื่องเดียวกันขณะที่ยังไม่ได้ตั้งความลับ (`backend/middleware/security.py`)

บนเซิร์ฟเวอร์จริงต้องตั้ง `BOOKDOSE_PROXY_SECRET` ทั้งสองฝั่งเสมอ ไม่อย่างนั้น IP ที่ใช้นับการจำกัดคำขอและบันทึกเหตุการณ์จะเป็นของ proxy ไม่ใช่ของผู้ใช้

## สิ่งที่ระบบตั้งใจไม่เก็บ

- ไม่เก็บรหัสผ่าน รหัสยืนยัน token หรือเนื้อความแชทในบันทึกเหตุการณ์ความปลอดภัยและประวัติบัญชี เก็บเพียงว่าเกิดอะไร จากที่ไหน เบราว์เซอร์อะไร
- บันทึกการเข้าถึงไม่เก็บ path และ query string เพราะอาจมีคำค้นที่ผู้ใช้พิมพ์
- อีเมลและ LINE ที่แจ้งลูกค้าว่าทีมตอบแล้ว มีเพียงหัวเรื่องและลิงก์ ไม่มีเนื้อความ
- รายงานปัญหาถึงผู้ดูแลแพลตฟอร์มไม่แนบบทสนทนากับลูกค้า
- ข้อมูลที่ส่งให้ AI ไม่มีชื่อ อีเมล หรือเบอร์โทรของลูกค้า อีเมลและเบอร์โทรที่พิมพ์อยู่ในข้อความถูกปิดบังก่อนส่งในงานที่ระบุไว้ ดู [AI](../features/ai.md)
- รูปโปรไฟล์ของเพื่อนร่วมงานเห็นได้เฉพาะสมาชิกองค์กรเดียวกัน ยกเว้นทีมงานที่เลือกเองให้ลูกค้าเห็นรูปบนการ์ดขอบคุณ และองค์กรเปิดการ์ดนั้น รูปบนการ์ดเปิดได้เฉพาะลูกค้าเจ้าของบทสนทนา

## ข้อจำกัดที่รู้อยู่

1. **บน Windows ไฟล์ความลับไม่ได้สิทธิ์ `0600` จริง** Windows ไม่ใช้สิทธิ์แบบ POSIX เนื้อหายังเข้ารหัสอยู่ แต่ถ้าใช้งานจริงบน Windows ต้องจำกัดสิทธิ์โฟลเดอร์ข้อมูลด้วย ACL เอง
2. **กุญแจเริ่มต้นอยู่ในโฟลเดอร์ข้อมูล** ถ้าไม่ตั้ง `BOOKDOSE_SECRET_KEY`
3. **การจำกัดคำขอเก็บในหน่วยความจำ** เริ่มนับใหม่ทุกครั้งที่เปิด API ใหม่ ส่วนการล็อกบัญชีเก็บในฐานข้อมูลจึงข้ามการเปิดใหม่ได้
4. **ไม่มี CI** ในโปรเจกต์ มีเพียงการตรวจช่องโหว่ของไลบรารีวันละครั้งจากคอนโซล
5. **เหตุการณ์ความปลอดภัยเก็บ 90 วัน** ถ้าต้องสืบย้อนนานกว่านั้น ต้องส่งออกไปเก็บที่อื่นก่อน
6. **ยังไม่เคยผ่านการทดสอบเจาะระบบจากภายนอก** เนื้อหาในเอกสารนี้มาจากการอ่านโค้ดและชุดทดสอบ ไม่ใช่ผลรับรองจากบุคคลที่สาม
