# การอัปเดตสด

ข้อความใหม่ สถานะเคส กำลังพิมพ์ และอ่านแล้ว ขึ้นบนหน้าจอภายในไม่ถึงวินาทีผ่าน WebSocket ถ้าเชื่อมต่อไม่ได้ หน้าจอดึงข้อมูลตามรอบแทนและทำงานได้เหมือนเดิม

## หลักการ

**socket ส่งสัญญาณ REST ส่งข้อมูล**

เหตุการณ์บอกเพียงว่าอะไรเปลี่ยน หน้าเว็บจึงไปดึงข้อมูลใหม่ผ่าน API เดิม กติกาสิทธิ์ทั้งหมดจึงอยู่ที่ REST ที่เดียว

เหตุการณ์ไม่มีเนื้อความแชท ชื่อไฟล์แนบ บันทึกภายใน อีเมล หรือเบอร์โทร ยกเว้น 2 อย่างที่แสดงจากเหตุการณ์โดยตรง คือ กำลังพิมพ์ (ใช้ชื่อที่อีกฝั่งเห็นอยู่แล้ว) และอ่านแล้ว (เวลา)

## จุดเชื่อมต่อ

ทุกจุดอยู่ใต้ origin เดียวกับหน้าเว็บ ผ่าน Next.js ที่พอร์ต 3000

| path | ใคร | คุกกี้ |
|---|---|---|
| `/api/realtime/staff` | ทีมงานในองค์กรที่เซสชันเลือกอยู่ | เซสชันทีมงาน |
| `/api/realtime/customer` | ลูกค้าที่เข้าสู่ระบบ ทุกองค์กรที่เชื่อมไว้ | เซสชันลูกค้า |
| `/api/public/<org>/guest/realtime` | ผู้เยี่ยมชมขององค์กรนั้น | `g_<org>` |

## การตรวจตอนเชื่อมต่อ

รับการเชื่อมต่อก่อน แล้วตรวจตามลำดับ ถ้าไม่ผ่านจะปิดพร้อมรหัส

| ตรวจ | ไม่ผ่านปิดด้วย |
|---|---|
| IP ถูกบล็อก | 4403 |
| Host เหมือนคำขอ HTTP และ Origin ต้องเป็นเว็บไซต์ของเราเอง (กันการขโมย WebSocket ข้ามเว็บไซต์) | 4403 |
| ไม่มีคุกกี้ หรือเซสชันไม่ถูกต้อง | 4401 |
| องค์กรไม่ได้เปิดแชทผู้เยี่ยมชม | 4403 |

ผ่านแล้วเซิร์ฟเวอร์ส่ง `{"type":"hello","poll_ms":60000}`

## ระหว่างเชื่อมต่อ

- ตรวจเซสชันซ้ำทุกนาที ออกจากระบบ อุปกรณ์ถูกสั่งออก สมาชิกถูกปิด สลับองค์กร หรือองค์กรถูกระงับ ปิดด้วย 4401
- เซิร์ฟเวอร์ส่ง `{"type":"ping"}` ทุก 25 วินาที ไม่มีเฟรมจากเบราว์เซอร์ 70 วินาที ปิดด้วย 4408
- เปิดได้ไม่เกิน 5 socket ต่อเซสชัน หรือต่อเบราว์เซอร์ของผู้เยี่ยมชม
- เฟรมไม่เกิน 2 KB และไม่เกิน 20 เฟรมต่อ 10 วินาที เกินปิดด้วย 4429
- socket ที่รับเหตุการณ์ไม่ทัน ปิดด้วย 1013 หน้าเว็บต่อใหม่แล้วดึงข้อมูลใหม่

การใช้ socket ไม่นับเป็นการใช้งานที่ต่ออายุเซสชัน ดู [การเข้าสู่ระบบและเซสชัน](security/authentication.md)

## ข้อความจากเซิร์ฟเวอร์

```text
{"type":"changed","scope":"conversation","id":"<id>","org":"<slug>"}   ข้อความใหม่ สถานะ แบบประเมิน สถานะ AI
{"type":"changed","scope":"conversations","org":"<slug>"}              รายการบทสนทนาเปลี่ยน
{"type":"changed","scope":"ticket","id":"<id>","org":"<slug>"}         เคสหนึ่งเปลี่ยน
{"type":"changed","scope":"tickets","org":"<slug>"}                    รายการเคสเปลี่ยน
{"type":"changed","scope":"alerts"}                                    การแจ้งเตือนของลูกค้าเปลี่ยน
{"type":"typing","conversation_id":"<id>","who":"staff|customer","name":"<ชื่อ>","ttl_ms":6000}
{"type":"here","conversation_id":"<id>","user_id":"<id>","name":"<ชื่อ>","typing":false,"ttl_ms":25000}
{"type":"read","conversation_id":"<id>","by":"staff|customer","at":"<เวลา>"}
{"type":"ping"}
```

## ข้อความจากเบราว์เซอร์

| ข้อความ | ใครส่ง | เงื่อนไข |
|---|---|---|
| `{"type":"pong"}` | ทุกคน | ตอบ ping |
| `{"type":"typing","conversation_id":"<id>"}` | ทุกคน | ส่งไม่เกิน 1 ครั้งต่อ 3 วินาทีขณะช่องพิมพ์มีข้อความ ไม่ส่งจากโหมดบันทึกภายใน |
| `{"type":"viewing","conversation_id":"<id>"}` | ทีมงาน | ทุก 15 วินาทีขณะเปิดบทสนทนาอยู่และแท็บอยู่ด้านหน้า |

เซิร์ฟเวอร์ส่งต่อเฉพาะเมื่อผู้ส่งตอบในบทสนทนานั้นได้ และไม่เกิน 1 ครั้งต่อ 2.5 วินาทีต่อบทสนทนาต่อ socket

## ใครได้รับอะไร

| ผู้รับ | ได้รับ |
|---|---|
| ทีมงาน | เหตุการณ์ของบทสนทนาและเคสที่ตนมีสิทธิ์เห็น เจ้าหน้าที่เห็นเฉพาะทีมตัวเอง เจ้าขององค์กรเห็นทุกทีม |
| ลูกค้าที่เข้าสู่ระบบ | เฉพาะบทสนทนาและเคสที่บัญชีตนเป็นเจ้าของ |
| ผู้เยี่ยมชม | เฉพาะบทสนทนาที่ตนเริ่มเอง จนกว่าประวัติจะย้ายเข้าบัญชี |

บันทึกภายใน สถานะการส่ง และข้อมูลเฉพาะทีมงานของเคส (ความเร่งด่วน ทีม ผู้รับผิดชอบ การยกระดับ) ส่งถึงทีมงานเท่านั้น

`here` บอกทีมว่ามีใครเปิดบทสนทนานี้อยู่ เพื่อไม่ให้สองคนตอบลูกค้าคนเดียวกันพร้อมกัน ไม่ได้ล็อกอะไร และส่งถึงทีมงานเท่านั้น

## จุดที่ส่งเหตุการณ์

ทุกจุดส่งหลัง commit เท่านั้น การเปลี่ยนที่ rollback ไม่ส่งอะไร

| จุด | ทีมงาน | ลูกค้าหรือผู้เยี่ยมชมเจ้าของ |
|---|---|---|
| บันทึกข้อความทุกช่องทาง | ได้ | ได้ ยกเว้นบันทึกภายใน |
| คำตอบของ AI ข้อความระบบ ส่งต่อเจ้าหน้าที่ | ได้ | เฉพาะของ Chatbot |
| เปิด อัปเดต ลบ หรือกู้คืนเคส | ได้ | เฉพาะเมื่อสถานะเปลี่ยน เปิด ลบ หรือกู้คืน |
| ยกระดับ SLA | ได้ | ไม่ได้ |
| สถานะการส่งออก LINE อีเมล Facebook | ได้ | ไม่ได้ |
| เปิดอ่านบทสนทนา | อ่านแล้ว เมื่อลูกค้าอ่านคำตอบของทีม | อ่านแล้ว เมื่อทีมเปิดอ่านหลังข้อความล่าสุดของลูกค้า |

การรวมรายชื่อลูกค้าซ้ำ การย้ายแชทผู้เยี่ยมชมเข้าบัญชี และการตั้งค่าองค์กร ยังไม่ส่งเหตุการณ์ หน้าจอเห็นผ่านการดึงข้อมูลตามรอบ

## ฝั่งหน้าเว็บ

- `src/lib/realtime.ts` เชื่อมต่อ 1 socket ต่อหน้า ต่อใหม่แบบรอนานขึ้นเรื่อย ๆ ตั้งแต่ 1 ถึง 30 วินาที หยุดเมื่อแท็บถูกซ่อนเกิน 5 นาที และกลับมาเมื่อผู้ใช้กลับมาที่แท็บ
- `src/lib/realtime-provider.tsx` แปลงเหตุการณ์เป็นการโหลด query ใหม่ เหตุการณ์ที่มาติดกันภายใน 150 มิลลิวินาทีรวมเป็นการโหลดรอบเดียว
- ขณะเชื่อมต่ออยู่ การดึงข้อมูลตามรอบช้าลงเหลือทุก 60 วินาที ไว้เป็นตาข่ายกันพลาด
- รหัสปิด 4401 ไม่ลองต่อใหม่จนกว่าเซสชันจะเปลี่ยน รหัส 4403 และ 4429 ลองใหม่ทุกราว 30 วินาที
- หน้าจอที่อัปเดตเองใช้ `useRealtimeInterval(ms)` และเพิ่ม key ของหน้านั้นใน `eventTargets`

## ข้อจำกัด

ศูนย์กลางของ socket อยู่ในหน่วยความจำของ process เดียว ถ้ารันหลาย worker หรือหลายเครื่อง ต้องมีตัวกลางส่งข้อความ เช่น Redis pub/sub

## โค้ดที่เกี่ยวข้อง

| ไฟล์ | หน้าที่ |
|---|---|
| `backend/realtime/hub.py` | ศูนย์กลางใน process ส่งจาก thread ใดก็ได้เข้า event loop |
| `backend/realtime/events.py` | จุดที่ service เรียก หาผู้รับภายใน transaction แล้วฝากเหตุการณ์ไว้ส่งหลัง commit |
| `backend/realtime/socket.py` | 3 จุดเชื่อมต่อ การตรวจตอนเชื่อมต่อ ขีดจำกัด และเฟรมจากเบราว์เซอร์ |
| `frontend/src/lib/realtime.ts` | การเชื่อมต่อฝั่งเบราว์เซอร์ |
| `frontend/src/lib/realtime-provider.tsx` | แปลงเหตุการณ์เป็นการโหลดข้อมูลใหม่ กำลังพิมพ์ และอ่านแล้ว |
