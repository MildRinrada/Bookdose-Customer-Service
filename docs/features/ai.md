# AI

AI ขององค์กรช่วย 2 ฝั่ง คือ ช่วยทีมงาน (ร่างคำตอบ สรุป ผู้ช่วยที่ถามและสั่งงานได้) และตอบลูกค้าเอง (Chatbot) แต่ละองค์กรเชื่อม AI ของตัวเอง ใช้คีย์และโควตาของตัวเอง

## งานของ AI

| งาน | ใครใช้ | ทำอะไร |
|---|---|---|
| ร่างคำตอบ | ทีมงาน | ร่างคำตอบพร้อมอ้างอิงบทความ ทีมงานตรวจแล้วส่งเอง |
| Chatbot | ลูกค้า | ตอบลูกค้าเองในแชทบนเว็บ ปุ่มแชทบนเว็บไซต์ LINE และอีเมล |
| ผู้ช่วย AI | ทีมงาน | ถามเรื่องงาน สั่งงานเคส และหาต้นเหตุปัญหา จากปุ่มมุมขวาล่างของทุกหน้า |
| สรุปบทสนทนา | ทีมงาน | สรุปสิ่งที่ลูกค้าต้องการ สิ่งที่ลองแล้ว และสิ่งที่ยังค้าง |
| อ่านอารมณ์ลูกค้า | ทีมงาน | บอกว่าลูกค้าไม่พอใจหรือโกรธแค่ไหน |
| แปลภาษาอัตโนมัติ | ทีมงานและลูกค้า | แปลข้อความลูกค้าเป็นภาษาไทย และแปลคำตอบของทีมเป็นภาษาของลูกค้า |
| คำแนะนำ | เจ้าขององค์กร | สรุปประจำวัน และร่างบทความจากคำถามที่ยังไม่มีคำตอบ |

## เชื่อม AI

ตั้งที่ **ตั้งค่าองค์กร → AI Assistant** เฉพาะเจ้าขององค์กร

| ผู้ให้บริการ | วิธีเชื่อม |
|---|---|
| OpenAI | ใส่ API key ของ OpenAI ใช้ Responses API แบบ `store: false` และ Structured Outputs โมเดลเริ่มต้น `gpt-4.1-mini` |
| Google Gemini | ใส่ API key ของ Gemini (ขึ้นต้นด้วย `AQ.` หรือ `AIza`) ระบบรู้เองจากรูปแบบคีย์ |
| n8n | ใส่ Webhook URL และรหัสลับ แล้วให้ workflow ใน n8n เลือกโมเดลเอง เมื่อมี Webhook ระบบใช้ n8n แทนผู้ให้บริการอื่น ดู [integrations/n8n](../../integrations/n8n/README.md) |

- API key และรหัสลับเข้ารหัสเก็บเป็นไฟล์ฝั่งเซิร์ฟเวอร์ ไม่ส่งกลับหน้าเว็บ ไม่ใส่ใน prompt หรือ log
- ปุ่ม **ทดสอบการเชื่อมต่อ** ส่งข้อความทดสอบที่ไม่มีข้อมูลลูกค้าไปที่บริการจริง ใช้โควตาและอาจเสียค่าบริการ

### ค่าที่ตั้งได้

| ค่า | ค่าเริ่มต้น | ขอบเขต |
|---|---|---|
| AI ช่วยเจ้าหน้าที่ (ร่างคำตอบ และสรุปบทสนทนา) | ปิด | |
| Chatbot ตอบลูกค้าในแชทบนเว็บ | ปิด | |
| อ่านอารมณ์ลูกค้าด้วย AI | เปิด | |
| แปลภาษาอัตโนมัติ | ปิด | |
| งาน AI ต่อวัน (นับตามวัน UTC) | 100 | 1 ถึง 10,000 |
| คำตอบของ Chatbot ต่อบทสนทนา | 20 | 1 ถึง 100 |
| ความยาวคำตอบสูงสุด | 1,000 tokens | 200 ถึง 2,000 |

Chatbot บน LINE และอีเมลเปิดแยกในหน้าตั้งค่าของแต่ละช่องทาง ไม่ต้องเปิด Chatbot บนเว็บด้วย

## ร่างคำตอบ

1. ทีมงานกด **AI ช่วยร่าง** ในช่องพิมพ์ แล้วพิมพ์ต่อได้ระหว่างรอ
2. AI อ่านบทสนทนาและคลังความรู้
3. ร่างขึ้นเหนือช่องพิมพ์พร้อมแหล่งอ้างอิง
4. ทีมงานตรวจ แล้วกด **นำร่างใส่ช่องข้อความ** จากนั้นแก้และกดส่งเอง

- ร่างไม่ถูกส่งให้ลูกค้าเองเด็ดขาด
- การขอร่างทำให้ทีมงานรับช่วงบทสนทนานั้น
- ถ้าข้อความ ความรู้ สิทธิ์ หรือการตั้งค่าเปลี่ยนระหว่างร่าง ระบบยกเลิกผลเก่าให้ร่างใหม่
- ร่างอาจใช้บันทึกภายในและบทความภายใน จึงต้องตรวจทานก่อนส่ง
- ขอร่างได้ไม่เกิน 10 ครั้งต่อ 60 วินาทีต่อคน

## Chatbot

**ทำงานที่:** แชทบนเว็บ ปุ่มแชทบนเว็บไซต์ขององค์กร LINE และอีเมล **ไม่ทำงาน** บน Facebook และ Instagram

- เริ่มทำงานกับบทสนทนาใหม่หลังเปิดใช้ ไม่ตอบบทสนทนาเก่าเอง
- ใช้เฉพาะบทความที่เผยแพร่ให้ลูกค้าขององค์กรนั้น ไม่อ่านบันทึกภายใน ข้อมูลลูกค้า หรือข้อมูลขององค์กรอื่น
- ตอบพร้อมแหล่งอ้างอิง บน LINE และอีเมลขึ้นต้นด้วย `[Bookdose AI]`
- ทุกคำตอบต้องอ้างข้อความจากบทความที่ส่งไปจริง ระบบตรวจซ้ำ ถ้าอ้างอิงไม่ตรงจะส่งต่อเจ้าหน้าที่แทน

### ส่งต่อเจ้าหน้าที่เมื่อ

- ลูกค้ากด **คุยกับเจ้าหน้าที่** (ทำได้ตลอดเวลา)
- ลูกค้าส่งไฟล์แนบ ขอคนจริง ขอคืนเงินหรือยกเลิก
- ความรู้ไม่พอ หรือตรวจอ้างอิงไม่ได้
- บริการ AI ล้มเหลว หรือเกินเพดาน
- คำตอบยาวเกินข้อจำกัดของ LINE (ส่งต่อแทนการตัดคำตอบ)

เมื่อส่งต่อ ระบบหยุด AI และเปิดหรือเชื่อมเคสให้ทีม ลูกค้าที่ปิดหน้าเว็บไปแล้วได้รับแจ้งทางช่องทางที่เลือกไว้

### ทีมงานรับช่วง

- ทีมงานกด **รับช่วงดูแล** หรือส่งคำตอบเอง Chatbot ของบทสนทนานั้นหยุดทันที คำตอบ AI ที่กำลังประมวลผลจะไม่ถูกส่งแทรกภายหลัง
- ต้องการให้ AI ดูแลต่อ กด **ให้ AI ดูแลข้อความถัดไป** AI เริ่มกับข้อความใหม่ของลูกค้า ไม่ตอบข้อความเก่าซ้ำ

### กลุ่ม LINE

ต้องเปิด **ให้ AI ตอบในกลุ่มเมื่อเรียก /bookdose หรือเมนชัน** เพิ่ม ลูกค้าต้องพิมพ์ เช่น `/bookdose ดาวน์โหลดรายงานอย่างไร` หรือเมนชันบัญชี OA บอตใช้เฉพาะข้อความที่เรียกครั้งนั้น ไม่ส่งบทสนทนาทั่วไปของสมาชิกในกลุ่มไปให้ AI

### อีเมล

อีเมลที่ AI ส่งมี header `Auto-Submitted` และตัวรับอีเมลข้ามข้อความอัตโนมัติ จึงไม่ตอบวนกับระบบอื่น

## ผู้ช่วย AI

ปุ่มลอยมุมขวาล่างของทุกหน้าทีมงาน พิมพ์ถามหรือสั่งงานได้เลย

| ทำอะไรได้ | ตัวอย่าง |
|---|---|
| ตอบคำถามจากคลังความรู้ | คลังความรู้เขียนเรื่องนี้ไว้ว่าอย่างไร |
| ค้นหาและสรุปเคส | เคสไหนค้างนานที่สุด ลูกค้าของเคสนี้เคยแจ้งอะไรบ้าง |
| สั่งงานเคส | ปิดเคสนี้ มอบหมายเคสที่ยังไม่มีคนรับให้คนในทีม ตอบลูกค้าว่ากำลังตรวจสอบ |
| หาต้นเหตุปัญหาและเสนอวิธีแก้ | ทำไมเคสใหม่ไม่ถูกแจกอัตโนมัติ ทำไมข้อความ LINE ไม่ส่ง |

- ตอบจากคลังความรู้ขององค์กร รวมบทความภายใน พร้อมอ้างอิง
- เปิดหน้าเคสหรือแชทไว้แล้วพิมพ์ว่า "เคสนี้" ได้ ผู้ช่วยได้เลขเคสและข้อความล่าสุดของหน้านั้นไปด้วย
- เลขเคสในคำตอบกดไปที่เคสได้
- ระหว่างรอ แสดงสถานะทีละขั้นจากเซิร์ฟเวอร์จริง ได้แก่ อ่านข้อมูลอะไรไปบ้าง (จำนวนเคส บทความ เคสที่เปิดอยู่) มีงาน AI ขององค์กรรออยู่ก่อนกี่งาน AI ตัวไหนกำลังคิดและคิดมานานเท่าไร รอได้นานสุดเท่าไร และหน้าเว็บยังได้รับสถานะจากเซิร์ฟเวอร์อยู่หรือไม่ ถ้ารอนานจะบอกเหตุผลที่เป็นไปได้ เช่น คำถามที่ต้องดูหลายเคส หรือ n8n ที่ใช้โมเดลบนเครื่อง
- หลังได้คำตอบ กด **ใช้เวลา ... วินาที** ใต้คำตอบเพื่อดูขั้นตอนและเวลาของแต่ละขั้น
- กด **หยุดรอ** ระหว่างรอได้ ถ้า AI ยังไม่เริ่ม คำถามนั้นไม่ถึง AI ถ้าเริ่มแล้ว ผู้ให้บริการทำต่อจนเสร็จและยังนับเป็นการใช้งาน แต่คำตอบไม่แสดง คำถามที่หยุดแล้วไม่ถูกส่งไปกับคำถามถัดไป
- อีเมลและเบอร์โทรที่ทีมงานพิมพ์ และที่อยู่ในข้อความของลูกค้า ถูกปิดบังก่อนส่ง ไม่ส่งชื่อลูกค้า
- บทสนทนาจำไว้เฉพาะแท็บนั้น (sessionStorage) และส่งรอบล่าสุดไปกับทุกคำถาม
- เลือกบุคลิกของผู้ช่วยได้ เช่น ทางการ เป็นกันเอง หรือบรรยายเอง บุคลิกนี้ใช้เฉพาะตอนคุยกับทีมงาน ไม่มีผลกับข้อความถึงลูกค้า
- ถามได้ไม่เกิน 30 ครั้งต่อชั่วโมงต่อคน กดทำเลยได้ไม่เกิน 30 ครั้งต่อชั่วโมงต่อคน

### สั่งงาน

ผู้ช่วยไม่ลงมือเอง มันเสนอรายการสิ่งที่จะทำไว้ใต้คำตอบ ทีมงานตรวจ ติ๊กออกข้อที่ไม่เอา แก้ข้อความถึงลูกค้าหรือบันทึกภายในได้ แล้วกด **ทำเลย** ครั้งเดียว

| รายการ | ทำอะไร |
|---|---|
| แก้เคส | เปลี่ยนสถานะ ความเร่งด่วน ทีม หรือผู้รับผิดชอบ ย้ายทีมโดยไม่ระบุคนรับ เคสจะว่างให้ทีมใหม่รับ |
| ติดป้าย | ติดหรือเอาป้ายเคสออก เฉพาะป้ายที่องค์กรตั้งไว้ |
| พักเคส | พักไว้ถึงเวลาที่กำหนด ไม่เกิน 90 วัน พร้อมเหตุผล |
| นำเคสกลับเข้าคิว | ปลุกเคสที่พักไว้ทันที |
| บันทึกภายใน | เขียนบันทึกในเคสให้ทีมเห็น ลูกค้าไม่เห็น |
| ตอบลูกค้า | ส่งข้อความในเคสหรือแชทที่เปิดอยู่ ผ่านช่องทางของบทสนทนานั้น |
| ส่งข้อความซ้ำ | ส่งข้อความของเคสที่ส่งไม่สำเร็จอีกครั้ง |
| แจกเคสอัตโนมัติ | เปิดหรือปิด และตั้งเพดานต่อคน เฉพาะเจ้าขององค์กร |

- รายการบนหน้าจอเขียนจากสิ่งที่ระบบตรวจแล้ว ไม่ใช่คำบรรยายของ AI จึงตรงกับสิ่งที่จะเกิดจริง
- ตอนคำตอบมาถึง ระบบตัดรายการที่อ้างถึงเคส คน ทีม หรือป้ายที่ผู้ช่วยไม่ได้เห็นทิ้ง และบอกว่าข้ามไปกี่รายการ
- ตอนกดทำเลย ทุกรายการผ่านขั้นตอนเดียวกับการกดเองบนหน้าเคส ด้วยสิทธิ์ของคนที่กด เจ้าหน้าที่ทำได้เฉพาะเคสในทีมตัวเอง
- รายการหนึ่งทำไม่ได้ รายการอื่นยังทำต่อ แต่ละรายการบอกผลและเหตุผล
- คำตอบหนึ่งกดทำเลยได้ครั้งเดียว โดยคนที่ถามเท่านั้น และภายใน 60 นาทีหลังได้คำตอบ เพราะเคสอาจเปลี่ยนไปแล้ว
- ทุกการเปลี่ยนแปลงบันทึกในประวัติการใช้งานในชื่อของคนที่กด และมีแถว **สั่งงานผ่านผู้ช่วย AI** บอกว่าสำเร็จกี่รายการ
- ข้อความของลูกค้าและบทความถูกบอก AI ว่าเป็นข้อมูล ไม่ใช่คำสั่ง ผู้ช่วยเสนอเฉพาะสิ่งที่ทีมงานขอ

### หาต้นเหตุปัญหา

ถามว่า "ทำไม..." หรือ "...ไม่ทำงาน" ผู้ช่วยอ่านสถานะที่ส่งไปกับทุกคำถาม บอกต้นเหตุที่ข้อมูลชี้ สิ่งที่ตรวจแล้ว และเมนูที่ต้องแก้ ถ้ามีรายการสั่งงานที่แก้ได้ก็เสนอมาให้กดทำเลย

| สถานะที่ผู้ช่วยเห็น | ตัวอย่างปัญหาที่ตอบได้ |
|---|---|
| ช่องทาง: เปิดอยู่หรือไม่ ปัญหาการเชื่อมต่อ ข้อความเข้าล่าสุดเมื่อไร ข้อความที่ส่งไม่สำเร็จหรือรอส่ง | ข้อความ LINE ไม่เข้า อีเมลไม่ออก |
| แจกเคสอัตโนมัติ: เปิดอยู่หรือไม่ เพดาน ทีมที่แจก เคสที่รอแจก และแต่ละคนพร้อมรับหรือไม่เพราะอะไร (เจ้าขององค์กรเท่านั้น) | เคสใหม่ไม่ถูกแจก |
| AI: เปิดงานไหนอยู่ ใช้ไปกี่งานวันนี้ เพดานต่อวัน งานที่ล้มเหลวเพราะอะไร | Chatbot ไม่ตอบ |
| SLA ของแต่ละความเร่งด่วน และเคสที่ยังไม่มีคนรับ | ทำไมเคสเกินกำหนดเยอะ |

ผู้ช่วยแก้โค้ด เชื่อมบัญชี ใส่คีย์ หรือเปลี่ยนสถานะการทำงานของคนอื่นไม่ได้ สิ่งเหล่านี้จะบอกว่าต้องไปแก้ที่เมนูไหน

### สิ่งที่ผู้ช่วยเห็น

เฉพาะสิ่งที่ทีมงานคนนั้นเห็นบนหน้าจอของตัวเอง

- เคสที่เปิดอยู่ไม่เกิน 60 เคส เรียงจากเกินกำหนดนานที่สุด พร้อมบอกว่ามีอีกกี่เคสที่ไม่ได้ส่ง เคสที่คำถามระบุเลขมาถูกส่งเพิ่มแม้ปิดแล้ว
- เคสส่งเป็นเลขเคส หัวเรื่อง สถานะ ความเร่งด่วน ทีม ผู้รับผิดชอบ ป้าย เวลาที่เปิดมา เวลาที่เกินกำหนด และระดับความไม่พอใจของลูกค้า
- ทีม ทีมงาน และป้ายเคส ส่งเป็นชื่อพร้อมรหัสสั้น เช่น u1 t1 g1 รหัสจริงอยู่ในงานบนเซิร์ฟเวอร์ ไม่ส่งไป
- เคสหรือแชทที่เปิดอยู่: ข้อความล่าสุดไม่เกิน 14 ข้อความ รวมบันทึกภายใน และเคสอื่นของลูกค้าคนนั้น
- ลูกค้าที่คำถามระบุชื่อ อีเมล หรือเบอร์โทร: ส่งเคสของลูกค้าคนนั้น แต่ไม่ส่งชื่อหรือช่องทางติดต่อ
- เจ้าหน้าที่เห็นเฉพาะทีมของตัวเองและคนในทีม

## สรุปบทสนทนา

สิ่งที่ทีมงานต้องรู้เมื่อรับบทสนทนาต่อ แทนการอ่านทั้งหมด เขียนเป็นข้อสั้น ๆ 3 หัวข้อ: ลูกค้าต้องการอะไร ลองอะไรไปแล้ว อะไรยังค้าง

- **เก็บไว้** ขอซ้ำโดยไม่มีข้อความใหม่ ได้สรุปเดิมทันที ไม่เรียก AI
- **อัปเดตเฉพาะส่วนใหม่** มีข้อความใหม่ AI ได้สรุปเดิมกับข้อความหลังจากนั้นเท่านั้น
- **จำกัดสิ่งที่ส่ง** ข้อความใหม่สุดไม่เกิน 40 ข้อความ ตัดข้อความยาว และตัดข้อความเก่าสุดก่อนเมื่อรวมกันยาวเกิน AI ถูกบอกว่ามีข้อความถูกตัดไปกี่ข้อความ
- **เขียนล่วงหน้า** ตอนบทสนทนาเปลี่ยนมือ เช่น Chatbot ส่งต่อคน หรือเคสถูกมอบให้คนอื่น เมื่อบทสนทนายาวพอ
- รวมบันทึกภายในด้วย เพราะเป็นสิ่งที่เพื่อนร่วมทีมลองแล้ว เห็นเฉพาะทีมงาน ไม่ส่งชื่อ ช่องทางติดต่อ หรือไฟล์แนบ
- ใช้สวิตช์เดียวกับ AI ช่วยเจ้าหน้าที่

## อ่านอารมณ์ลูกค้า

ลูกค้าที่โกรธไม่ควรถูกทิ้งไว้ท้ายคิวเพียงเพราะเขียนเข้ามาทีหลัง

- ทุกข้อความของลูกค้าถูกอ่านจาก **คำในข้อความ** ทันที ฟรี และบอกได้ว่าดูจากคำไหน
- ถ้าองค์กรเชื่อม AI และเปิด **อ่านอารมณ์ลูกค้าด้วย AI** AI อ่านข้อความล่าสุดหลายข้อความพร้อมกัน จับสิ่งที่คำพลาด เช่น ข้อความสุภาพจากคนที่หมดความอดทน การประชด หรือการขู่ที่ไม่ใช้คำทั่วไป ผลของ AI แทนผลจากคำ
- ระดับมี 3 แบบ คือ ปกติ ไม่พอใจ และโกรธมาก พร้อมบอกว่าลูกค้าบอกว่ารอไม่ได้ (ด่วน) หรือไม่ และเหตุผลสั้น ๆ
- บทสนทนาเก็บผลของข้อความล่าสุดของลูกค้า ข้อความที่ใจเย็นลงแปลว่าลูกค้าใจเย็นลง
- คิวงานใช้ผลนี้ เคสของลูกค้าที่ไม่พอใจมาก่อนเคสที่แค่รอนานกว่า
- ป้ายแสดงเฉพาะลูกค้าที่ไม่พอใจ ลูกค้าปกติไม่มีป้าย

## แปลภาษาอัตโนมัติ

สำหรับลูกค้าที่ไม่ได้เขียนภาษาไทย

- ข้อความของลูกค้าที่ไม่ใช่ภาษาไทย (ตรวจจากตัวอักษร ฟรี) ถูกส่งให้ AI เฉพาะข้อความ ไม่มีข้อมูลว่าใครเขียน AI บอกภาษาและแปลเป็นไทย
- ข้อความเดิมไม่ถูกเปลี่ยน ทีมเห็นภาษาไทยพร้อมต้นฉบับในคลิกเดียว ภาษานั้นกลายเป็นภาษาที่ใช้ตอบของบทสนทนา
- คำตอบภาษาไทยของทีมถูกกักไว้ระหว่างแปล แล้วส่งเป็นภาษาของลูกค้า ข้อความที่เก็บคือสิ่งที่ลูกค้าได้รับ ภาษาไทยที่ทีมเขียนเก็บไว้คู่กัน
- คำตอบที่ทีมเขียนเป็นภาษาของลูกค้าอยู่แล้ว หรือเลือกส่งตามที่พิมพ์ ส่งทันที
- คำตอบที่แปลไม่สำเร็จ ถูกยกเลิก หรือรอนานเกิน 90 วินาที ส่งเป็นภาษาไทยตามที่เขียน และทีมเห็นว่าเกิดอะไรขึ้น
- ภาษาที่ทีมเลือกเองในข้อมูลลูกค้าชนะภาษาที่ตรวจพบ
- งานแปลและงานอ่านอารมณ์นับโควตาแยกจากงานอื่น แชทยาวของลูกค้าต่างชาติจึงไม่กินโควตาของ Chatbot และร่างคำตอบ

## ข้อมูลที่ส่งให้ AI

| งาน | สิ่งที่ส่ง | สิ่งที่ไม่ส่ง |
|---|---|---|
| ร่างคำตอบ และ Chatbot | หัวเรื่อง ข้อความล่าสุดไม่เกิน 14 ข้อความ (ตัดที่ 2,500 ตัวอักษร) และส่วนของบทความที่เกี่ยวข้อง | ไฟล์แนบ ชื่อ อีเมล เบอร์โทรของลูกค้า |
| ผู้ช่วย AI | คำถาม รอบสนทนาล่าสุด บทความที่ตรง เคส ทีมงาน ทีม ป้าย ข้อความของเคสที่เปิดอยู่ และสถานะระบบ ตามสิทธิ์ของคนที่ถาม | ชื่อ อีเมล และเบอร์โทรของลูกค้า (อีเมลและเบอร์โทรในข้อความปิดบังก่อน) |
| คำแนะนำ | จำนวน เคสที่เปิดอยู่ และคำถามของลูกค้า | อีเมลและเบอร์โทร (ปิดบังก่อน) |
| แปลภาษา | ข้อความเดียว | ข้อมูลว่าใครเขียน |

ข้อความที่ผู้ใช้พิมพ์เองอาจมีข้อมูลส่วนบุคคลอยู่ AI ไม่ลงมือแก้อะไรเอง ผู้ช่วย AI เสนอรายการ ทีมงานกดยืนยันก่อน และระบบทำด้วยสิทธิ์ของทีมงานคนนั้น

การค้นความรู้ใช้คำภาษาอังกฤษและกลุ่มอักขระภาษาไทยภายในฐานข้อมูลขององค์กร ไม่ใช้ vector database ภายนอก การอ้างอิงที่ถูกต้องไม่ได้รับประกันว่าทุกประโยคในคำตอบถูก ควรทดลองกับคำถามจริงและปรับคลังความรู้ก่อนเปิด Chatbot กับลูกค้าจำนวนมาก

## การทำงานเบื้องหลัง

- งาน AI เป็นคิวในฐานข้อมูลขององค์กร บันทึกพร้อมข้อความที่รับเข้า หน้ารับข้อความไม่รอ AI
- งานเบื้องหลัง `bookdose-ai` เรียกผู้ให้บริการได้ครั้งละหนึ่งงานต่อองค์กร และวนทำทีละองค์กร งานที่ถูกยกเลิกระหว่างรอผู้ให้บริการยังนับว่ากำลังทำ จนกว่าผู้ให้บริการตอบกลับ งานถัดไปจึงไม่ซ้อนกัน
- รอ OpenAI ไม่เกิน 25 วินาที (ผู้ช่วย AI 60 วินาที เพราะคำตอบอาจมีหลายรายการ) Gemini รอได้นานกว่า และ n8n รอได้ถึง 5 นาที
- งานที่ค้างเพราะระบบปิดระหว่างทำ ส่งต่อเจ้าหน้าที่โดยไม่เรียก AI ซ้ำ
- หน้าที่รองาน AI ตรวจสถานะทุก 1.5 วินาที ถ้าติดต่อเซิร์ฟเวอร์ไม่ได้ชั่วครู่ ลองใหม่ทุก 3 วินาทีได้ 5 ครั้งก่อนแจ้งว่าล้มเหลว เพราะงานยังทำต่อที่เซิร์ฟเวอร์
- สถานะงานที่ยังรออยู่บอกจำนวนงานที่ต้องทำก่อน เวลาที่รอ เวลาที่ AI ทำมาแล้ว ผู้ให้บริการ และเวลารอนานสุด
- คำตอบของ AI และข้อความส่งต่อไม่นับเป็นการตอบครั้งแรกของทีมใน SLA
- เพดานนับงานที่เข้าคิว รวมงานทดสอบ งานที่ล้มเหลว และงานที่ยกเลิก ไม่ใช่วงเงินเป็นบาท จำนวน tokens มาจากผู้ให้บริการ และ n8n ไม่ส่งจำนวน tokens กลับ
