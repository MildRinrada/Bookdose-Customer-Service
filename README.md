# Bookdose Customer Service

โปรแกรมเว็บภาษาไทยสำหรับดูแลลูกค้าหลายองค์กร มี 2 ส่วน: API และข้อมูลเป็น Python 3.10 ขึ้นไป (เซิร์ฟเวอร์ API ใช้ FastAPI บน uvicorn ติดตั้งจาก `requirements.txt` ส่วนอื่นใช้ standard library) และหน้าเว็บเป็น Next.js ในโฟลเดอร์ `frontend/` (ต้องมี Node.js 20 ขึ้นไป) ระบบหลักใช้งานออฟไลน์ได้ ส่วน AI, LINE และ Email ต้องใช้อินเทอร์เน็ตและบัญชีบริการขององค์กร

รายละเอียดการปรับหน้าจอและความปลอดภัยตามไฟล์ Customer Service.xlsx ทั้ง 73 ข้อ ดู [รายการตรวจรับ](docs/EXCEL-REVIEW.md) รุ่นนี้เพิ่มรูปโปรไฟล์ ชื่อ/นามสกุลลูกค้า ตัวกรองรายงาน เครื่องมือจัดรูปแบบบทความ และแท็บตั้งค่าองค์กร ปุ่มลืมรหัสผ่านแจ้งช่องทางติดต่อผู้ดูแลตามทางเลือกในเอกสาร ยังไม่มีการรีเซ็ตรหัสผ่านผ่านอีเมล

## เปิดใช้งาน

**นำขึ้นออนไลน์ด้วย Render:** มีไฟล์ตั้งค่าพร้อมแล้ว ดู [คู่มือ deploy](docs/DEPLOY-RENDER.md) ใช้ 2 บริการ (หน้าเว็บ Node.js และ API Python แบบ private พร้อมดิสก์ถาวร) แบบเสียเงิน และรหัสป้องกันการสร้างผู้ดูแลครั้งแรก

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https%3A%2F%2Fgithub.com%2FA10U%2Fbookdose-customer-service)

ติดตั้ง Python 3.10 ขึ้นไป และ [Node.js](https://nodejs.org) 20 ขึ้นไปก่อน แล้ว

**macOS:** ดับเบิลคลิก `Start Bookdose.command` แล้วเปิด **http://localhost:3000** ในเบราว์เซอร์

**Windows:** ดับเบิลคลิก `Start Bookdose.bat` แล้วเปิด **http://localhost:3000**

ครั้งแรกสคริปต์จะติดตั้งแพ็กเกจ Python ของเซิร์ฟเวอร์ API (FastAPI, uvicorn) และติดตั้งและ build หน้าเว็บให้ (ใช้เวลาสักครู่และต้องต่ออินเทอร์เน็ต) หลังอัปเดตโค้ดให้ลบโฟลเดอร์ `frontend/.next` เพื่อ build ใหม่ สคริปต์เปิด API ที่ `127.0.0.1:8787` และหน้าเว็บที่พอร์ต 3000 ในหน้าต่างเดียวกัน

หรือเปิด Terminal 2 หน้าต่างในโฟลเดอร์โปรแกรม (โหมดพัฒนา แก้โค้ดแล้วเห็นผลทันที):

```sh
python3 -m pip install -r requirements.txt  # ครั้งแรก และทุกครั้งที่ requirements.txt เปลี่ยน
python3 app.py                       # API ที่ http://127.0.0.1:8787 (FastAPI บน uvicorn)
cd frontend && npm install && npm run dev   # หน้าเว็บที่ http://localhost:3000
```

**เซิร์ฟเวอร์ API:** `python3 app.py` เปิด FastAPI บน uvicorn แบบ worker เดียว (การจำกัดคำขอ, SQLite และงานเบื้องหลังอยู่ใน process เดียวกัน อย่ารันหลาย worker) ตัวเลือกเดิมใช้ได้ทั้งหมด (`--host`, `--port`, `--secure-cookies`, `--backup`, `--restore`) uvicorn ไม่เชื่อ `X-Forwarded-For` เอง ที่อยู่ของผู้ใช้มาจากหน้าเว็บ Next.js ตามเดิม (`backend/middleware/security.py`) และ log ไม่พิมพ์ path หรือ query string

**Realtime (WebSocket):** บน FastAPI หน้าเว็บต่อ WebSocket ที่ `/api/realtime/staff` (ทีมงาน), `/api/realtime/customer` (ลูกค้าที่เข้าสู่ระบบ) และ `/api/public/<รหัสองค์กร>/guest/realtime` (ผู้เยี่ยมชม) ผ่าน Next.js ที่พอร์ต 3000 ช่องนี้ส่งแค่ "มีอะไรเปลี่ยน" (หน้าเว็บดึงข้อมูลใหม่ผ่าน API เดิม) สถานะกำลังพิมพ์ และอ่านแล้ว ใช้แพ็กเกจ `websockets` จาก `requirements.txt` ตรวจ Host/Origin และคุกกี้แบบเดียวกับ HTTP ต้องรัน worker เดียว (ศูนย์กลางข้อความอยู่ในหน่วยความจำ ถ้ารันหลาย worker ต้องมี broker เช่น Redis) เซิร์ฟเวอร์เดิม (`legacy`) ไม่มี WebSocket หน้าเว็บจะดึงข้อมูลเป็นระยะแบบเดิม รายละเอียดใน [docs/REALTIME-DESIGN.md](docs/REALTIME-DESIGN.md) และโค้ดใน `backend/realtime/`

**ความปลอดภัยการเข้าสู่ระบบ (รอบความปลอดภัย, [docs/SECURITY-DESIGN.md](docs/SECURITY-DESIGN.md)):**

- **ล็อกบัญชีแบบเพิ่มเวลา:** กรอกรหัสผ่านผิด (ลูกค้า: รวมรหัสยืนยันสองขั้นตอน รหัสสำรอง และ Passkey ที่ถูกปฏิเสธ) 5 ครั้งใน 15 นาทีต่ออีเมลที่พิมพ์ (ไม่ว่ามีบัญชีหรือไม่) ล็อก 5 นาที → 15 นาที → 1 ชั่วโมง → 24 ชั่วโมง ระดับลดลง 1 ทุก 24 ชั่วโมงที่ไม่ถูกล็อกใหม่ ระหว่างล็อกทุกครั้งตอบ 429 `{error, retry_after}` พร้อม `Retry-After` เหมือนกันทั้งอีเมลที่มีและไม่มีบัญชี และไม่ต่อเวลาล็อก ปลดล็อกเองเมื่อครบเวลา เมื่อลูกค้าตั้งรหัสผ่านใหม่จากลิงก์อีเมล หรือเมื่อผู้ดูแลแพลตฟอร์มกดปลดล็อก เข้าสู่ระบบสำเร็จล้างจำนวนครั้ง เจ้าของบัญชีได้อีเมลแจ้ง (IP ถูกปิดบางส่วน) ไม่เกินวันละครั้งเมื่อตั้งกล่องจดหมายกลางแล้ว ข้อมูลอยู่ในตาราง `login_failures` ของฐานข้อมูลกลาง หน้าเข้าสู่ระบบใช้ `POST /api/sign-in` ครั้งเดียวตรวจทั้งบัญชีทีมงานและบัญชีลูกค้าของอีเมลนั้น (นับด้วยคีย์ `signin:<อีเมล>` นับผิด 1 ครั้งเมื่อรหัสไม่ตรงกับบัญชีใดเลย ถ้าตรงทั้งคู่เข้าเป็นทีมงาน) ส่วน `/api/login` และ `/api/customer/login` ยังใช้ได้ด้วยคีย์ `staff:` / `customer:` ของตัวเอง และคีย์ใดของอีเมลเดียวกันถูกล็อก อีกสองทางก็ตอบ 429 ด้วย
- **อายุเซสชัน:** หมดเมื่อไม่ได้ใช้งานเกินกำหนด หรือครบอายุสูงสุด ค่าเริ่มต้น เจ้าหน้าที่ 60 นาที / 12 ชม., ผู้ดูแลแพลตฟอร์ม 30 นาที / 8 ชม., ลูกค้า 7 วัน / 30 วัน (แก้ได้ที่ **คอนโซลระบบกลาง → ความปลอดภัย**) คำขอ GET ที่ดึงข้อมูลเป็นระยะและ WebSocket ไม่นับเป็นการใช้งาน การใช้งานคือคำขอที่เปลี่ยนข้อมูล หรือ `POST /api/session/activity` (ทีมงาน) / `POST /api/customer/activity` (ลูกค้า) ที่หน้าเว็บส่งไม่เกินนาทีละครั้งขณะผู้ใช้กดหรือพิมพ์ เซสชันที่หมดตอบ 401 `{error, reason: idle|absolute}` และถูกลบ WebSocket ของเซสชันนั้นปิดด้วยรหัส 4401 ในรอบตรวจถัดไป เซสชันเดิมก่อนอัปเกรดนับเวลาเริ่มจากตอนอัปเกรด (ไม่มีใครถูกออกจากระบบเพราะการอัปเกรด)
- **เหตุการณ์ความปลอดภัยและแดชบอร์ด:** ระบบบันทึกเข้าสู่ระบบล้มเหลว การล็อก เซสชันหมดอายุ คำขอถี่เกิน CSRF/Origin ที่ถูกปฏิเสธ การเข้าองค์กรอื่นที่ถูกปฏิเสธ การเข้าช่วยเหลือองค์กร ลายเซ็น Webhook ผิด ลิงก์ผู้เยี่ยมชมที่ใช้ไม่ได้ IP ที่ถูกบล็อก และทุกการเปลี่ยนแปลงของผู้ดูแลแพลตฟอร์ม (`security_events` เก็บ 90 วัน เหตุการณ์ซ้ำในนาทีเดียวกันรวมเป็นแถวเดียว ไม่เก็บรหัสผ่าน รหัส โทเคน หรือข้อความ) worker `bookdose-security` ตรวจกฎแจ้งเตือนทุกนาที (`security_alerts` เกณฑ์ปรับได้) และส่งอีเมลถึงผู้ดูแลแพลตฟอร์มเมื่อมีระดับวิกฤต API อยู่ที่ `/api/platform/security/*` (เฉพาะผู้ดูแลแพลตฟอร์ม)
- **บล็อก IP:** ผู้ดูแลแพลตฟอร์มบล็อก IP ได้ 1 ชม. / 24 ชม. / 7 วัน / ถาวร (`ip_blocks`) ตรวจก่อนทุกอย่างทั้ง HTTP (403) และ WebSocket (ปิด 4403) ใช้ที่อยู่ของผู้ใช้ชุดเดียวกับการจำกัดคำขอ (ที่อยู่ socket หรือ `X-Bookdose-Client-IP` จากหน้าเว็บ Next.js ที่เชื่อถือได้ ไม่เชื่อ `X-Forwarded-For`) และบล็อก IP ของคำขอตัวเองไม่ได้
- **กับดัก (Honeypot / Honeytoken, [docs/HONEYPOT-DESIGN.md](docs/HONEYPOT-DESIGN.md)):** จับผู้สแกน บอท และคนในที่แตะสิ่งที่ผู้ใช้จริงไม่เคยแตะ โดยคำตอบไม่เปลี่ยนเลย (`backend/modules/security/traps.py`)
  - **เส้นทางล่อ:** API เช่น `/api/admin`, `/api/.env`, `/api/graphql` และเส้นทางที่ผู้ดูแลแพลตฟอร์มเพิ่มเอง (ไม่เกิน 50 แบบตรงตัวหรือขึ้นต้นด้วย ห้ามซ้อนกับ route จริง) ตอบเหมือน path ที่ไม่มีอยู่ทุกไบต์ หน้าเว็บล่อ (`/.env`, `/wp-login.php` …) และลิงก์ไฟล์ `/files/<token>` หน้าเว็บ Next.js รายงานผ่าน `POST /api/trap` (รับเฉพาะจากหน้าเว็บ: `X-Bookdose-Trap: 1` + เงื่อนไขเดียวกับ `X-Bookdose-Client-IP` นอกนั้นตอบเหมือน path ที่ไม่มีอยู่) เหตุการณ์ `honeypot_path` แตะครบ 3 ครั้งใน 10 นาทีบล็อก IP 1 ชม. (ปรับได้)
  - **ช่องซ่อนในฟอร์ม:** `website` (หรือ `company_website`) ในเข้าสู่ระบบ (`/api/sign-in`, `/api/login`, `/api/customer/login`) สมัครองค์กร สมัครลูกค้า ลืมรหัสผ่าน และเริ่มแชทผู้เยี่ยมชม ถ้ามีค่า คำขอไม่ถูกทำต่อแต่ตอบเหมือนความล้มเหลวปกติ (401 รหัสผิด / 202 ส่งลิงก์แล้ว / 400 ข้อความกันสแปม) ไม่นับเข้าการล็อกบัญชี เหตุการณ์ `honeypot_form`
  - **Honeytoken:** ผู้ดูแลแพลตฟอร์มสร้างอีเมลบัญชีล่อ API key (`bdk_live_…`) รหัสผ่าน หรือลิงก์ไฟล์ แสดงความลับครั้งเดียว เก็บเพียง SHA-256 (`honeytokens`) ตรวจในหน่วยความจำด้วย prefix 12 ตัวแรก (hash เฉพาะเมื่อ prefix ตรง) ใน Authorization, X-API-Key, คุกกี้, query string, JSON body ≤ 1 MB, อีเมลเข้าสู่ระบบ/ลืมรหัสผ่าน/สมัคร/เพิ่มสมาชิก และรหัสผ่านบน endpoint เข้าสู่ระบบ เมื่อถูกใช้: เหตุการณ์ `honeytoken_triggered` (วิกฤต ระบุผู้ใช้ถ้าเป็นคนในที่เข้าสู่ระบบอยู่) แจ้งเตือนทันที อีเมลผู้ดูแล (ไม่เกินชั่วโมงละครั้งต่อกับดัก) และบล็อก IP 24 ชม. (ปรับได้) ยกเว้น loopback และ IP ของผู้ดูแลแพลตฟอร์มที่เข้าสู่ระบบอยู่ การบล็อกอัตโนมัติบันทึกเป็น `trap_ip_block`
  - การบันทึกทำใน thread เบื้องหลัง `bookdose-traps` คำขอปกติเสียเวลาเพิ่มราว 1–2 ไมโครวินาที API: `GET/POST /api/platform/security/honeytokens`, `PATCH/DELETE /api/platform/security/honeytokens/<id>`, `POST …/<id>/test` และ `honeypot` ใน `/api/platform/security/settings`

**ย้อนกลับไปใช้เซิร์ฟเวอร์เดิม (`http.server`):** ตั้ง `BOOKDOSE_SERVER=legacy` ก่อนรัน เช่น `BOOKDOSE_SERVER=legacy python3 app.py` (Windows: `set BOOKDOSE_SERVER=legacy` แล้ว `py -3 app.py`) ทั้งสองแบบใช้ route, การตรวจสิทธิ์ และข้อความ error ชุดเดียวกัน (`backend/http/dispatch.py`) ชุดทดสอบเลือกเซิร์ฟเวอร์ด้วยตัวแปรเดียวกัน: `python -m unittest discover -s tests` ทดสอบบน FastAPI และ `BOOKDOSE_SERVER=legacy python -m unittest discover -s tests` ทดสอบบนเซิร์ฟเวอร์เดิม

เปิดหน้าต่าง Terminal ค้างไว้ระหว่างใช้งาน ปิดโปรแกรมด้วย `Ctrl+C` ข้อมูลจะยังอยู่เมื่อเปิดใหม่ ถ้าพอร์ต 8787 ถูกใช้อยู่ ให้ใช้ `python3 app.py --port 8788` แล้วตั้ง `BOOKDOSE_API_URL=http://127.0.0.1:8788` ให้หน้าเว็บ (ดู `frontend/.env.example`) ถ้าพอร์ต 3000 ถูกใช้อยู่ ให้ตั้ง `PORT=3001` ก่อน `npm run dev` / `npm start`

ครั้งแรกจะพบหน้าสร้างผู้ดูแล กรอกชื่อ อีเมล รหัสผ่านอย่างน้อย 10 ตัวอักษร ชื่อองค์กร และรหัสองค์กร เช่น `bookdose` บัญชีแรกเป็นทั้งผู้ดูแลแพลตฟอร์มและผู้ดูแลองค์กรแรก ไม่มีบัญชีหรือรหัสผ่านเริ่มต้นที่ฝังไว้ในโปรแกรม

เลือกเพิ่มข้อมูลตัวอย่างได้ จะมี 5 เคสและบทความภายใน 2 บทความ หากต้องการเริ่มใช้งานด้วยข้อมูลจริงทันที ให้เอาเครื่องหมายเพิ่มข้อมูลตัวอย่างออกก่อนสร้างองค์กร

## สมัครใช้งานสำหรับองค์กรใหม่

หลังเจ้าของระบบตั้งค่าครั้งแรกและเปิดใช้งานอีเมลยืนยันแล้ว ลูกค้าองค์กรใหม่กด **สมัครองค์กรใหม่** ที่หน้าเข้าสู่ระบบ หรือเปิด **http://localhost:3000/register** ได้เลย หากยังเข้าสู่ระบบด้วยบัญชีอื่นอยู่ ให้ออกจากระบบก่อน

1. กรอกชื่อผู้ดูแล อีเมล รหัสผ่านอย่างน้อย 10 ตัวอักษร และยืนยันรหัสผ่าน
2. กรอกชื่อองค์กรและรหัสองค์กรที่ยังไม่มีผู้ใช้ เช่น `my-company` ใช้ตัวอักษร a-z ตัวเลข และขีดกลาง
3. กด **สมัครและส่งอีเมลยืนยัน** แล้วตรวจกล่องจดหมายและสแปม ระบบยังไม่สร้างบัญชีหรือองค์กรจนกว่าจะยืนยันอีเมล
4. เปิดลิงก์ในอีเมล แล้วกด **ยืนยันอีเมลและสร้างองค์กร** ลิงก์มีอายุ 1 ชั่วโมง ใช้ได้ครั้งเดียว ระบบสร้างองค์กรและเข้าสู่ระบบให้ ไม่มีข้อมูลเคสตัวอย่าง
5. ไปที่ **ตั้งค่าองค์กร** เพื่อเพิ่มทีมและสมาชิก ตั้งค่าช่องทาง และคัดลอกลิงก์หน้าลูกค้าให้ลูกค้าปลายทาง (หน้าแรกของระบบ หรือ `/?org=my-company` เมื่อระบบให้บริการหลายองค์กร)

ผู้สมัครได้สิทธิ์ผู้ดูแลเฉพาะองค์กรที่สร้าง ไม่ได้สิทธิ์ผู้ดูแลแพลตฟอร์ม และเข้าข้อมูลองค์กรอื่นไม่ได้ การสมัครนี้สร้างองค์กรใหม่ ไม่ใช่การเข้าร่วมองค์กรเดิม หากมีบัญชีแล้วให้เข้าสู่ระบบและติดต่อผู้ดูแลแพลตฟอร์มเพื่อเพิ่มองค์กร หากต้องการเป็นสมาชิกในองค์กรเดิมให้ติดต่อผู้ดูแลองค์กรนั้น

หากไม่พบอีเมล ให้กด **ขอลิงก์ใหม่** จากหน้าเข้าสู่ระบบหรือหน้าตรวจอีเมล รออย่างน้อย 1 นาทีระหว่างการส่ง ลิงก์ใหม่ยกเลิกลิงก์เดิม คำขอที่ยังไม่ยืนยันเกิน 24 ชั่วโมงต้องสมัครใหม่ ระบบล้างคำขอเก่าเมื่อมีการสมัคร ขอลิงก์ หรือยืนยันครั้งถัดไป จำกัดการสมัครและขอลิงก์รวมกัน 5 คำขอต่อ IP ใน 15 นาที แยกจากการเข้าสู่ระบบ อีเมลที่มีบัญชีแล้วจะไม่สร้างบัญชีซ้ำ ให้เข้าสู่ระบบตามปกติ

ก่อนยืนยัน รหัสองค์กรยังไม่ได้ถูกจอง หากมีองค์กรอื่นใช้รหัสนั้นก่อน ให้กลับไปสมัครด้วยรหัสองค์กรใหม่ บัญชีที่มีอยู่เดิม บัญชีตั้งค่าครั้งแรก และบัญชีที่ผู้ดูแลสร้างให้ยังเข้าสู่ระบบตามเดิม ไม่ถูกระบุว่ายืนยันอีเมลแล้วโดยอัตโนมัติ ข้อมูลบัญชีและองค์กรยังอยู่หลังปิดและเปิดโปรแกรมใหม่เมื่อใช้โฟลเดอร์ข้อมูลเดิม

สำหรับลูกค้าภายนอก ให้ติดตั้งระบบบนโดเมน HTTPS ที่เข้าถึงได้และส่งลิงก์ `https://โดเมนของคุณ/register` แทน localhost ซึ่งใช้ได้เฉพาะเครื่องที่เปิดโปรแกรม

### ตั้งค่าอีเมลยืนยัน (ผู้ดูแลแพลตฟอร์ม)

เปิด **คอนโซลระบบกลาง → จัดการองค์กร → อีเมลยืนยันการสมัครองค์กร** กรอกโดเมนเว็บไซต์ เช่น `https://support.example.com` อีเมลผู้ส่ง เซิร์ฟเวอร์ SMTP พอร์ต 465 (TLS) หรือ 587 (STARTTLS) ชื่อผู้ใช้ และรหัสผ่าน SMTP / App Password จากผู้ให้บริการ แล้วเลือก **เปิดรับสมัครองค์กรพร้อมยืนยันอีเมล** และบันทึก

อีเมลชุดนี้เป็นบัญชีส่งของแพลตฟอร์ม Bookdose แยกจากกล่องรับเรื่องรายองค์กร ใช้ SMTP แบบรหัสผ่าน / App Password ที่ผู้ให้บริการอนุญาต รุ่นนี้ยังไม่ใช้ OAuth สำหรับอีเมลยืนยัน แม้ช่องทางรับเรื่องรายองค์กรจะรองรับ OAuth แล้ว การบันทึกตรวจรูปแบบค่าแต่ไม่ได้ทดสอบส่งจริง ตรวจการส่งได้ด้วยการสมัครอีเมลที่คุณเป็นเจ้าของ

โดเมนต้องตรงกับเว็บไซต์ที่ลูกค้าเปิดได้ ลิงก์ในอีเมลใช้ค่าที่ผู้ดูแลตั้งไว้ ไม่ใช้ Host จากคำขอ ใช้ที่อยู่ของหน้าเว็บ (แอป Next.js) ไม่ใช่ของ API สำหรับทดสอบในเครื่องเดียวใช้ `http://localhost:3000` ได้ หากยังไม่ตั้งค่าหรือไม่มีรหัสผ่านผู้ส่ง ระบบจะปิดรับสมัครใหม่และไม่ข้ามขั้นตอนยืนยัน บัญชีเดิมยังใช้ได้

รหัสผ่านผู้ส่งอยู่ใน `data/secrets/registration-smtp.json` เข้ารหัสด้วยกุญแจของแพลตฟอร์ม สิทธิ์ไฟล์ 0600 ไม่ส่งกลับหน้าจอ ไม่รวมใน Git ไฟล์สำรองทั้งระบบมีเฉพาะแบบเข้ารหัส กู้คืนพร้อมกุญแจเดิมแล้วใช้ต่อได้ทันที การกู้คืนทั้งระบบล้างคำขอสมัครค้างเพื่อไม่ให้ลิงก์ที่เคยใช้แล้วกลับมาใช้ซ้ำได้ รหัสผ่านของผู้สมัครและโทเคนยืนยันในฐานข้อมูลเก็บเฉพาะค่าแฮช เมื่อ SMTP แจ้งผลไม่แน่นอน ระบบไม่ส่งซ้ำอัตโนมัติ ให้ตรวจกล่องจดหมายก่อนขอลิงก์ใหม่

## ขั้นตอนใช้งานประจำวัน

**ปรับขนาดตัวอักษร:** กด **A− / A+** บริเวณด้านบนของหน้าเพื่อลดหรือเพิ่มครั้งละ 10% หรือเลือกเปอร์เซ็นต์โดยตรงได้ตั้งแต่ **80% ถึง 150%** (ค่าเริ่มต้น 100% ของขนาดพื้นฐานเบราว์เซอร์) ใช้ได้ทั้งหน้าเข้าสู่ระบบ หน้าพนักงาน และหน้าลูกค้า โปรแกรมจดจำในเบราว์เซอร์เดิมและใช้ร่วมกันระหว่างแท็บ กลับค่าเริ่มต้นด้วยการเลือก “100%” หากเบราว์เซอร์ปิดการจัดเก็บข้อมูล ยังปรับขนาดในหน้าปัจจุบันได้

1. **ตั้งค่าองค์กร:** เพิ่มทีมและสมาชิก กำหนด SLA และข้อความต้อนรับ สมาชิกใหม่ได้รับบัญชีใช้งานทันที ผู้ดูแลแจ้งรหัสผ่านให้เจ้าตัวด้วยช่องทางที่เหมาะสม โปรแกรมไม่ส่งอีเมลเชิญ
2. **ลูกค้าเข้าใช้หน้าแรกเดียวกัน:** ลูกค้าเปิดหน้าแรกของระบบ (เช่น `http://localhost:3000/`) กดแท็บ **สมัครสมาชิก** หรือเข้าสู่ระบบในช่องเดียวกับเจ้าหน้าที่ แล้วเริ่มแชทถึงทีมงาน (ดู [บัญชีลูกค้าและหน้าลูกค้า](#บัญชีลูกค้าและหน้าลูกค้า))
3. **รับเรื่องในกล่องข้อความ:** เลือกบทสนทนา ตอบลูกค้า หรือเพิ่มบันทึกภายใน ถ้าต้องติดตามงานให้กด **เปิดเคส** บทสนทนากับเคสเป็นข้อมูลคนละชุด คำถามที่ตอบจบได้ไม่จำเป็นต้องเปิดเคส
4. **จัดการเคส:** เลือกทีม ผู้รับผิดชอบ สถานะ และความเร่งด่วน แล้วกดบันทึก เคสที่เจ้าหน้าที่สร้างเองใช้บันทึกภายใน ส่วนเคสที่มาจากแชทของลูกค้าตอบถึงลูกค้าได้ และลูกค้าเห็นสถานะในเมนู **เคสของฉัน**
5. **ติดตามฝั่งลูกค้า:** ลูกค้าเข้าสู่ระบบแล้วเห็น **แชทของฉัน** และ **เคสของฉัน** ทุกเรื่อง อ่านคำตอบและส่งข้อความเพิ่มได้ ไม่ต้องเก็บลิงก์ ข้อความอัปเดตทุก 10 วินาทีเมื่อเปิดแชทอยู่ และได้รับอีเมลแจ้งเมื่อทีมตอบ
6. **ปิดงาน:** เปลี่ยนสถานะเป็นแก้ไขแล้วหรือปิดเคส ลูกค้าส่งข้อความเพิ่มในเรื่องเดิมจะเปิดเคสกลับมาเป็นกำลังดำเนินการโดยอัตโนมัติ
7. **รายงาน:** เลือกช่วงวันที่สร้างเคส ทีม และผู้รับผิดชอบ ดูสถานะ เวลาตอบเฉลี่ย และเปรียบเทียบช่วงก่อนหน้าที่ยาวเท่ากัน CSV หน้ารายงานใช้ตัวกรองเดียวกับรายงาน ส่วนหน้าเคสเลือก Checkbox เพื่อส่งออกเฉพาะเคสที่เลือกได้ ทุกส่วนจำกัดข้อมูลตามสิทธิ์

## บัญชีลูกค้าและหน้าลูกค้า

ลูกค้าใช้หน้าแรกของระบบเหมือนเจ้าหน้าที่ ไม่มีลิงก์เฉพาะที่ต้องจำ ช่องเข้าสู่ระบบเดียวกันพาเจ้าหน้าที่ไปหน้าทำงาน และพาลูกค้าไปหน้าลูกค้า ลิงก์ `/support/…` แบบเดิมเลิกใช้แล้ว

**บัญชีเดียวใช้ได้ทุกองค์กร:** ลูกค้าคนหนึ่งอาจเป็นลูกค้าของ Bookdose และขององค์กรอื่นบนระบบพร้อมกัน จึงสมัครครั้งเดียวแล้วติดต่อได้ทุกองค์กรที่เกี่ยวข้อง

- **องค์กรที่ติดต่อได้:** Bookdose (องค์กรที่สร้างตอนตั้งค่าครั้งแรก) อยู่บนสุดเสมอ เพื่อให้แจ้งปัญหาตัวระบบได้ตลอด องค์กรอื่นเพิ่มเข้ามาเมื่อลูกค้าเปิดลิงก์ขององค์กรนั้น (`/?org=<รหัสองค์กร>`) หรือกรอกรหัสองค์กรในหน้า **เริ่มแชทใหม่** / **ตั้งค่าบัญชี** รายชื่อลูกค้าของแต่ละองค์กรไม่ถูกเปิดเผยให้คนทั่วไป
- **เริ่มแชทใหม่:** เลือกองค์กรปลายทางก่อน (ติดต่อ Bookdose โดยตรงสำหรับปัญหาระบบ แพลตฟอร์มค้าง แจ้ง Bug / องค์กรคู่ค้าสำหรับบริการ สินค้า หรือเคสขององค์กรนั้น) ข้อความต้อนรับและเวลาตอบกลับเปลี่ยนตามองค์กรที่เลือก แล้วเลือก **หมวดเรื่อง** ของกลุ่มนั้น เรื่องจะเข้าทีมที่องค์กรกำหนดให้หมวดนั้นทันที และนับ SLA ขององค์กรนั้น
- **หมวดเรื่อง:** ผู้ดูแลองค์กรตั้งได้ที่ **ตั้งค่าองค์กร → ภาพรวมและบริการ → หมวดเรื่องที่ลูกค้าเลือก** 1-12 หมวด แต่ละหมวดเลือกทีมที่รับเรื่องได้ (ค่าเริ่มต้น: สอบถามบริการ / แจ้งปัญหาการใช้งาน / ข้อเสนอแนะและร้องเรียน) เจ้าหน้าที่เห็นหมวดในหัวบทสนทนา และเคสที่เปิดจากบทสนทนาใช้หมวดนั้น
- **แยกข้อมูลตามองค์กร:** รายการแชทและเคสมีป้ายชื่อองค์กร และกรองตามองค์กรได้ แชท เคส และข้อมูลติดต่อของแต่ละองค์กรเก็บในฐานข้อมูลขององค์กรนั้น ทีมขององค์กรหนึ่งไม่เห็นเรื่องที่ลูกค้าคุยกับองค์กรอื่นหรือกับ Bookdose
- **หลังปิดเคส:** แบบประเมินให้เลือก 1-5 ดาวพร้อมช่องความคิดเห็น (ไม่บังคับ ไม่เกิน 1,000 ตัวอักษร) ความคิดเห็นแสดงในหน้าเคสของเจ้าหน้าที่ ถ้า AI ตอบอยู่ ลูกค้ากด **คุยกับเจ้าหน้าที่** เพื่อส่งให้เจ้าหน้าที่ขององค์กรนั้นได้ตลอดเวลา

บัญชีลูกค้าที่เคยเก็บแยกในฐานข้อมูลแต่ละองค์กรจะถูกย้ายมาเป็นบัญชีกลางอัตโนมัติเมื่อเปิดโปรแกรมรุ่นนี้ครั้งแรก (อีเมลเดียวกันจากหลายองค์กรรวมเป็นบัญชีเดียว ใช้รหัสผ่านของบัญชีที่สร้างก่อน) และลูกค้าต้องเข้าสู่ระบบใหม่หนึ่งครั้ง

เมื่อเข้าสู่ระบบ ลูกค้าเห็นเมนูด้านข้าง แถบด้านบน และการ์ดแบบเดียวกับหน้าทีมงาน:

| เมนู | ใช้ทำอะไร |
|---|---|
| **แชทของฉัน** | รายการแชททั้งหมดทางซ้าย เปิดอ่านและตอบทางขวา เริ่มแชทใหม่พร้อมแนบไฟล์ ขอคุยกับเจ้าหน้าที่เมื่อ AI ตอบอยู่ และให้คะแนน 1-5 ดาวหลังปิดเคส ข้อความอัปเดตทุก 10 วินาที |
| **เคสของฉัน** | เคสที่ทีมรับไว้ (เลข BD-xx) พร้อมสถานะ กำหนดตอบครั้งแรก กำหนดเสร็จ วันที่ทีมนัดติดตาม และแชทที่อยู่ในเคส ไม่แสดงความเร่งด่วน ทีม ผู้รับผิดชอบ หรือบันทึกภายใน |
| **คำถามที่พบบ่อย** | บทความสาธารณะในคลังความรู้ ค้นหาและกรองตามหมวดได้ ลิงก์บทความที่ทีมส่งให้ (`#faq/<id>`) เปิดอ่านได้โดยไม่ต้องเข้าสู่ระบบ |
| **การแจ้งเตือน** | สิ่งที่รอลูกค้า (ทีมตอบแล้ว ทีมรอข้อมูล แบบประเมิน) นับเป็นตัวเลขบนกระดิ่ง และความคืบหน้าล่าสุด (เคสเสร็จใน 7 วัน นัดติดตาม) รายการหายเองเมื่ออ่านแชท ตอบแบบประเมิน หรือทีมเปลี่ยนสถานะ |
| **ตั้งค่าบัญชี** | แบ่งเป็นแท็บ (`?tab=`): **ข้อมูลส่วนตัว** (ชื่อ เบอร์โทร ความยินยอม ออกจากระบบ) · **ความปลอดภัย** (รหัสผ่าน การยืนยันสองขั้นตอน Passkey อุปกรณ์ที่เข้าสู่ระบบ ประวัติการใช้งาน) · **องค์กรของฉัน** (องค์กรที่ติดต่อได้ และการเพิ่มองค์กรด้วยรหัส ลิงก์ หรือสแกน QR) · **การแจ้งเตือน** (อีเมล/LINE และการเชื่อม LINE ขององค์กร) |
| **ภาพรวม** | ระดับการให้บริการของเคสตัวเองต่อองค์กร: จำนวนเคส เคสที่ยังเปิด เวลาตอบครั้งแรกและเวลาแก้ไขเฉลี่ย สัดส่วนที่ทันกำหนด SLA และคะแนนความพึงพอใจเฉลี่ย |

**บัญชีลูกค้า (ความปลอดภัย องค์กร การแจ้งเตือน):**

- **ความปลอดภัยบัญชีลูกค้า:** การยืนยันสองขั้นตอนด้วยแอป (TOTP) พร้อมรหัสสำรอง 10 รหัส (ใช้ได้ครั้งเดียว), **Passkey** (WebAuthn ทั้ง P-256 และ Windows Hello), รายการอุปกรณ์ที่เข้าสู่ระบบพร้อมปุ่มออกจากระบบทีละเครื่องหรือทุกเครื่อง และประวัติการใช้งานบัญชี (เข้าสู่ระบบ การยืนยันสองขั้นตอน Passkey เปลี่ยนรหัสผ่าน) — ของฝั่งทีมงานยังเหมือนเดิม
- **ลิงก์และ QR ขององค์กร:** ผู้ดูแลองค์กรสร้างลิงก์เชิญพร้อม QR ที่ **ตั้งค่าองค์กร → ลิงก์และ QR สำหรับลูกค้า** (กำหนดอายุและจำนวนคน ยกเลิกได้) ลูกค้าสแกนแล้วเปิด `/join/<token>` กดเข้าร่วมองค์กรได้ทันที หรือสแกน QR จากหน้าตั้งค่าบัญชีเอง
- **แจ้งเตือนทาง LINE:** เลือกช่องทาง (อีเมล / LINE) ได้ที่ **ตั้งค่าบัญชี → การแจ้งเตือน** เชื่อม LINE ขององค์กรโดยส่งรหัส 6 หลัก (อายุ 10 นาที) ในแชท 1:1 กับ LINE OA แล้วเมื่อทีมตอบในแชทจะได้ข้อความแจ้งพร้อมลิงก์ (ไม่มีเนื้อหาข้อความ) รหัสที่พิมพ์ในกลุ่ม LINE ใช้ไม่ได้และถูกยกเลิกทันที ส่งซ้ำเมื่อล้มเหลวได้ 3 ครั้ง

1. **สมัครสมาชิก:** กรอกเฉพาะชื่อ-นามสกุลหรือชื่อที่ต้องการให้เรียก อีเมล รหัสผ่าน (อย่างน้อย 10 ตัวอักษร) และเบอร์โทรศัพท์ถ้าต้องการ แล้วติ๊กยอมรับประกาศความเป็นส่วนตัว ระบบไม่ขอที่อยู่ วันเกิด เพศ ตำแหน่ง หรือบริษัท
2. **ยืนยันอีเมลก่อนใช้งาน:** ระบบส่งลิงก์ไปที่อีเมล (อายุ 24 ชั่วโมง) หน้ายืนยันขอรหัสผ่านที่ตั้งไว้ตอนสมัคร แล้วเข้าสู่ระบบให้ทันที ไม่มี OTP ถ้าคนอื่นเคยใช้อีเมลของคุณสมัครไว้ก่อน ลิงก์ของเขาใช้กับรหัสผ่านของคุณไม่ได้ จึงยึดบัญชีไม่ได้ ถ้าอีเมลมีบัญชีแล้ว ระบบส่งวิธีเข้าสู่ระบบไปที่อีเมลนั้นแทน และตอบบนหน้าจอเหมือนกัน เพื่อไม่เปิดเผยว่าใครเป็นลูกค้า
3. **แจ้งเตือนทางอีเมล:** เมื่อทีมตอบในแชทของลูกค้า ระบบส่งอีเมลแจ้งพร้อมลิงก์เปิดแชทนั้น (เปิดหลังเข้าสู่ระบบ) โดยไม่ใส่เนื้อหาข้อความในอีเมล ถ้าลูกค้าเปิดอ่านบนหน้าเว็บภายใน 2 นาทีจะไม่ส่ง และค้างได้อย่างมากหนึ่งฉบับต่อแชท
4. **ลืมรหัสผ่าน:** กด **ลืมรหัสผ่าน?** ในหน้าเข้าสู่ระบบ แล้วขอลิงก์ตั้งรหัสผ่านใหม่ทางอีเมล (อายุ 1 ชั่วโมง ใช้ได้ครั้งเดียว) เมื่อตั้งใหม่ อุปกรณ์อื่นที่เข้าสู่ระบบไว้จะออกจากระบบ

อีเมลทั้งหมดส่งผ่านบัญชีอีเมลยืนยันของแพลตฟอร์ม (**คอนโซลระบบกลาง → จัดการองค์กร → อีเมลยืนยันการสมัครองค์กร**) ถ้ายังไม่ได้ตั้งค่า ลูกค้ายังสมัครได้และเข้าใช้ได้ทันที แต่บัญชีจะถูกบันทึกว่า “ยังไม่ยืนยันอีเมล” จึงไม่รวมเรื่องเดิมที่เคยส่งด้วยอีเมลนั้น ไม่มีอีเมลแจ้งเตือนหรือลิงก์ลืมรหัสผ่าน และสมัครซ้ำด้วยอีเมลเดิมไม่ได้ หน้าตั้งค่าองค์กรจะเตือนเรื่องนี้ เมื่อตั้งค่าอีเมลแล้ว การสมัครใหม่จะกลับไปต้องยืนยันอีเมลก่อนใช้งานอัตโนมัติ และบัญชีเดิมที่ตั้งรหัสผ่านใหม่ผ่านลิงก์อีเมลจะถือว่ายืนยันแล้ว บัญชีลูกค้าเดียวใช้ได้ทุกองค์กร แต่แชทและเคสของแต่ละองค์กรเก็บแยกในฐานข้อมูลขององค์กรนั้น

เมื่อสมัครและยืนยันอีเมลเดียวกับที่เคยกรอกตอนส่งเรื่องก่อนมีบัญชี เรื่องเดิมจะแสดงในแชทของฉัน การรวมรายชื่อลูกค้าซ้ำโดยทีมจะย้ายสิทธิ์ของบัญชีตามไปด้วย และลบรายชื่อที่เป็นบัญชีลูกค้าไม่ได้ รุ่นนี้ยังไม่มี Social Login (Google / LINE / Facebook)

### แชทบนเว็บไซต์โดยไม่ต้องเข้าสู่ระบบ (ผู้เยี่ยมชม)

ลูกค้าเริ่มแชทกับองค์กรได้ทันทีที่ `/chat/<รหัสองค์กร>` โดยไม่ต้องสมัคร เปิด/ปิดได้ที่ **ตั้งค่าองค์กร → แชทบนเว็บไซต์** (ผู้ดูแลองค์กร ค่าเริ่มต้นเปิด) เมื่อปิด API ของผู้เยี่ยมชมตอบ 403 และให้เริ่มแชทได้เฉพาะสมาชิกที่เข้าสู่ระบบ

- **ติดตามแชทต่อได้ 4 ทาง:** (1) **จำในเบราว์เซอร์นี้** คุกกี้ `g_<รหัสองค์กร>` แบบ HttpOnly อายุ 400 วัน ต่ออายุเองเมื่อใช้งาน ปิดได้สำหรับเครื่องสาธารณะ (ลืมเมื่อปิดเบราว์เซอร์) หรือกด **ลืมแชทในเบราว์เซอร์นี้** (2) **ลิงก์ทางอีเมล** และ (3) **ลิงก์ทาง SMS** รูปแบบ `/chat/<org>/resume#t=<token>` (โทเคนอยู่หลัง `#` จึงไม่ถูกส่งหรือบันทึกในเซิร์ฟเวอร์) ใช้ได้ 30 วัน สูงสุด 20 ครั้ง ลิงก์ใหม่ทางเดียวกันยกเลิกลิงก์เก่า เปิดลิงก์แล้วถือว่ายืนยันอีเมล/เบอร์นั้น ขอลิงก์ได้ 3 ครั้งต่อชั่วโมงต่อผู้เยี่ยมชมและต่อปลายทาง และ 10 ครั้งต่อชั่วโมงต่อ IP (4) **แจ้งเตือนทาง LINE** เมื่อองค์กรเชื่อม LINE OA ส่งรหัส 6 หลักในแชท 1:1 เหมือนบัญชีลูกค้า
- **SMS:** ยังไม่มีผู้ให้บริการจริง ผู้ดูแลแพลตฟอร์มเลือกที่ **คอนโซลระบบกลาง → ระบบ** (`/api/platform/sms`): `off` (ค่าเริ่มต้น ซ่อนตัวเลือก SMS) หรือ `log` (ทดสอบ: เขียนข้อความพร้อมลิงก์ลง log ของเซิร์ฟเวอร์ ห้ามใช้กับลูกค้าจริง) ผู้ให้บริการใหม่เพิ่มใน `backend/extensions/sms.py` เบอร์ไทยแปลงเป็น `+66…`
- **แจ้งเมื่อทีมตอบ:** ถ้ายังไม่อ่านภายใน 2 นาที ส่งหนึ่งครั้งต่อแชทต่อช่วงที่ยังไม่ได้อ่าน เฉพาะช่องทางที่ยืนยันแล้ว (อีเมล/เบอร์ที่เปิดลิงก์แล้ว, LINE ที่เชื่อมแล้ว) พร้อมลิงก์ใหม่ ไม่มีเนื้อหาข้อความ ส่งโดย worker ระบบอัตโนมัติ
- **ย้ายเข้าบัญชี:** เมื่อเข้าสู่ระบบในเบราว์เซอร์ที่เคยแชทไว้ หน้าลูกค้าเสนอ **ย้ายเข้าบัญชีนี้** (`/api/customer/guest-claims` ต้องกดยืนยันเอง เพื่อไม่ให้เครื่องที่ใช้ร่วมกันส่งแชทให้คนถัดไป) ส่วนแชทที่ยืนยันอีเมลเดียวกับบัญชีที่ยืนยันแล้วจะย้ายให้อัตโนมัติเมื่อยืนยันอีเมลหรือเข้าสู่ระบบ คุกกี้และลิงก์เดิมใช้ไม่ได้หลังย้าย
- **กันสแปม:** ช่องซ่อน (honeypot) ต้องว่าง และต้องเปิดฟอร์มไว้อย่างน้อย 2 วินาที แชทใหม่ได้ 5 เรื่องต่อชั่วโมงต่อ IP และ 10 เรื่องต่อวันต่อผู้เยี่ยมชม ทุกคำขอที่เปลี่ยนข้อมูลต้องมี `X-Guest-CSRF`
- **ฝั่งทีมงาน:** ผู้เยี่ยมชมเป็นรายชื่อลูกค้าที่สร้างโดย `guest` บทสนทนาและรายชื่อมี `guest: {follow: [...]}` (browser / email / sms / line) ให้หน้ากล่องข้อความแสดงป้าย **ผู้เยี่ยมชม** การรวมรายชื่อซ้ำยังใช้ได้ ผู้เยี่ยมชมเห็นเฉพาะแชทที่ตนเริ่มเอง อุปกรณ์ที่ไม่ได้ใช้ 400 วันและลิงก์/รหัสที่หมดอายุถูกลบอัตโนมัติ

**ปุ่มแชทบนเว็บไซต์ขององค์กร (widget):** เปิด **ปุ่มแชทบนเว็บไซต์** ใส่เว็บไซต์ที่อนุญาตสูงสุด 10 รายการ (`https://โดเมน[:พอร์ต]` หรือ `http://localhost…` สำหรับทดสอบ) เลือกตำแหน่ง (ขวา/ซ้าย) สี และหัวข้อ แล้ววางโค้ดนี้ก่อนปิด `</body>` ของเว็บไซต์:

```html
<script src="https://<โดเมนของระบบ>/widget.js" data-org="<รหัสองค์กร>" async></script>
```

หน้าแชทใน iframe (`/chat/<org>/embed`) ยอมให้ฝังได้เฉพาะเว็บไซต์ที่อนุญาต คุกกี้ในกรอบบนเว็บไซต์อื่นต้องใช้ HTTPS (`--secure-cookies`) จึงจะจำแชทได้ ค่าที่สคริปต์อ่านอยู่ที่ `GET /api/public/<org>/widget`

รหัสผ่านเก็บแบบ PBKDF2-SHA256 จำกัดการสมัครและขอลิงก์ 5 ครั้ง เข้าสู่ระบบ 15 ครั้ง และเปลี่ยนรหัสผ่าน 10 ครั้ง ต่อ IP ใน 15 นาทีต่อองค์กร

## ระบบอัตโนมัติและมุมมองผู้ดูแล

เจ้าขององค์กรตั้งค่าได้ที่เมนู **ระบบอัตโนมัติ** (`/#automation`) ผลทั้งหมดแสดงในหน้า **ภาพรวม**

- **กฎรับเรื่องและส่งต่อ (Trigger & Routing):** เลือกช่องทาง (Web, LINE, Email, Facebook, เคสที่บันทึกเอง หรือทุกช่องทาง) และคำค้นในหัวเรื่องหรือข้อความ แล้วกำหนดความเร่งด่วน ทีม และผู้รับผิดชอบ เช่น ถ้ามาจาก Facebook และมีคำว่า “ระบบล่ม” ให้ความเร่งด่วนสูงและส่งให้ทีมเทคนิค เมื่อข้อความแรกของเรื่องใหม่ตรงกฎ ระบบเปิดเคสให้ทันที กฎยังทำงานกับเคสที่เปิดด้วยวิธีอื่นด้วย กฎทำงานตามลำดับที่สร้าง ผู้รับผิดชอบที่ไม่อยู่ในทีมสุดท้ายของเคสจะไม่ถูกมอบหมาย
- **ยกระดับ SLA อัตโนมัติ:** ระบบตรวจทุก 30 วินาที เคสที่ยังไม่มีผู้รับผิดชอบและยังไม่ได้ตอบเกินจำนวนนาทีที่ตั้ง (เริ่มต้น 15 นาที) จะย้ายให้เจ้าขององค์กร (เลือกคนที่ว่างรับงาน อยู่ทีมเดียวกับเคส และถืองานน้อยที่สุดก่อน) เคสที่มีผู้รับผิดชอบแต่ใกล้ครบเวลาตอบกลับครั้งแรกจะแจ้งเจ้าขององค์กรโดยไม่ย้าย แต่ละเคสยกระดับครั้งเดียว บันทึกในประวัติเคส และแจ้งในหน้าภาพรวมกับกระดิ่ง
- **Macro:** ปุ่มเดียวทำหลายขั้น เช่น **ขอข้อมูลเพิ่มเติม** ส่งข้อความแม่แบบ เปลี่ยนสถานะเป็นรอลูกค้า และตั้งเตือนติดตามใน 24 ชั่วโมง ข้อความแทนค่า `{customer}` `{case}` `{agent}` ได้ ใช้ได้จากหน้าเคสและปุ่ม **Macro** ในช่องพิมพ์ ข้อความส่งผ่านช่องทางเดิมของลูกค้าเหมือนเจ้าหน้าที่พิมพ์เอง เคสที่บันทึกเองจะข้ามขั้นส่งข้อความ ตั้งเตือนติดตามเองได้จากหน้าเคส แล้วกด **เสร็จแล้ว** เมื่อติดตามเรียบร้อย
- **แบบประเมินความพึงพอใจ (CSAT):** เมื่อเปลี่ยนเคสเป็นแก้ไขแล้วหรือปิดเคส ระบบส่งคำถามในบทสนทนาของเคส แชทบนหน้าลูกค้าแสดงปุ่มดาว 1-5 ส่วน LINE / Email / Facebook ให้ลูกค้าตอบเป็นตัวเลข 1-5 ภายใน 7 วัน คำตอบคะแนนไม่เปิดเคสกลับ แบบประเมินเป็นข้อความระบบ จึงไม่นับเป็นการตอบครั้งแรกใน SLA ปิดการส่งหรือแก้ข้อความได้ที่หน้าระบบอัตโนมัติ
- **บันทึกภายในและ @แท็ก:** ในบันทึกภายในพิมพ์ `@ชื่อสมาชิก` หรือกดปุ่ม **แท็กทีม** (`@ทีม` แท็กทุกคนในทีมของบทสนทนา) ผู้ถูกแท็กที่มีสิทธิ์เห็นบทสนทนาจะเห็นในการ์ด **ถึงคุณ** และกระดิ่ง ลูกค้าไม่เห็นบันทึกภายใน ปุ่ม **เฉพาะบันทึกภายใน** เหนือบทสนทนาแสดงเฉพาะการคุยกันในทีม การแจ้งเตือนแสดงในโปรแกรมเท่านั้น ไม่ส่งอีเมลหรือ LINE
- **ค้นคลังความรู้จากช่องพิมพ์:** ปุ่ม **ค้นคู่มือ** ค้นบทความ กด **ส่งลิงก์ให้ลูกค้า** เพื่อส่งลิงก์บทความที่เผยแพร่แล้วในบทสนทนาทันที ลูกค้าเปิดอ่านได้โดยไม่ต้องเข้าสู่ระบบ หรือกด **แทรกเนื้อหา** เพื่อแก้ไขก่อนส่ง
- **กล่องข้อความรวมทุกช่องทาง:** แชทบนเว็บ, LINE, Email และ Facebook Messenger อยู่ในกล่องเดียว กรองตามช่องทางได้ และตอบจากที่เดียว วิธีเชื่อม Facebook ดูใน [คู่มือช่องทาง](CHANNELS.md#facebook-messenger)
- **มุมมองผู้ดูแล (หน้าภาพรวม เฉพาะเจ้าขององค์กร):** สถานะเจ้าหน้าที่ (กำลังใช้งาน = เปิดโปรแกรมภายใน 5 นาทีล่าสุด) เคสที่ถืออยู่ ปิดวันนี้ ตอบวันนี้ เวลาตอบครั้งแรกเฉลี่ย และ CSAT 30 วัน, คะแนน CSAT รวม, สรุประบบอัตโนมัติ และแผนภาพช่วงเวลาที่เรื่องเข้ามามากที่สุดของสัปดาห์ (เฉลี่ยจาก 8 สัปดาห์ ตามเวลาของเครื่องผู้ดู) พร้อมช่วงพีคและคำแนะนำจัดกะ ส่วนนี้อัปเดตเองทุก 30 วินาที

ข้อจำกัด: กฎใช้เงื่อนไขช่องทางและคำค้นเท่านั้น ยังไม่มีเงื่อนไขซ้อนหรือเวลาทำการ การค้นคำเป็นการหาข้อความตรงตัวโดยไม่สนตัวพิมพ์เล็ก-ใหญ่ การยกระดับนับเวลาต่อเนื่อง 24 ชั่วโมงเหมือน SLA “กำลังใช้งาน” มาจากการเรียกใช้โปรแกรม ไม่ใช่สถานะที่เจ้าหน้าที่ตั้งเอง คำแนะนำจัดกะคำนวณจากจำนวนเรื่องที่เข้ามาเท่านั้น ไม่รวมความยากหรือเวลาที่ใช้ต่อเรื่อง

ไฟล์แนบรองรับ PNG, JPG, GIF, WebP, MP4, WebM, PDF และ TXT สูงสุด 3 ไฟล์ต่อข้อความ รวมไม่เกิน 5 MB ภาพแสดงในบทสนทนาและกดขยายได้ วิดีโอมีปุ่มเล่นในข้อความโดยไม่เล่นอัตโนมัติ ไฟล์ในบันทึกภายในเปิดได้เฉพาะเจ้าหน้าที่ที่มีสิทธิ์ในบทสนทนานั้น

คลังความรู้เลือกได้ระหว่าง **ภายในองค์กร** และ **เผยแพร่ให้ลูกค้า** บทความสาธารณะจะแสดงในเมนู **คำถามที่พบบ่อย** ของหน้าลูกค้า

## บทบาทหลักของระบบ

| บทบาท | ใครใช้ | หน้าที่เห็น |
| --- | --- | --- |
| **เจ้าของแพลตฟอร์ม** | บัญชีที่สร้างตอนติดตั้งครั้งแรก | ทุกอย่างของผู้ดูแลแพลตฟอร์ม และเป็นคนเดียวที่เพิ่มหรือถอดผู้ดูแลแพลตฟอร์มได้ |
| **ผู้ดูแลแพลตฟอร์ม (Super Admin)** | ทีม Bookdose ที่ดูแลเซิร์ฟเวอร์ | **คอนโซลระบบกลาง**: ภาพรวมระบบ, จัดการองค์กร, FAQ กลาง, ตั้งค่าระบบ, ดูทีมผู้ดูแลระบบ |
| **เจ้าขององค์กร และเจ้าหน้าที่** | องค์กรที่ใช้ Bookdose ดูแลลูกค้าของตัวเอง รวมถึงทีมติดต่อลูกค้าของ Bookdose เอง | พื้นที่ทำงานองค์กร: ภาพรวม กล่องข้อความ เคส ลูกค้า คลังความรู้ (FAQ ขององค์กร) รายงาน ระบบอัตโนมัติ ช่องทาง LINE / Facebook / Email ลิงก์และ QR สำหรับลูกค้า ตั้งค่าทีมและเจ้าหน้าที่ และ **คู่มือจาก Bookdose** |
| **ลูกค้าปลายทาง** | ลูกค้าขององค์กร ทั้งที่เข้าสู่ระบบและไม่เข้าสู่ระบบ (แชทบนเว็บ LINE Facebook อีเมล) | หน้าลูกค้า: ภาพรวม แชทของฉัน เคสของฉัน คำถามที่พบบ่อย การแจ้งเตือน ตั้งค่าบัญชี (ดู [บัญชีลูกค้าและหน้าลูกค้า](#บัญชีลูกค้าและหน้าลูกค้า)) |

Bookdose มีสองบทบาทแยกกัน: **ทีมจัดการระบบ** (ผู้ดูแลแพลตฟอร์ม) คือบัญชีในหน้า **ทีมผู้ดูแลระบบ** ของคอนโซล ดูแลระบบอย่างเดียว ไม่รับเคสและไม่ตอบลูกค้า เข้าสู่ระบบแล้วไปที่ `/platform/system` เสมอ ส่วน **ทีมติดต่อลูกค้า Bookdose** คือสมาชิกขององค์กร Bookdose (เจ้าขององค์กร เจ้าหน้าที่) เจ้าขององค์กรคนแรกเชิญจากคอนโซล → จัดการองค์กร → **เชิญผู้ดูแล** แล้วจัดการทีมต่อที่ ตั้งค่าองค์กร → ทีมและสมาชิก บัญชีเดียวเป็นทั้งสองอย่างไม่ได้ (ระบบไม่ให้เชิญบัญชีผู้ดูแลแพลตฟอร์มเข้าองค์กร และไม่ให้ตั้งทีมงานขององค์กรเป็นผู้ดูแลแพลตฟอร์ม) ผู้ดูแลแพลตฟอร์มดูข้อมูลขององค์กรได้เฉพาะเมื่อองค์กรอนุมัติสิทธิ์เข้าช่วยเหลือ และดูได้อย่างเดียว

### คอนโซลระบบกลาง

- **ภาพรวมระบบ:** Server Health (เวลาทำงาน เวอร์ชัน Python ขนาดฐานข้อมูลและไฟล์แนบ พื้นที่ดิสก์ เตือนเมื่อเหลือน้อยกว่า 10%), งานเบื้องหลัง (AI, ส่งข้อความ, รับอีเมล, ระบบอัตโนมัติ) พร้อมคิวที่รอในทุกองค์กร, API Usage รายชั่วโมง 24 ชั่วโมงล่าสุด แยกตามส่วนของระบบและองค์กรที่ใช้มากที่สุด, และ Logs (ข้อผิดพลาดล่าสุด กับเหตุการณ์ของแพลตฟอร์ม) หน้าอัปเดตเองทุก 30 วินาที ตัวเลขการใช้งานและข้อผิดพลาดเก็บในหน่วยความจำ จึงเริ่มนับใหม่เมื่อเปิดโปรแกรมใหม่ และบันทึกเส้นทาง API เฉพาะคำขอที่ผิดพลาด โดยไม่เก็บ query string
- **จัดการองค์กร:** สร้างองค์กร ดูและเชิญผู้ดูแลองค์กร (ทางอีเมล หรือสร้างบัญชีพร้อมรหัสผ่านเริ่มต้นเมื่อยังไม่มีอีเมลกลาง) เตือนเมื่อองค์กรยังไม่มีผู้ดูแล ขอสิทธิ์เข้าช่วยเหลือ (อ่านอย่างเดียว) ระงับ/เปิดใช้งาน คัดลอกลิงก์หน้าลูกค้า และตั้งค่าอีเมลยืนยันการสมัครองค์กร
- **FAQ กลาง:** เขียนบทความครั้งเดียวแล้วเลือกผู้อ่าน: **เฉพาะผู้ดูแลระบบกลาง** (อ่านได้ในคอนโซลนี้), **แอดมินและทีมงานองค์กร** (แสดงในเมนู **คู่มือจาก Bookdose** ของทุกองค์กร) หรือ **ลูกค้าปลายทาง** (แสดงต่อจากบทความสาธารณะขององค์กรในคำถามที่พบบ่อยของลูกค้าทุกองค์กร) มีผลทันทีกับทุกองค์กร รวมถึงองค์กรที่สร้างภายหลัง ระบบใส่บทความเริ่มต้นให้ครั้งเดียว (ตั้งค่าเซิร์ฟเวอร์, แก้ปัญหาระบบล่ม, เงื่อนไข License/SLA ซึ่งเป็นแม่แบบที่ต้องใส่เงื่อนไขจริงเอง, การกระจายเคส, เชื่อมช่องทาง, อ่านรายงาน, สมัครสมาชิก, เปลี่ยนรหัสผ่าน, ส่งเรื่องและติดตามสถานะ) แก้หรือลบได้ตามต้องการ และจะไม่ถูกเพิ่มกลับหลังลบ
- **ทีมผู้ดูแลระบบ:** ผู้ดูแลทุกคนเห็นรายชื่อ แต่เฉพาะ **เจ้าของแพลตฟอร์ม** (บัญชีที่สร้างตอนติดตั้งครั้งแรก เก็บใน platform setting `platform_owner`) เพิ่มสิทธิ์ให้บัญชีที่มีอยู่ สร้างบัญชีใหม่ด้วยชื่อและรหัสผ่านเริ่มต้น หรือถอดสิทธิ์ได้ เจ้าของถูกถอดไม่ได้ ระบบจึงมีผู้ดูแลอย่างน้อยหนึ่งคนเสมอ ระบบที่ติดตั้งก่อนมีเจ้าของจะตั้งผู้ดูแลที่สร้างก่อนสุดเป็นเจ้าของตอนเปิดเซิร์ฟเวอร์ สิทธิ์มีผลตั้งแต่คำขอถัดไป และบันทึกในประวัติแพลตฟอร์ม

## หลายองค์กรและสิทธิ์

| บทบาท | สิทธิ์ |
| --- | --- |
| เจ้าของแพลตฟอร์ม | ทุกอย่างของผู้ดูแลแพลตฟอร์ม และเพิ่ม/ถอดผู้ดูแลแพลตฟอร์ม |
| ผู้ดูแลแพลตฟอร์ม | ใช้คอนโซลระบบกลาง: ดูสถานะระบบ สร้างองค์กร เชิญเจ้าขององค์กร เขียน FAQ กลาง และดูประวัติแพลตฟอร์ม ไม่รับเคส ไม่ตอบลูกค้า ดูข้อมูลองค์กรได้เฉพาะเมื่อองค์กรอนุมัติสิทธิ์เข้าช่วยเหลือ และดูได้อย่างเดียว |
| เจ้าขององค์กร (`role=admin`) | จัดการงานทุกทีม สมาชิก การตั้งค่า บทความ ประวัติ และสำรองข้อมูลองค์กร องค์กรหนึ่งมีเจ้าของได้หลายคน แต่ต้องเหลืออย่างน้อย 1 คนเสมอ (ลดบทบาทหรือปิดบัญชีเจ้าของคนสุดท้ายไม่ได้) |
| เจ้าหน้าที่ | ดูเคส บทสนทนา ไฟล์ และรายงานเฉพาะทีม ดูลูกค้าที่ตนสร้างหรือเกี่ยวข้องกับงานของทีม อ่านคลังความรู้ขององค์กร |
| ลูกค้า (หน้าลูกค้า) | เข้าสู่ระบบด้วยบัญชีลูกค้าขององค์กรนั้น อ่านและตอบเฉพาะแชทของบัญชีตนเอง ดูสถานะและกำหนดเวลาของเคสตนเอง อ่านบทความสาธารณะ ไม่เห็นบันทึกภายใน ความเร่งด่วน หรือผู้รับผิดชอบ |

ผู้ดูแลแพลตฟอร์มสร้างองค์กรใหม่และระบุอีเมลผู้ดูแลองค์กรได้ หากอีเมลมีบัญชีอยู่แล้ว จะเพิ่มบัญชีเดิมเป็นผู้ดูแลในองค์กรใหม่ โดยไม่เปลี่ยนรหัสผ่าน บัญชีหนึ่งจึงสลับได้หลายองค์กรผ่านเมนูซ้ายบน สมาชิกทั่วไปที่เพิ่มจากหน้าตั้งค่าต้องใช้อีเมลบัญชีใหม่ในรุ่นนี้

บทบาท **หัวหน้าทีม** (`manager`) ถูกยกเลิกแล้ว เมื่อเปิดเซิร์ฟเวอร์ หัวหน้าทีมเดิมจะกลายเป็นเจ้าหน้าที่ (สิทธิ์เข้าช่วยเหลือแบบหัวหน้าทีมกลายเป็นแบบเจ้าของ ซึ่งยังดูได้อย่างเดียว) ถ้าต้องการให้ใครจัดการได้ ให้เจ้าขององค์กรตั้งเป็นเจ้าของอีกคน

การเปลี่ยนสถานะสมาชิกหรือระงับองค์กรมีผลในการเรียก API ครั้งถัดไป หน้าจอไม่มีปุ่มระงับองค์กรแล้ว การระงับยังทำได้ผ่าน API `PATCH /api/platform/tenants/<id>` ของผู้ดูแลระบบกลาง และต้องส่ง CONFIRM หรือชื่อองค์กร ข้อมูลที่แสดงหรือดาวน์โหลดไปก่อนหน้านั้นไม่สามารถเรียกคืนได้ การเปลี่ยนรหัสผ่านจากเมนูบัญชีจะออกจากเซสชันอื่นทั้งหมด เมนูบัญชียังใช้เปลี่ยนชื่อและอัปโหลด/ลบรูปโปรไฟล์ของตนเองได้

## การเก็บข้อมูล

```text
data/
  control.sqlite3             บัญชี เซสชัน องค์กร และสมาชิก
  tenants/<tenant-id>.sqlite3  ฐานข้อมูลงานบริการแยกไฟล์รายองค์กร
  files/<tenant-id>/<file-id>  ไฟล์แนบส่วนตัวรายองค์กร
  secrets/<tenant-id>.openai-key  API Key รายองค์กร เข้ารหัสแล้ว ไม่รวมใน Git (ไฟล์สำรองทั้งระบบมีเฉพาะแบบเข้ารหัส)
  keys/secret.key              กุญแจเข้ารหัส เมื่อไม่ได้ตั้ง BOOKDOSE_SECRET_KEY ไม่รวมในไฟล์สำรองใด ๆ
```

รุ่นนี้ใช้ **SQLite แยกฐานข้อมูลรายองค์กร** เพื่อเปิดใช้บนเครื่องได้ทันที จึงไม่ได้ใช้ PostgreSQL/RLS ตามสถาปัตยกรรมเป้าหมายในเอกสารต้นทาง ทุก API ตรวจสมาชิก สถานะองค์กร บทบาท และทีมที่ฝั่งเซิร์ฟเวอร์ ก่อนเลือกฐานข้อมูลและตรวจสิทธิ์ทรัพยากร ข้อมูลลูกค้าที่ทีมสร้างเองไม่ถูกนำประวัติมารวมกันโดยอัตโนมัติ ยกเว้นเรื่องที่ส่งผ่านหน้าลูกค้าแบบเดิมด้วยอีเมลเดียวกับบัญชีที่ยืนยันแล้ว

รหัสผ่านเก็บด้วย PBKDF2-SHA256 และ salt เฉพาะบัญชี เซสชันเจ้าหน้าที่หมดอายุใน 12 ชั่วโมง ใช้คุกกี้ HttpOnly + SameSite และ CSRF token บัญชีลูกค้าใช้คุกกี้แยก (อายุ 30 วัน ส่งเฉพาะไปที่ API ฝั่งลูกค้าขององค์กรนั้น) พร้อม CSRF token ของเซสชัน ลิงก์ยืนยันอีเมลและตั้งรหัสผ่านใหม่เก็บเฉพาะค่าแฮช

## สำรองและกู้คืน

ผู้ดูแลองค์กรดาวน์โหลดฐานข้อมูลและไฟล์แนบขององค์กรตนเองได้จาก **ตั้งค่าองค์กร → สำรองข้อมูลองค์กร** ZIP นี้เหมาะสำหรับสำรองหรือส่งออกข้อมูลเฉพาะองค์กร ไม่มีบัญชีสมาชิกจากฐานข้อมูลแพลตฟอร์ม และไม่ใช้กับคำสั่งกู้คืนทั้งระบบด้านล่าง

สำรองทั้งระบบ: หยุดโปรแกรมด้วย `Ctrl+C` เพื่อไม่ให้เกิดการเปลี่ยนแปลงระหว่างสำรองหลายฐานข้อมูล แล้วรัน:

```sh
python3 app.py --backup backups/bookdose-2026-09-07.zip
```

คำสั่งจะไม่เขียนทับไฟล์สำรองที่มีชื่ออยู่แล้ว ให้ตั้งชื่อใหม่ในแต่ละครั้ง ไฟล์สำรองเก็บฐานข้อมูล ไฟล์แนบที่อ้างอิงจาก snapshot และค่าลับใน `data/secrets` (token ของ LINE, Facebook, อีเมล, OpenAI, SMS และรหัสผ่านอีเมลกลาง) **ในรูปที่เข้ารหัสแล้วเท่านั้น**

**กุญแจเข้ารหัสไม่อยู่ในไฟล์สำรอง** (คำสั่งพิมพ์รหัสกุญแจที่ใช้ไว้ให้ตอนสำรอง) เก็บกุญแจแยกจากไฟล์สำรอง เช่น ในตัวจัดการรหัสผ่าน: ค่า `BOOKDOSE_SECRET_KEY` ถ้าตั้งไว้ หรือไฟล์ `data/keys/secret.key` ถ้าไม่ได้ตั้ง ถ้าเก็บกุญแจไว้คู่กับไฟล์สำรอง ใครได้ไฟล์สำรองไปก็เปิด token ทั้งหมดได้

กู้คืนทั้งระบบไปยังโฟลเดอร์ใหม่ที่ยังไม่มีข้อมูล:

```sh
# ใช้กุญแจเดิม: ตั้ง BOOKDOSE_SECRET_KEY เดิม หรือวางไฟล์กุญแจเดิมก่อน
mkdir -p restored-data/keys && cp <ที่เก็บกุญแจ>/secret.key restored-data/keys/
BOOKDOSE_DATA=./restored-data python3 app.py --restore backups/bookdose-2026-09-07.zip
BOOKDOSE_DATA=./restored-data python3 app.py
```

ถ้าเครื่องนี้ไม่มีกุญแจที่เปิดค่าลับในไฟล์สำรองได้ การกู้คืนจะหยุดก่อนเขียนอะไรลงดิสก์ และบอกรหัสกุญแจที่ต้องใช้ ถ้ากุญแจหายจริง ใช้ `--restore <ไฟล์> --new-key` เพื่อกู้ข้อมูลทั้งหมดยกเว้นค่าลับ แล้วกรอก token ของทุกช่องทาง อีเมลกลาง และ SMS ใหม่ บัญชีที่เปิด 2FA ด้วยแอปต้องใช้รหัสสำรอง หรือรีเซ็ต (เจ้าหน้าที่: `python -m backend.modules.staff_security reset <อีเมล>`)

บน Windows ใช้ `set BOOKDOSE_DATA=restored-data` ก่อนรันคำสั่ง Python ไม่มีการเขียนทับฐานข้อมูลเดิมระหว่างกู้คืน เจ้าหน้าที่ทุกบัญชีต้องล็อกอินใหม่หลังการกู้คืน เก็บ ZIP ในพื้นที่ที่จำกัดผู้เข้าถึง เพราะมีข้อมูลลูกค้าและบันทึกภายใน ไฟล์สำรองไม่ได้เข้ารหัส

## ขอบเขตของรุ่นนี้

พร้อมใช้เป็นระบบหลักบนเครื่อง: การเข้าใช้และสิทธิ์หลายองค์กร, แชทบนเว็บและหน้าลูกค้า, Inbox, เคส, มอบหมายทีมและเจ้าหน้าที่, ไฟล์แนบ, รายชื่อลูกค้า, SLA, คำตอบสำเร็จรูป, คลังความรู้, รายงาน CSV, Audit, สำรองและกู้คืนทั้งระบบ, กฎรับเรื่องอัตโนมัติ, ยกระดับ SLA, Macro และเตือนติดตามผล, CSAT, @แท็กในบันทึกภายใน, มุมมองผู้ดูแล รวมถึง LINE OA และกลุ่ม LINE, IMAP/SMTP Email พร้อม OAuth และคิวส่ง, Facebook Messenger, AI ช่วยร่างคำตอบกับ Chatbot ในแชทบนเว็บ/LINE/Email เมื่อตั้งค่าบัญชีบริการแล้ว

SLA ใช้เวลาต่อเนื่อง 24 ชั่วโมง ไม่ใช้ปฏิทินวันทำการ วันหยุด หรือหยุดนับระหว่างรอลูกค้า การตั้งค่า SLA ใหม่มีผลเฉพาะเคสที่สร้างใหม่ การเปิดเคสเดิมอีกครั้งใช้กำหนดเวลาเดิม การแจ้งเตือนในรุ่นนี้แสดงผ่านเคสเกิน SLA การยกระดับอัตโนมัติ และหน้าภาพรวม

**ยังไม่รวม:** SSO, การส่งแจ้งเตือนภายนอก, สแกนไวรัสไฟล์แนบ, กฎ workflow แบบเงื่อนไขซ้อนหรือตามเวลาทำการ, Chatbot บน Facebook Messenger, แพ็กเกจและโควตาทรัพยากรทั่วไป, support access grant แบบหมดอายุ, การลบองค์กรและ retention, การกู้คืนเฉพาะองค์กรผ่านหน้าจอ, PostgreSQL/RLS และระบบสำรองอัตโนมัติ รายการเหล่านี้ไม่ได้แสดงว่าเชื่อมต่อสำเร็จบนหน้าจอ

โปรแกรมเริ่มที่ `127.0.0.1` จึงใช้ได้เฉพาะเครื่องนี้ ลิงก์ `localhost` ที่ส่งให้ผู้อื่นจะไม่ชี้มาที่เครื่องของคุณ สำหรับออนไลน์มี [Render Blueprint และขั้นตอนเชื่อมบัญชี](docs/DEPLOY-RENDER.md) โดยต้องสร้างบริการบนบัญชี Render จึงจะได้ URL จริง `--host 0.0.0.0` ใช้เปิดรับในเครือข่ายที่ตั้งใจอนุญาตเท่านั้น ส่วน `--secure-cookies` ใช้เมื่อมี HTTPS reverse proxy แล้ว เซิร์ฟเวอร์ API (FastAPI บน uvicorn แบบ worker เดียว) ยังไม่ได้ผ่านการทดสอบรับโหลดระดับแพลตฟอร์มสาธารณะ

## เปิดใช้ AI ทั้งสองแบบ

1. หยุดโปรแกรมเดิมแล้วเปิดใหม่ เพื่ออัปเดตโครงสร้างข้อมูลอัตโนมัติ การอัปเดตเพิ่มตารางใหม่โดยไม่ลบเคสเดิม
2. เข้า **ตั้งค่าองค์กร → AI Assistant & Chatbot** ด้วยบัญชีผู้ดูแลองค์กร
3. ใส่ **OpenAI API Key** ขององค์กร กำหนดโมเดล และเพดานคำขอต่อวัน ค่าเริ่มต้นคือ `gpt-4.1-mini`, 100 คำขอต่อวัน UTC, Chatbot สูงสุด 20 คำขอต่อบทสนทนา และ output สูงสุด 1,000 tokens ต่อคำขอ เปลี่ยนโมเดลได้ โดยต้องรองรับ Responses API และ Structured Outputs
   - **หรือ** เชื่อม **n8n Webhook** แทน แล้วให้ AI Agent ใน n8n ตอบ (เลือกโมเดลใน n8n เอง)
   - ใช้ workflow สำเร็จรูปใน [integrations/n8n](integrations/n8n/README.md)
   - เมื่อมี Webhook ระบบจะใช้ n8n แทน OpenAI
4. เลือกเปิด **AI ช่วยร่างคำตอบให้เจ้าหน้าที่** และ/หรือ **Chatbot ตอบลูกค้าในแชทบนเว็บ** แล้วบันทึก
5. กด **ทดสอบการเชื่อมต่อ** เพื่อส่งข้อความทดสอบที่ไม่มีข้อมูลลูกค้าไปยังบริการจริง การทดสอบนี้ใช้โควตาและอาจมีค่าใช้บริการ API
6. เพิ่มบทความที่ถูกต้องในคลังความรู้ สำหรับ Chatbot ต้องเลือก **เผยแพร่ให้ลูกค้า** ถ้าใช้ข้อมูลตัวอย่าง บทความตัวอย่างเป็นบทความภายในทั้งหมด จึงยังไม่ใช่แหล่งตอบอัตโนมัติ

**AI ช่วยเจ้าหน้าที่:** เปิดบทสนทนาหรือเคสแล้วกด **AI ช่วยร่างคำตอบ** ระบบแสดงสรุป ร่างคำตอบ และข้อความอ้างอิงจากบทความ เจ้าหน้าที่ตรวจเนื้อหาแล้วกด **นำร่างใส่ช่องข้อความ** จากนั้นกดส่งเอง ร่างและสรุปไม่ถูกส่งให้ลูกค้าอัตโนมัติ การขอร่างจะให้เจ้าหน้าที่รับช่วงบทสนทนานั้น และหากมีข้อความ/ความรู้/สิทธิ์/การตั้งค่าเปลี่ยนระหว่างร่าง ระบบจะยกเลิกผลเก่าให้ร่างใหม่

**Chatbot:** เริ่มทำงานในบทสนทนาเว็บใหม่หลังเปิดใช้ ตอบด้วยชื่อ **Bookdose AI · AI Chatbot** พร้อมแหล่งอ้างอิง ใช้เฉพาะบทความสาธารณะขององค์กรนั้น ไม่อ่านบันทึกภายใน ข้อมูลผู้ติดต่อ หรือประวัติองค์กรอื่น ลูกค้ากด **คุยกับเจ้าหน้าที่** ได้เสมอ การขอคน การส่งไฟล์แนบ ความรู้ไม่พอ คำตอบตรวจอ้างอิงไม่ได้ บริการล้มเหลว หรือเกินเพดาน จะหยุด AI และเปิด/เชื่อมเคสให้ทีมงาน

เจ้าหน้าที่กด **รับช่วงดูแล** หรือส่งคำตอบเอง จะหยุด Chatbot ของบทสนทนานั้นทันที ผล AI ที่กำลังประมวลผลจะไม่ส่งแทรกภายหลัง หากต้องการให้ AI ดูแลต่อ ให้กด **ให้ AI ดูแลข้อความถัดไป** ซึ่งเริ่มกับข้อความใหม่จากลูกค้า ไม่ตอบข้อความเก่าซ้ำ การเปิดหรือปิด Chatbot จากหน้าตั้งค่าไม่เปิด AI ให้บทสนทนาเก่าโดยอัตโนมัติ

**ขอบเขตข้อมูลและการประมวลผล:** ส่งหัวเรื่องและข้อความล่าสุดสูงสุด 14 ข้อความ (ตัดข้อความยาวที่ 2,500 ตัวอักษร) กับส่วนบทความที่เกี่ยวข้องสูงสุด 5 ส่วนไปยัง OpenAI ไม่มีการส่งไฟล์แนบหรือรายการข้อมูลลูกค้า แต่ข้อความที่ผู้ใช้พิมพ์อาจมีข้อมูลส่วนบุคคลอยู่ด้วย ร่างสำหรับเจ้าหน้าที่อาจมีบันทึกภายในและใช้บทความภายใน จึงต้องตรวจทานก่อนส่งลูกค้า ไม่มีเครื่องมือให้โมเดลแก้บัญชีหรือเรียก API ธุรกิจ

การค้นความรู้ใช้คำภาษาอังกฤษและกลุ่มอักขระภาษาไทยภายในฐานข้อมูลขององค์กร ไม่ใช้ vector database ภายนอก ตรวจว่ารหัสบทความและข้อความอ้างอิงมาจากข้อมูลที่คัดให้โมเดลจริง พร้อมตรวจสิทธิ์ซ้ำก่อนเผยแพร่ อย่างไรก็ตาม การอ้างอิงถูกต้องไม่ได้รับประกันว่าคำตอบทุกประโยคถูกต้อง ควรทดลองกับคำถามจริงและปรับคลังความรู้ก่อนเปิดตอบอัตโนมัติให้ลูกค้าจำนวนมาก

**การทำงานเบื้องหลังและค่าใช้บริการ:** คิว AI อยู่ในฐานข้อมูลองค์กร บันทึกพร้อมข้อความรับเข้า Worker เริ่มพร้อมโปรแกรม มี provider call ที่ทำงานอยู่ได้หนึ่งงานต่อองค์กร และประมวลผลแต่ละองค์กรตามรอบ หน้ารับเรื่องไม่รอ AI ก่อนบันทึกข้อมูล จำกัดเวลาติดต่อบริการ 25 วินาที งานที่ค้างจากการปิดโปรแกรมเกิน 120 วินาทีจะส่งต่อเจ้าหน้าที่โดยไม่เรียกโมเดลซ้ำอัตโนมัติ ระบบไม่นับ AI และข้อความส่งต่อเป็นการตอบครั้งแรกของเจ้าหน้าที่ใน SLA เพดานคำขอนับงานที่รับเข้าคิว รวมงานทดสอบ งานล้มเหลว และงานยกเลิก ไม่ใช่การจำกัดวงเงินเป็นบาท จำนวน tokens เป็นค่าที่บริการส่งกลับและอาจไม่ครบหากเครือข่ายขาดก่อนรับผล

**API Key:** บันทึกในไฟล์ส่วนตัว `data/secrets/` โดยตั้งสิทธิ์ไฟล์เป็น `0600` บนระบบที่รองรับ ไม่บันทึกในฐานข้อมูล ไม่ส่งคีย์กลับไปหน้าเว็บ ไม่ใส่ใน prompt/log เข้ารหัสบนดิสก์ด้วยกุญแจของแพลตฟอร์ม ZIP สำรองขององค์กรไม่มีคีย์ ส่วน ZIP สำรองทั้งระบบมีเฉพาะแบบเข้ารหัส กู้คืนพร้อมกุญแจเดิมแล้วใช้ต่อได้ทันที บน Windows ให้จำกัดสิทธิ์โฟลเดอร์ข้อมูลด้วยสิทธิ์บัญชีระบบปฏิบัติการ บัญชีแต่ละองค์กรใช้คีย์แยกกัน

เชื่อมด้วย [OpenAI Responses API](https://developers.openai.com/api/docs/guides/text) โดยกำหนด `store: false` และใช้ [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) สำหรับรูปแบบคำตอบ อ้างอิงความสามารถโมเดลเริ่มต้นจาก [GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini) การกำหนด `store: false` ไม่ใช่การรับประกันว่าไม่มีการเก็บข้อมูลทุกประเภทโดยผู้ให้บริการ

## ทดสอบ

```sh
python3 scripts/check.py        # ตรวจ syntax Python, type และ lint ของหน้าเว็บ (frontend/) แล้วรัน tests ทั้งหมด
python3 -m unittest discover -s tests -v   # หรือรันเฉพาะ tests
```

การทดสอบใช้โฟลเดอร์ชั่วคราว ไม่แตะข้อมูลจริง ครอบคลุมระบบเดิม รวมถึงร่าง AI ที่ยังไม่ส่ง, Chatbot, ขอบเขตความรู้และคีย์รายองค์กร, ถอนสิทธิ์ระหว่างประมวลผล, ส่งต่อเจ้าหน้าที่, งานซ้ำ/ล้าสมัย, โควตา, ความล้มเหลวของบริการ และรูปแบบ HTTP สำหรับ Responses API โดยใช้ผู้ให้บริการจำลอง ไม่ใช้ API Key หรือคิดค่าบริการจริง ต้องทดสอบการเชื่อมต่อกับบัญชีจริงจากหน้าตั้งค่าอีกครั้งก่อนใช้งาน AI จริง `tests/test_automation.py` ครอบคลุมกฎรับเรื่อง การยกระดับ Macro CSAT @แท็ก มุมมองผู้ดูแล และ Facebook Messenger (จำลอง Graph API ไม่ส่งข้อความจริง)

หน้าเว็บตรวจด้วย `cd frontend && npm run typecheck && npm run lint && npm run build` การทดสอบเบราว์เซอร์ชุดเดิม (`tests/browser*.cjs`) ผูกกับหน้าจอรุ่นก่อน Next.js จึงถูกนำออกพร้อมหน้าจอเดิม ยังไม่มีชุดทดสอบเบราว์เซอร์อัตโนมัติสำหรับหน้าเว็บใหม่

## โครงสร้างซอร์สโค้ด

Backend แยกตาม feature ใน `backend/modules/<feature>/` แต่ละ feature แบ่งหน้าที่เป็นชั้น
**Route → Controller → Service → Repository → Database**

| ไฟล์ | หน้าที่ |
|---|---|
| `routes.py` | รายการ endpoint: method, URL, controller และระดับการเข้าถึง (ไม่มี logic ไม่มี query) |
| `controller.py` | รับ request เรียก service และส่ง response (status, cookie, ไฟล์ดาวน์โหลด) |
| `service.py` | กฎธุรกิจทั้งหมด เรียก repository หรือ service ของ feature อื่น |
| `repository.py` | Database query และไฟล์ข้อมูลบนดิสก์ (ไม่มีกฎธุรกิจ) |
| `model.py` | ตารางและค่าที่อนุญาตของ feature |
| `schema.py` | ตรวจข้อมูลที่ส่งเข้ามา และจัดรูปข้อมูลที่ส่งกลับ |

ไฟล์ไหนไม่มีเนื้อหาจะไม่สร้าง เช่น `portal` ไม่มีตารางของตัวเองจึงไม่มี `model.py` / `repository.py`

```text
app.py                     จุดเริ่มโปรแกรม: python app.py / --backup / --restore
config/settings.py         ค่าตั้งจาก environment หรือไฟล์ .env (ดู .env.example)
backend/
  asgi.py                  เซิร์ฟเวอร์หลัก: FastAPI (route เดียวรับทุกคำขอ) ส่งต่อให้ http/dispatch.py
  server.py                เซิร์ฟเวอร์เดิม (http.server) เก็บไว้ย้อนกลับด้วย BOOKDOSE_SERVER=legacy
  http/                    dispatch.py: ตาราง route และลำดับ middleware ตามระดับการเข้าถึง ใช้ร่วมกันทั้งสองเซิร์ฟเวอร์
                           แล้วเรียก controller; adapter.py: object `req` ของคำขอจาก ASGI
  workers.py               เริ่ม/หยุดงานเบื้องหลัง (AI, ช่องทาง, อีเมล, automation, ความปลอดภัย) ครั้งเดียวต่อ process
  realtime/                WebSocket (FastAPI เท่านั้น): hub.py ศูนย์กลางใน process, events.py service เรียกเมื่อข้อมูลเปลี่ยน
                           (ส่งหลัง commit), socket.py endpoint ทีมงาน/ลูกค้า/ผู้เยี่ยมชม
  modules/
    auth/                  เข้าสู่ระบบ ตั้งค่าครั้งแรก สมัครองค์กรพร้อมยืนยันอีเมล เซสชัน บัญชีผู้ใช้
    platform/              ผู้ดูแลแพลตฟอร์ม: สร้าง/ระงับองค์กร และอีเมลที่ใช้ส่งลิงก์ยืนยันการสมัคร
    organization/          ภาพรวมพื้นที่ทำงาน ตั้งค่า SLA ทีม สมาชิก ประวัติการทำงาน สำรองข้อมูลองค์กร
    tickets/               เคสบริการ SLA และส่งออก CSV
    conversations/         กล่องข้อความ ข้อความ ไฟล์แนบ
    contacts/              ข้อมูลลูกค้า
    knowledge/             คลังความรู้
    portal/                API ฝั่งลูกค้า (/api/public/<รหัสองค์กร>): ข้อมูลองค์กร แชท ไฟล์แนบ แบบประเมิน
    customers/             บัญชีลูกค้า: สมัคร ยืนยันอีเมล เข้าสู่ระบบ ตั้งค่าบัญชี เคส ภาพรวม SLA และการแจ้งเตือน (อีเมล / LINE)
    customer_security/     ความปลอดภัยบัญชีลูกค้า: TOTP รหัสสำรอง Passkey อุปกรณ์ที่เข้าสู่ระบบ ประวัติการใช้งาน
    security/              ความปลอดภัยของแพลตฟอร์ม: ล็อกบัญชี (lockout.py), อายุเซสชันและค่าตั้ง (sessions.py),
                           เหตุการณ์ (events.py), บล็อก IP (blocks.py), กฎแจ้งเตือนและ worker (alerts.py), กับดัก
                           honeypot/honeytoken (traps.py), API แดชบอร์ด
    org_links/             ลิงก์เชิญและ QR ขององค์กร การเข้าร่วมองค์กรของลูกค้า
    guest/                 แชทบนเว็บไซต์โดยไม่ต้องเข้าสู่ระบบ: คุกกี้ผู้เยี่ยมชม ลิงก์ติดตาม (อีเมล/SMS) LINE แจ้งเตือน
                           ย้ายเข้าบัญชี และตั้งค่า widget
    ai/                    ร่างคำตอบ AI, Chatbot, คิวงาน AI และ worker
    automation/            กฎรับเรื่อง ยกระดับ SLA (worker) Macro เตือนติดตาม CSAT @แท็ก และข้อมูลมุมมองผู้ดูแล
    channels/              LINE / Email: ตั้งค่า รับ-ส่งข้อความ outbox worker (+ email_oauth.py, file_links.py,
                           facebook.py สำหรับ Facebook Messenger)
  middleware/              security headers + ตรวจ Host/Origin, เซสชัน/CSRF/สิทธิ์ตามบทบาท,
                           ขอบเขตทีมของเจ้าหน้าที่ (access.py), จำกัดความถี่คำขอ
  database/                การเชื่อมต่อ SQLite (db.py), สร้างตารางจาก model ของทุก feature (schema.py),
                           audit log, สำรอง/กู้คืน (backup.py), ข้อมูลตัวอย่าง (seed.py)
  exceptions/              ชนิด error ทั้งหมด (errors.py) และการแปลงเป็น HTTP status (handlers.py)
  extensions/              ต่อบริการภายนอก: OpenAI (openai_client.py), LINE / IMAP / SMTP (channel_transport.py),
                           SMS (sms.py: off / log)
  utils/                   ตัวช่วยที่ใช้ซ้ำ: validation, วันเวลา, hashing/id, ไฟล์ส่วนตัว, HTTP, route table
frontend/                  หน้าเว็บ Next.js 16 (App Router) + React + TypeScript ส่งต่อ /api/* มายัง server นี้
  src/app/                 URL ของทุกหน้าจอ (บาง: อ่าน params แล้วเรียก screen)
  src/features/<feature>/  หนึ่งโฟลเดอร์ต่อ feature ชื่อตรงกับ backend/modules: screen, components, api.ts, types.ts
  src/components/          UI กลาง (ฟอร์ม, กล่องโต้ตอบ, ตาราง, ตัวกรอง) และกรอบหน้าจอทีม / ลูกค้า
  src/lib/                 client เรียก API, เซสชัน, URL, จัดรูปแบบข้อมูล
  src/styles/              CSS ทั้งหมด (base → components → layout → pages/*.css → text-size → theme)
  src/proxy.ts             CSP nonce ต่อหน้า และ header ให้ server นี้เชื่อโดเมน/IP ที่ส่งต่อมา
                           รายละเอียดและกติกาการเขียน: frontend/README.md
tests/                     HTTP integration tests
scripts/check.py           ตรวจ syntax และรัน tests ทั้งหมด
```
