# การเฝ้าระวังและกับดัก

ส่วนหนึ่งของ [ความปลอดภัย](README.md)

ทุกอย่างในเอกสารนี้ดูและตั้งค่าได้ที่ **คอนโซลระบบกลาง → ความปลอดภัย** เฉพาะผู้ดูแลแพลตฟอร์ม

## บันทึก 3 ชั้น

| บันทึก | เก็บอะไร | อยู่ที่ไหน | เก็บนาน |
|---|---|---|---|
| `audit_logs` | ใครทำอะไรกับข้อมูลไหน | ฐานข้อมูลกลาง และของทุกองค์กร | ไม่ลบ |
| `security_events` | สิ่งที่ด่านต่าง ๆ เห็น | ฐานข้อมูลกลาง | 90 วัน |
| `*_activity` | ประวัติของบัญชีตัวเอง เช่น เข้าสู่ระบบ สองขั้นตอน Passkey อุปกรณ์ รหัสผ่าน | ฐานข้อมูลกลาง | 365 วัน |

## เหตุการณ์ความปลอดภัย

`backend/modules/security/events.py`

เหตุการณ์ถูกเขียนตรงจุดที่การตรวจปฏิเสธบางอย่าง แต่ละเหตุการณ์ใช้ transaction สั้นของตัวเอง คำขอที่ถูกปฏิเสธและ rollback จึงยังทิ้งร่องรอยไว้ การบันทึกไม่ทำให้คำขอล้ม

**ชนิดที่บันทึก** เช่น

| กลุ่ม | ชนิด |
|---|---|
| เข้าสู่ระบบ | `login_failed`, `login_locked`, `login_after_lock`, `twofa_failed`, `password_reset_requested`, `password_reset_completed` |
| เซสชัน | `session_expired`, `sessions_revoked` |
| คำขอ | `rate_limited`, `csrf_rejected`, `origin_rejected`, `ip_blocked_request` |
| ข้อมูล | `cross_tenant_denied`, `support_access` |
| ช่องทาง | `webhook_signature_failed`, `guest_link_invalid` |
| ฟอร์มสาธารณะ | `captcha_failed`, `captcha_unavailable` |
| กับดัก | `honeypot_path`, `honeypot_form`, `honeytoken_triggered`, `trap_ip_block` |
| ผู้ดูแล | `admin_unlock`, `admin_ip_block`, `security_settings_changed` |
| บัญชีผู้ดูแลแพลตฟอร์ม | `reauth_failed` (ยืนยันรหัสผ่านซ้ำผิด), `sign_in_new_place` (เข้าสู่ระบบจากที่ใหม่ พร้อมประเทศ ผู้ให้บริการ และสัญญาณที่พบ เป็นระดับเฝ้าระวังเมื่อเดินทางเป็นไปไม่ได้ และเปิดการแจ้งเตือน `impossible_travel`), `sign_in_disowned` (เจ้าของกด "ไม่ใช่ฉัน" ระดับวิกฤต และเปิดการแจ้งเตือนทันที) ดู [การยืนยันตัวตน](authentication.md#บัญชีผู้ดูแลแพลตฟอร์ม) |

**กันน้ำท่วม** เหตุการณ์เหมือนกัน (ชนิด IP และเป้าหมาย) ในนาทีเดียวกันรวมเป็นแถวเดียวแล้วเพิ่มตัวนับ และเขียนแถวใหม่ไม่เกิน 1,000 แถวต่อนาที การยิงถล่มจึงไม่ทำให้ฐานข้อมูลบวม

## การแจ้งเตือนอัตโนมัติ

`backend/modules/security/alerts.py` งานเบื้องหลังตรวจทุกนาที เพดานปรับได้ในหน้าตั้งค่า

| กฎ | ค่าเริ่มต้น | ระดับ |
|---|---|---|
| เข้าสู่ระบบล้มเหลวจาก IP เดียว | 30 ครั้งใน 10 นาที | เตือน |
| เข้าสู่ระบบล้มเหลวทั้งแพลตฟอร์ม | 100 ครั้งใน 10 นาที | วิกฤต |
| บัญชีถูกล็อก | 10 บัญชีใน 1 ชั่วโมง | วิกฤต |
| คำขอถูกจำกัดจาก IP เดียว | 200 ครั้งใน 10 นาที | เตือน |
| ลายเซ็น Webhook ผิด | 20 ครั้งใน 10 นาที | เตือน |

- เปิดการแจ้งเตือนหนึ่งรายการต่อกฎต่อ IP แล้วอัปเดตรายการเดิมขณะเหตุยังเกิดต่อ
- การแจ้งเตือนระดับวิกฤตใหม่ส่งอีเมลถึงผู้ดูแลแพลตฟอร์ม ไม่เกินชั่วโมงละครั้งต่อกฎ
- ผู้ดูแลกด **รับทราบ** ได้ เหตุที่ยังเกิดในกรอบเวลาเดิมจะอัปเดตรายการเดิมเงียบ ๆ แทนการเปิดใหม่

## บล็อก IP

`backend/modules/security/blocks.py`

- ผู้ดูแลแพลตฟอร์มบล็อกได้ 1 ชั่วโมง 24 ชั่วโมง 7 วัน หรือถาวร พร้อมเหตุผล
- ตรวจก่อนทุกอย่าง ทั้งคำขอ HTTP (ตอบ 403) และ WebSocket (ปิด 4403)
- ใช้ที่อยู่ของผู้ใช้ชุดเดียวกับการจำกัดคำขอ ไม่เชื่อ `X-Forwarded-For` ดิบ
- บล็อก IP ของคำขอตัวเองไม่ได้
- เป็นคนละเรื่องกับ [บล็อกผู้ก่อกวน](../features/support-page-and-guest-chat.md#บล็อกผู้ก่อกวน) ของเจ้าขององค์กร ซึ่งกัน IP ไว้ 7 วันเฉพาะการเริ่มแชทผู้เยี่ยมชมในองค์กรนั้น ส่วนตรงนี้กันทั้งระบบ

## ข้อมูล IP และการตรวจการปลอมตัว

`backend/modules/security/ip_intel.py`

การปลอม IP ต้นทางในแพ็กเก็ตใช้กับเว็บไม่ได้ เพราะการเชื่อมต่อแบบ TCP ต้องตอบกลับไปมาก่อน สิ่งที่ผู้ไม่หวังดีทำได้จริงคือใช้ IP ของคนอื่น (VPN พร็อกซี เครื่องเช่าบนคลาวด์) หรือปลอม header ส่วน header ระบบกันไว้แล้ว API เชื่อ IP เฉพาะที่หน้าเว็บของเราส่งมาพร้อมความลับร่วม ดู [การป้องกันระดับคำขอ](request-protection.md) ส่วนนี้จึงช่วยเรื่องแรก

**ฐานข้อมูลในเครื่อง**

- ใช้ไฟล์ฟรีของ DB-IP 2 ไฟล์ คือประเทศของ IP และผู้ให้บริการเครือข่าย (ASN) อัปเดตรายเดือน สัญญาอนุญาต CC BY 4.0 คอนโซลจึงแสดงข้อความ "IP Geolocation by DB-IP"
- เปิดที่ **คอนโซล → ความปลอดภัย → ตั้งค่า → ฐานข้อมูล IP** ก่อนกด ระบบไม่ดาวน์โหลดอะไรเลย และทุกอย่างทำงานเหมือนเดิม
- กดแล้วดาวน์โหลดประมาณ 12 MB ใช้เวลาราว 1 นาทีใน thread แยก จากนั้นงานเบื้องหลังอัปเดตเองทุกเดือน ถ้าดาวน์โหลดไม่สำเร็จจะใช้ฉบับเดิมต่อ และลองใหม่ทุก 6 ชั่วโมง
- ค้น IP ในเซิร์ฟเวอร์เอง ไม่ส่ง IP ของผู้ใช้ไปที่ใด
- เก็บที่ `data/ip-intel/` ไฟล์ใหม่ทุกครั้งที่อัปเดต ไฟล์เก่าลบเมื่อไม่มีใครใช้แล้ว ไม่อยู่ในไฟล์สำรอง เพราะดาวน์โหลดใหม่ได้
- **เครือข่ายคลาวด์หรือ VPN** ดูจากหมายเลขเครือข่ายของผู้ให้บริการที่รู้จัก (AWS, Google Cloud, Azure, DigitalOcean, Hetzner, OVH, Cloudflare WARP, M247 และอื่น ๆ) และคำในชื่อเครือข่าย เช่น hosting, cloud, data center, VPN
- ปุ่ม **เลิกใช้** ลบไฟล์และหยุดอัปเดต

**ใช้ที่ไหนบ้าง** ทุกข้อเป็นสัญญาณประกอบ ไม่มีข้อไหนบล็อกใครเพราะเรื่องนี้อย่างเดียว เพราะคนทั่วไปใช้ VPN ของบริษัทหรือ iCloud Private Relay กันมาก

| ที่ | ผล |
|---|---|
| หน้าความปลอดภัย | ประเทศ ผู้ให้บริการ และป้าย **คลาวด์หรือ VPN** ข้าง IP ในบันทึกเหตุการณ์ การแจ้งเตือน IP ที่มีเหตุการณ์มากที่สุด และรายการ IP ที่บล็อก (`ip_info` ในคำตอบของ API) |
| แชทผู้เยี่ยมชม | IP ของเครือข่ายคลาวด์หรือ VPN เริ่มแชทใหม่ได้ 5 เรื่องใน 24 ชั่วโมงต่อองค์กร แทน 20 เรื่อง |
| การเข้าสู่ระบบของผู้ดูแลแพลตฟอร์ม | อีเมลแจ้งที่ใหม่บอกประเทศและผู้ให้บริการ และตรวจ 3 สัญญาณ ดู [การยืนยันตัวตน](authentication.md#อีเมลแจ้งเมื่อเข้าสู่ระบบจากที่ใหม่) |

**ที่ตั้งใจไม่ทำ** เพราะทำไม่ได้กับระบบนี้ หรือเสี่ยงพังมากกว่าได้

- WebRTC leak (เบราว์เซอร์รุ่นใหม่ซ่อน IP จริงแล้ว และเข้าข่ายสอดแนม) และขอพิกัดจากเครื่อง (ขออนุญาตทุกครั้ง ปลอมง่าย และเป็นข้อมูลอ่อนไหว)
- วิเคราะห์แพ็กเก็ต (TTL MTU RTT p0f) เพราะ API อยู่หลังหน้าเว็บและ load balancer ไม่เห็นแพ็กเก็ตของผู้ใช้
- ลำดับของ header เพราะหน้าเว็บสร้างคำขอใหม่ก่อนส่งต่อ และแต่ละเบราว์เซอร์เรียงไม่เหมือนกัน
- บริการตรวจ residential proxy แบบเสียเงิน เพราะต้องส่ง IP ของผู้ใช้ทุกคนให้บริษัทอื่น
- ตรวจจากระบบปฏิบัติการหรือแอปในเครื่อง (ใช้ได้เฉพาะแอปมือถือ) และ Ingress filtering (เป็นหน้าที่ของ ISP)

## กับดัก

กับดักคือสิ่งที่ผู้ใช้จริงไม่เคยแตะ การแตะจึงบอกว่ามีผู้สแกน บอต หรือคนในกำลังทำอะไรบางอย่าง **กับดักไม่เปลี่ยนคำตอบ** คำขอเดินต่อเหมือนเดิมทุกประการ ผู้บุกรุกจึงไม่รู้ว่าถูกจับได้ (`backend/modules/security/traps.py`)

การบันทึกทำใน thread เบื้องหลัง `bookdose-traps` คำขอที่ติดกับดักจึงไม่ช้ากว่าคำขออื่น

### เส้นทางล่อ

| ชนิด | ตัวอย่าง | ใครตอบ |
|---|---|---|
| หน้าเว็บ | `/.env`, `/.git/config`, `/wp-login.php`, `/wp-admin`, `/phpmyadmin`, `/backup.zip`, `/vendor/phpunit` | Next.js ตอบหน้า 404 เดียวกับ URL ที่ไม่มีอยู่ แล้วรายงานไปที่ API หลังตอบ |
| API | `/api/admin`, `/api/.env`, `/api/graphql`, `/api/swagger.json`, `/api/debug` และที่ผู้ดูแลเพิ่มเอง | API ตอบเหมือน path ที่ไม่มีอยู่ทุกไบต์ |

- ผู้ดูแลเพิ่มเส้นทางล่อของ API เองได้ไม่เกิน 50 แบบ ตรงตัวหรือขึ้นต้นด้วย ระบบไม่ยอมให้ซ้อนกับ route จริง
- หน้าเว็บรายงานผ่าน `POST /api/trap` ซึ่งรับเฉพาะจากหน้าเว็บที่เชื่อถือได้ คำขอจากที่อื่นได้คำตอบเหมือน path ที่ไม่มีอยู่
- แตะครบ 3 ครั้งใน 10 นาทีจาก IP เดียว บล็อก IP นั้น 1 ชั่วโมง (ปรับได้)

### ช่องซ่อนในฟอร์ม

ช่อง `website` หรือ `company_website` ที่คนมองไม่เห็นและเข้าถึงไม่ได้ อยู่ในฟอร์มเข้าสู่ระบบ สมัครองค์กร สมัครลูกค้า ลืมรหัสผ่าน และเริ่มแชทผู้เยี่ยมชม

ถ้ามีค่า คำขอไม่ถูกทำต่อ แต่ตอบเหมือนความล้มเหลวปกติ

| ฟอร์ม | คำตอบ |
|---|---|
| เข้าสู่ระบบ | 401 รหัสผ่านผิด และไม่นับเข้าการล็อกบัญชี |
| สมัคร ลืมรหัสผ่าน | 202 ส่งลิงก์แล้ว |
| เริ่มแชทผู้เยี่ยมชม | 400 ข้อความกันสแปมทั่วไป |

### Honeytoken

ผู้ดูแลแพลตฟอร์มสร้างของล่อแล้วนำไปวางในที่ที่ผู้บุกรุกหรือคนในที่อยากรู้จะเจอ

| ชนิด | ผู้ดูแลได้อะไร | ทำงานเมื่อ |
|---|---|---|
| บัญชีล่อ | อีเมลที่ดูเหมือนจริงแต่ไม่มีบัญชี | มีคนเข้าสู่ระบบด้วยอีเมลนี้ ขอลิงก์ลืมรหัสผ่าน หรือเชิญเข้าองค์กร |
| API key | ข้อความที่ดูเหมือนคีย์ เช่น `bdk_live_...` | ข้อความนี้ปรากฏใน `Authorization`, `X-API-Key`, คุกกี้, query string หรือ JSON body ของคำขอใดก็ได้ |
| รหัสผ่าน | รหัสผ่านที่ดูเหมือนจริง | มีคนใช้เป็นรหัสผ่านบน endpoint เข้าสู่ระบบใดก็ได้ อีเมลใดก็ได้ |
| ลิงก์ไฟล์ | `https://<host>/files/<สุ่ม>` ที่ดูเหมือนไฟล์แชร์ | มีคนเปิดลิงก์ หน้าตอบว่าไฟล์ถูกย้ายหรือหมดอายุ |

- ความลับแสดงครั้งเดียวตอนสร้าง ระบบเก็บเพียง SHA-256
- ตรวจแบบประหยัด โหลด prefix 12 ตัวแรกไว้ในหน่วยความจำ และ hash เฉพาะเมื่อ prefix ตรง JSON body ตรวจเฉพาะที่ไม่เกิน 1 MB
- เมื่อทำงาน: บันทึกเหตุการณ์ระดับวิกฤต เปิดการแจ้งเตือนทันที ส่งอีเมลถึงผู้ดูแล (ไม่เกินชั่วโมงละครั้งต่อกับดัก) และบล็อก IP 24 ชั่วโมง (ปรับได้)
- ไม่บล็อก loopback และ IP ของผู้ดูแลแพลตฟอร์มที่เข้าสู่ระบบอยู่
- ถ้าผู้ที่แตะคือทีมงานที่เข้าสู่ระบบอยู่ ระบบบันทึกชื่อไว้ในเหตุการณ์ แต่ไม่สั่งออกจากระบบ
- ปุ่มทดสอบสร้างเหตุการณ์ระดับข้อมูลที่ระบุว่าเป็นการทดสอบ ไม่บล็อก ไม่ส่งอีเมล

## หน้าความปลอดภัยของคอนโซล

| แท็บ | มีอะไร |
|---|---|
| ภาพรวม | ตัวเลขและกราฟของช่วง 24 ชั่วโมงหรือ 7 วัน IP และบัญชีที่ถูกโจมตีมากที่สุด |
| ตรวจสุขภาพ | security header และใบรับรอง HTTPS ของเว็บไซต์ กุญแจเข้ารหัสแยกจากโฟลเดอร์ข้อมูลหรือไม่ Turnstile องค์กรที่ไม่มีเจ้าของ และองค์กรที่ไม่มีเพดานพื้นที่ |
| เหตุการณ์ | บันทึกเหตุการณ์ กรองตามชนิด ระดับ ผู้ใช้ IP องค์กร และคำค้น |
| การเข้าถึง | บัญชีที่ถูกล็อกพร้อมปุ่มปลดล็อก รายการ IP ที่บล็อก และยุติเซสชันทั้งหมดของบัญชี |
| กับดัก | Honeytoken เหตุการณ์กับดักล่าสุด และตั้งค่ากับดัก |
| ช่องโหว่ | ไลบรารีที่เซิร์ฟเวอร์ใช้เทียบกับช่องโหว่ที่เผยแพร่แล้ว |
| ตั้งค่า | อายุเซสชันของแต่ละกลุ่มผู้ใช้ และเพดานการแจ้งเตือน |

การแจ้งเตือนที่ยังเปิดอยู่แสดงเหนือทุกแท็บ หน้านี้อัปเดตเองทุกนาทีด้วยคำขอ GET ซึ่งไม่นับเป็นการใช้งานของผู้ดูแล

`backend/modules/platform/vulns.py`

- ตรวจวันละครั้งกับ OSV.dev ซึ่งรวบรวมรายการ CVE คำเตือนของ GitHub และของ PyPI กับ npm
- ตรวจสิ่งที่รันจริง คือแพ็กเกจ Python ที่ติดตั้งอยู่บนเซิร์ฟเวอร์ และทุกแพ็กเกจใน `frontend/package-lock.json` แพ็กเกจที่ใช้เฉพาะตอน build แสดงแยกและไม่ส่งอีเมล
- ส่งออกไปเพียงชื่อและรุ่นของแพ็กเกจ
- พบช่องโหว่ระดับสูงหรือวิกฤตใหม่ ส่งอีเมลถึงผู้ดูแลแพลตฟอร์มทันที
