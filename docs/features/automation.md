# ระบบอัตโนมัติ

เครื่องมือที่ทำงานแทนทีมในงานซ้ำ ๆ เจ้าขององค์กรตั้งค่าได้ที่เมนู **ระบบอัตโนมัติ** (`/automation`) ยกเว้นการปิดเคสเมื่อลูกค้าเงียบ ซึ่งอยู่ที่ **ตั้งค่าองค์กร → มาตรฐานบริการ**

| เครื่องมือ | ทำอะไร |
|---|---|
| กฎรับเรื่องและส่งต่อ | ตั้งความเร่งด่วน ทีม ผู้รับผิดชอบ และป้ายเคสให้เรื่องใหม่ตามช่องทางและคำค้น |
| แจกเคสอัตโนมัติ | ส่งเคสที่ยังไม่มีผู้รับผิดชอบให้คนในทีมที่พร้อมและถืองานน้อยที่สุด |
| ยกระดับ SLA | ย้ายเคสที่ยังไม่มีใครรับให้เจ้าขององค์กร |
| Macro | ปุ่มเดียวทำหลายขั้น |
| ติดตามผล | เตือนให้กลับมาดูเคสในวันที่กำหนด |
| แบบประเมินความพึงพอใจ | ถามคะแนนเมื่อปิดเคส |
| การ์ดขอบคุณหลังปิดเคส | ลูกค้าที่แชทบนเว็บเห็นชื่อและรูปของทีมงานที่ดูแลเคส |
| ปิดเคสเมื่อลูกค้าเงียบ | ถามลูกค้าที่เงียบไป แล้วปิดเคสเมื่อยังไม่ตอบ |

งานเบื้องหลัง `bookdose-automation` ทำงานทุก 30 วินาที

## กฎรับเรื่องและส่งต่อ

**เงื่อนไข:** ช่องทาง (แชทบนเว็บ LINE อีเมล Facebook Instagram เคสที่บันทึกเอง หรือทุกช่องทาง) และคำค้นในหัวเรื่องหรือข้อความ

**ผล:** ตั้งความเร่งด่วน ทีม ผู้รับผิดชอบ และติดป้ายเคส (จากรายการป้ายขององค์กร ดู [เคส](tickets.md#ป้ายเคส))

ตัวอย่าง: ถ้ามาจาก Facebook และมีคำว่า "ระบบล่ม" ให้ความเร่งด่วนสูง และส่งให้ทีมเทคนิค

- เมื่อข้อความแรกของเรื่องใหม่ตรงกฎ ระบบเปิดเคสให้ทันที
- กฎยังทำงานกับเคสที่เปิดด้วยวิธีอื่นด้วย
- กฎทำงานตามลำดับที่สร้าง
- ผู้รับผิดชอบที่ไม่อยู่ในทีมสุดท้ายของเคสจะไม่ถูกมอบหมาย
- ไม่มอบเคสให้สมาชิกที่พัก ยุ่ง ไม่อยู่ นอกเวลาทำงาน หรือลา เคสจะรอทีมแทน ดู [ทีมและบัญชีทีมงาน](team-and-staff-account.md#สถานะการทำงาน)
- ความเร่งด่วนที่กฎตั้งทำให้กำหนดเวลา SLA ถูกคำนวณใหม่ตามความเร่งด่วนนั้น
- หลายกฎที่ตรงกันติดป้ายรวมกันทุกป้าย ไม่เกิน 10 ป้ายต่อเคส ป้ายที่ถูกลบออกจากรายการหายจากกฎด้วย
- ถ้ากฎไม่ได้ระบุผู้รับผิดชอบ และเปิดแจกเคสอัตโนมัติไว้ เคสจะถูกแจกต่อ (หัวข้อถัดไป)

**ข้อจำกัด:** ใช้เงื่อนไขช่องทางและคำค้นเท่านั้น ยังไม่มีเงื่อนไขซ้อน การค้นคำเป็นการหาข้อความตรงตัวโดยไม่สนตัวพิมพ์เล็กใหญ่

## แจกเคสอัตโนมัติ

ค่าเริ่มต้นปิด เปิดแล้วเคสใหม่ที่ยังไม่มีผู้รับผิดชอบไปถึงคนในทีมทันที ไม่ต้องรอใครกดรับ

**ใครรับเคสได้** สมาชิกที่ใช้งานอยู่ของทีมเคส (เจ้าขององค์กรด้วยเมื่อเลือก "แจกให้เจ้าขององค์กรด้วย") ที่

1. สถานะพร้อมรับเรื่อง อยู่ในเวลาทำงาน และไม่ลา ดู [ทีมและบัญชีทีมงาน](team-and-staff-account.md#สถานะการทำงาน)
2. เปิดโปรแกรมภายใน 10 นาทีที่ผ่านมา สถานะที่ลืมเปลี่ยนไว้ข้ามคืนจึงไม่เก็บเคสของทั้งคืน
3. ถือเคสไม่ถึงเพดานที่ตั้ง (1 ถึง 50 เคส ค่าเริ่มต้น 5) นับเฉพาะเคสที่ต้องทำตอนนี้ ไม่นับเคสที่รอลูกค้าหรือพักไว้

**ได้ใคร** คนที่ถือเคสน้อยที่สุด ถ้าเท่ากัน คนที่ได้เคสจากการแจกครั้งล่าสุดนานที่สุด

**กติกา**

- แจกเฉพาะเคสที่ยังไม่มีผู้รับผิดชอบ กฎที่ระบุผู้รับผิดชอบและการมอบหมายเองทำก่อนเสมอ
- ใช้กับทุกทีม หรือเฉพาะทีมที่เลือก
- ไม่มีใครรับได้ เคสรอในคิวของทีม งานเบื้องหลังลองแจกใหม่ทุก 30 วินาที เคสด่วนก่อน แล้วเคสที่รอนานที่สุด
- งานเบื้องหลังแจกก่อนยกระดับในรอบเดียวกัน เคสที่ยังไม่มีใครรับจนครบเวลายังถูกยกระดับตามปกติ
- บันทึกแล้ว เคสที่รออยู่ถูกแจกทันที
- คนที่ได้เคสได้รับการแจ้งเตือนแบบเดียวกับถูกมอบหมาย ประวัติเคสบันทึกว่าแจกให้ใคร และตอนนั้นถืออยู่กี่เคส
- คนที่เปลี่ยนเป็นพักหรือไม่อยู่ยังถือเคสเดิม ระบบไม่ดึงเคสคืน

หน้าระบบอัตโนมัติแสดงรายชื่อคนที่ระบบจะพิจารณา ถืออยู่กี่เคส และถ้ารับไม่ได้เพราะอะไร พร้อมจำนวนที่แจกวันนี้และจำนวนที่รอคนรับ

## ยกระดับ SLA

ค่าเริ่มต้นเปิด และใช้เวลา 15 นาที

- **เคสที่ยังไม่มีผู้รับผิดชอบและยังไม่มีใครตอบ** เกินเวลาที่ตั้ง ย้ายให้เจ้าขององค์กร เลือกคนที่พร้อมรับงาน อยู่ทีมเดียวกับเคส และถืองานน้อยที่สุดก่อน
- **เคสที่มีผู้รับผิดชอบแต่ใกล้ครบเวลาตอบครั้งแรก** แจ้งเจ้าขององค์กรโดยไม่ย้าย
- แต่ละเคสยกระดับครั้งเดียว
- บันทึกในประวัติเคส แจ้งในหน้าภาพรวมและกระดิ่ง และส่งอีเมลถึงผู้ที่รับเคสถ้าเขาเปิดการแจ้งเตือนทางอีเมลไว้
- การยกระดับเปลี่ยนผู้รับผิดชอบ ไม่เปลี่ยนสถานะ

## Macro

ปุ่มเดียวทำหลายขั้น เช่น Macro **ขอข้อมูลเพิ่มเติม**

1. ส่งข้อความแม่แบบถึงลูกค้า
2. เปลี่ยนสถานะเป็นรอลูกค้า
3. ตั้งเตือนติดตามใน 24 ชั่วโมง

- ข้อความแทนค่า `{customer}`, `{case}` และ `{agent}` ได้
- ใช้ได้จากหน้าเคสและปุ่ม Macro ในช่องพิมพ์
- ข้อความส่งผ่านช่องทางเดิมของลูกค้าเหมือนทีมงานพิมพ์เอง
- เคสที่บันทึกเองข้ามขั้นส่งข้อความ
- Macro เปลี่ยนเป็นสถานะใดก็ได้ยกเว้น "ใหม่" หรือคงสถานะเดิม
- หลังกด ข้อความสั้นบอกว่าทำอะไรไปแล้ว และขั้นไหนใช้ไม่ได้

## ติดตามผล

- ตั้งจาก Macro หรือจากหน้าเคสเองก็ได้
- ครบกำหนดแล้วแสดงในการ์ด **ถึงคุณ** และกระดิ่ง
- กด **เสร็จแล้ว** เมื่อติดตามเรียบร้อย
- การติดตามผลไม่กั้นอะไร เป็นการเตือนเท่านั้น

## แบบประเมินความพึงพอใจ (CSAT)

ค่าเริ่มต้นเปิด

- ส่งเมื่อเคสเปลี่ยนเป็นแก้ไขแล้วหรือปิดเคส หนึ่งครั้งต่อการปิด
- **แชทบนเว็บ** ลูกค้าเห็นปุ่มดาว 1 ถึง 5 พร้อมช่องความคิดเห็น (ไม่บังคับ ไม่เกิน 1,000 ตัวอักษร)
- **LINE อีเมล Facebook Instagram** ลูกค้าตอบเป็นตัวเลข 1 ถึง 5 ภายใน 7 วัน
- คำตอบคะแนนไม่เปิดเคสกลับมา
- แบบประเมินเป็นข้อความระบบ ไม่นับเป็นการตอบครั้งแรก
- ความคิดเห็นแสดงในหน้าเคสของทีมงาน
- ปิดการส่งหรือแก้ข้อความได้ที่หน้าระบบอัตโนมัติ

## การ์ดขอบคุณหลังปิดเคส

ค่าเริ่มต้นปิด เจ้าขององค์กรเปิดได้ที่หน้าระบบอัตโนมัติ ใต้แบบประเมินความพึงพอใจ

เมื่อเปิดแล้ว เคสที่ปิดและมีบทสนทนาบนเว็บ (หน้าช่วยเหลือ แชทผู้เยี่ยมชม หรือหน้าลูกค้า) ได้การ์ดเล็ก ๆ ท้ายบทสนทนา มีชื่อและรูปของทีมงานที่ดูแลเคส พร้อมข้อความขอบคุณ ให้ลูกค้ารู้ว่าคุยกับคนจริง

- **ใครอยู่บนการ์ด** ผู้รับผิดชอบเคส ถ้าไม่มี คือคนที่ปิดเคส ชื่อคือชื่อที่ลูกค้าเห็นในคำตอบอยู่แล้ว (ชื่อที่แสดงต่อลูกค้า ถ้าตั้งไว้)
- **รูปเป็นของเจ้าตัว** ทีมงานแต่ละคนเลือกเองที่ ตั้งค่าบัญชี → ข้อมูลส่วนตัว ว่าจะให้ลูกค้าเห็นรูปไหม ค่าเริ่มต้นไม่ให้เห็น การ์ดจึงแสดงตัวอักษรแรกของชื่อแทน
- **ข้อความ** องค์กรตั้งข้อความกลางได้ไม่เกิน 200 ตัวอักษร (เว้นว่างใช้ข้อความเริ่มต้น) ทีมงานเขียนข้อความของตัวเองแทนได้
- การ์ดคำนวณใหม่ทุกครั้งที่ลูกค้าเปิดแชท ทีมงานเลิกแสดงรูป หรือองค์กรปิดการ์ด มีผลกับการ์ดที่ให้ไปแล้วทันที
- การ์ดหายเมื่อลูกค้าพิมพ์ต่อ หรือเคสเปิดใหม่ ปิดเคสอีกครั้งได้การ์ดใหม่
- รูปบนการ์ดเปิดได้เฉพาะลูกค้าเจ้าของบทสนทนานั้น
- LINE อีเมล Facebook และ Instagram ไม่ได้รับอะไรเพิ่ม
- ประวัติเคสบันทึกว่าลูกค้าได้การ์ดขอบคุณ

## ปิดเคสเมื่อลูกค้าเงียบ

เคสที่อยู่ในสถานะ "รอลูกค้า" แล้วลูกค้าไม่ตอบ ไม่ค้างอยู่ในรายการตลอดไป ค่าเริ่มต้นปิด

1. ลูกค้าเงียบครบจำนวนวันที่ตั้ง (ค่าเริ่มต้น 3 วัน) ระบบส่งข้อความถามว่ายังต้องการความช่วยเหลือหรือไม่
2. ถามแล้วยังเงียบครบจำนวนวันที่ตั้ง (ค่าเริ่มต้น 2 วัน) ระบบปิดเคส พร้อมข้อความบอกว่าตอบกลับเมื่อไรเรื่องจะเปิดขึ้นอีกครั้ง

- ตั้งได้ 1 ถึง 30 วัน และแก้ข้อความทั้งสองได้ ใส่ `{วัน}` ในข้อความถาม ระบบเติมจำนวนวันก่อนปิด
- นับความเงียบจากการเปลี่ยนแปลงล่าสุดของเคส และข้อความล่าสุดที่ไม่ใช่ข้อความระบบ บันทึกภายในของทีมก็นับ เพราะแปลว่ายังมีคนดูเรื่องนี้อยู่
- เคสที่พักไว้เริ่มนับเมื่อครบเวลาพัก
- ข้อความทั้งสองเป็นข้อความระบบ ส่งทางช่องทางเดิมของเคส ไม่นับเป็นการตอบครั้งแรก
- ลูกค้าตอบกลับเมื่อไร เคสเปิดกลับมาเอง
