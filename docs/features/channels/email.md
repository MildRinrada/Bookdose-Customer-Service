# อีเมล

รับอีเมลจากกล่องรับเรื่องขององค์กรผ่าน IMAP และตอบผ่าน SMTP ส่วนหนึ่งของ [ช่องทาง](README.md)

## เชื่อมต่อด้วยรหัสผ่าน

1. ใช้กล่องอีเมลที่เปิด IMAP และ SMTP พร้อมรหัสผ่าน หรือ App Password ที่ใช้ได้ทั้งสองบริการ
2. ไปที่ **ตั้งค่าองค์กร → LINE / อีเมล / Facebook / Instagram → อีเมล** กรอกอีเมลรับเรื่อง ชื่อผู้ใช้ รหัสผ่าน และชื่อเซิร์ฟเวอร์ IMAP กับ SMTP โดยไม่ใส่ `https://`
3. IMAP ใช้ TLS พอร์ต 993 ส่วน SMTP เลือก 465 (TLS) หรือ 587 (STARTTLS)
4. เลือกทีม ตั้งรอบตรวจอีเมล (ค่าเริ่มต้น 60 วินาที ปรับได้ 30 ถึง 600 วินาที) ติ๊กเปิดรับและส่ง แล้วบันทึก ระบบทดสอบเข้า IMAP และ SMTP ก่อนเปิดใช้
5. ส่งอีเมลใหม่เข้ากล่องนี้ แล้วดูในกล่องข้อความ

ต้องใช้เซิร์ฟเวอร์สาธารณะที่มีใบรับรอง TLS ถูกต้อง ไม่รองรับเซิร์ฟเวอร์ใน LAN หรือ localhost

Gmail และ Outlook ที่เปิดการยืนยันตัวตน 2 ขั้น ต้องใช้ App Password หรือเชื่อมด้วย OAuth

## เชื่อมต่อด้วย OAuth

รองรับ Google Workspace หรือ Gmail และ Microsoft 365 หรือ Outlook ด้วย Authorization Code Flow พร้อม PKCE (S256) ผู้ดูแลองค์กรต้องลงทะเบียน OAuth application ของตัวเองก่อน

### Google

1. ใน Google Cloud สร้าง OAuth consent screen และ OAuth Client ID ชนิด **Web application**
2. เพิ่ม Authorized redirect URI ให้ตรงกับที่อยู่ของหน้าเว็บ เช่น `https://support.example.com/oauth/email/callback` (บนเครื่องตัวเองใช้ `http://localhost:3000/oauth/email/callback`)
3. ระบบขอ scope `https://mail.google.com/` ซึ่งเป็นสิทธิ์เข้ากล่องจดหมายแบบเต็ม แอปที่เผยแพร่ภายนอกอาจต้องผ่านการตรวจของ Google
4. ในระบบเลือก **Google Workspace / Gmail OAuth** แล้วใส่ Client ID และ Client Secret ระบบกำหนดเซิร์ฟเวอร์ IMAP และ SMTP ของ Gmail ให้

### Microsoft

1. ลงทะเบียนแอปใน Microsoft Entra เลือกประเภทบัญชีที่ต้องการ
2. เพิ่มแพลตฟอร์ม **Web** พร้อม Redirect URI แบบเดียวกับด้านบน สร้าง Client Secret แล้วคัดลอก **Value** ไม่ใช่ Secret ID
3. เพิ่ม delegated permissions ของ Office 365 Exchange Online: `IMAP.AccessAsUser.All`, `SMTP.Send` และ `offline_access`
4. ในระบบเลือก **Microsoft 365 / Outlook OAuth** แล้วใส่ Client ID และ Client Secret
5. ผู้ดูแล Microsoft ต้องอนุญาต IMAP และ SMTP AUTH ของบัญชีนั้นด้วย OAuth ไม่ได้ข้ามนโยบายที่ปิดโปรโตคอลไว้

### ขั้นตอนในระบบ

1. กรอกข้อมูล แล้ว **บันทึกโดยยังไม่เปิดช่องทาง**
2. เปิดระบบผ่านโดเมนและพอร์ตที่ตรงกับ Redirect URI แล้วกดเชื่อมบัญชี เลือกบัญชีที่มีสิทธิ์เข้ากล่องนั้น และอนุญาต
3. ระบบตรวจ state ที่ใช้ครั้งเดียว (อายุ 10 นาที ผูกกับเซสชันและองค์กรที่เริ่มเชื่อม) ตรวจ PKCE และลองเข้ากล่องอีเมลจริงก่อนเก็บ token
4. กลับไปหน้าตั้งค่า ติ๊กเปิดรับและส่ง แล้วบันทึก

- Access Token ต่ออายุด้วย Refresh Token เอง ถ้าสิทธิ์ถูกถอนหรือหมดอายุ หน้าตั้งค่าแสดงข้อผิดพลาด ให้เชื่อมใหม่
- เปลี่ยนผู้ให้บริการ Client ID หรือ Redirect URI ต้องอนุญาตใหม่
- หน้ารับกลับลบ code และ state ออกจากแถบที่อยู่ก่อนเรียก API
- การลบข้อมูลเชื่อมต่อหยุดใช้สิทธิ์ในระบบนี้ ถ้าต้องการถอนการอนุญาตที่ผู้ให้บริการด้วย ให้จัดการจากบัญชี Google หรือ Microsoft

## การรับอีเมล

- เริ่มรับเฉพาะอีเมลใหม่หลังเปิดใช้ครั้งแรก ไม่ดึงอีเมลเก่าทั้งกล่อง
- ใช้ IMAP UID และ `BODY.PEEK` แบบอ่านอย่างเดียว ไม่ลบ ไม่ย้าย และไม่ตั้งว่าอ่านแล้ว
- ดึงไม่เกิน 20 ฉบับต่อรอบ ข้ามฉบับที่ใหญ่กว่า 8 MB
- ข้ามข้อความอัตโนมัติและอีเมลตีกลับ
- เมื่อ UIDVALIDITY เปลี่ยน เริ่มจากอีเมลใหม่เพื่อไม่นำเข้าซ้ำ
- อ่าน plain text ก่อน หรือแปลง HTML เป็นข้อความธรรมดา ไม่โหลดรูปหรือสคริปต์ภายนอก
- ไฟล์แนบรับได้ไม่เกิน 3 ไฟล์ รวม 5 MB ชนิด PNG, JPG, PDF และ TXT ที่เกินหรือไม่รองรับมีข้อความให้ไปดูต้นฉบับ

## การเชื่อมอีเมลเข้าเรื่องเดิม

- เรื่องใหม่ไม่รวมกับลูกค้าเดิมเพียงเพราะอีเมลหรือหัวเรื่องเหมือนกัน
- อีเมลตอบกลับเข้าเรื่องเดิมเมื่อ `In-Reply-To` หรือ `References` ตรงกับรหัสของอีเมลที่ระบบสร้าง และผู้ส่งเป็นคนเดิมของช่องทางเดียวกันเท่านั้น
- ส่งตอบไปที่ From ที่รับเข้ามา ไม่ใช้ Reply-To หรือ CC และ BCC จากอีเมลของลูกค้า
- ชื่อและ From ที่ลูกค้าระบุไม่ใช่การยืนยันตัวตน

## การตอบ

- อีเมลตอบส่งเฉพาะข้อความและไฟล์ที่ทีมงานเลือกในครั้งนั้น ไม่แนบประวัติหรือบันทึกภายใน
- ข้อความแปลงจาก Markdown เป็น HTML ด้วยกติกาเดียวกับหน้าเว็บ มีกรอบอีเมลที่อ่านได้ทุกโปรแกรมอ่านอีเมล ไม่โหลดรูปจากภายนอก
- SMTP รับข้อความแล้วไม่ได้รับประกันว่าถึงปลายทาง ระบบไม่เพิ่มสำเนาเข้าโฟลเดอร์ Sent และไม่ประมวลผลใบยืนยันการอ่าน
- SMTP ไม่มีกุญแจกันส่งซ้ำ เมื่อเครือข่ายขาดระหว่างส่ง สถานะเป็น **ไม่ทราบผลการส่ง** และระบบไม่ส่งซ้ำเอง

## ชื่อผู้ส่งและลายเซ็น

ตั้งที่การ์ด **ชื่อผู้ส่งและลายเซ็น** ในหน้าตั้งค่าอีเมล

- **ชื่อผู้ส่ง** (ไม่เกิน 80 ตัวอักษร) ลูกค้าเห็นเป็นชื่อในช่อง From
- **ลายเซ็น** (ไม่เกิน 600 ตัวอักษร) ต่อท้ายทุกอีเมลที่ทีมตอบ
- การแก้ทั้งสองไม่ยกเลิกข้อความที่รอส่ง
