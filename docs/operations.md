# ดูแลระบบ

งานประจำของผู้ดูแลเซิร์ฟเวอร์ ได้แก่ สำรองข้อมูล กู้คืน ดูแลกุญแจเข้ารหัส อัปเดตรุ่น และเฝ้าดูงานเบื้องหลัง

## สำรองข้อมูล

มีไฟล์สำรอง 2 แบบ ใช้คนละจุดประสงค์

| แบบ | ใครสร้าง | มีอะไร | ใช้ทำอะไร |
|---|---|---|---|
| สำรองทั้งระบบ | ผู้ดูแลแพลตฟอร์ม | ทุกองค์กร ไฟล์แนบ และความลับแบบเข้ารหัส | กู้คืนทั้งระบบ |
| สำรองขององค์กร | เจ้าขององค์กร | ฐานข้อมูลและไฟล์แนบขององค์กรนั้น ไม่มีความลับ ไม่มีบัญชีผู้ใช้ | เก็บหรือส่งออกข้อมูลขององค์กร กู้คืนระบบไม่ได้ |

### สำรองทั้งระบบจากคอนโซล

**คอนโซลระบบกลาง → ภาพรวมระบบ → การสำรองข้อมูล**

- กดสำรองตอนนี้ได้ทุกเมื่อ
- เปิดสำรองอัตโนมัติวันละครั้งได้ เลือกชั่วโมง (เวลาไทย) และจำนวนไฟล์ที่เก็บไว้ ค่าเริ่มต้นคือปิด ตี 2 และเก็บ 14 ไฟล์
- ไฟล์อยู่ที่ `BOOKDOSE_BACKUP_DIR` หรือโฟลเดอร์ `backups` ข้างโฟลเดอร์ข้อมูล
- ไฟล์ที่อยู่ดิสก์เดียวกับข้อมูลไม่รอดถ้าดิสก์เสีย ต้องคัดลอกไปเก็บที่อื่นเอง
- ไฟล์สำรองไม่รวมฐานข้อมูล IP (`data/ip-intel/`) หลังกู้คืนให้กดดาวน์โหลดใหม่ในหน้าความปลอดภัย

### สำรองทั้งระบบจากคำสั่ง

หยุดระบบก่อน เพื่อไม่ให้ข้อมูลเปลี่ยนระหว่างสำรองหลายฐานข้อมูล แล้วรัน

```sh
python app.py --backup backups/bookdose-2026-09-26.zip
```

คำสั่งไม่เขียนทับไฟล์ที่มีชื่ออยู่แล้ว และพิมพ์รหัสของกุญแจที่ใช้ไว้ให้

### สำรองขององค์กร

เจ้าขององค์กรดาวน์โหลดได้ที่ **ตั้งค่าองค์กร → ข้อมูลและการสำรอง**

## กุญแจเข้ารหัส

ความลับทุกอย่างที่ระบบเก็บ เช่น token ของ LINE และ Facebook รหัสผ่านอีเมล API key ของ AI และความลับของการยืนยันสองขั้นตอน ถูกเข้ารหัสด้วยกุญแจของแพลตฟอร์ม

- กุญแจมาจาก `BOOKDOSE_SECRET_KEY` ถ้าไม่ตั้ง ระบบสร้างไฟล์ `data/keys/secret.key` ให้
- **ไฟล์สำรองไม่มีกุญแจอยู่ข้างใน** มีเฉพาะค่าที่เข้ารหัสแล้วและรหัสประจำกุญแจ
- เก็บกุญแจแยกจากไฟล์สำรอง เช่น ในตัวจัดการรหัสผ่าน ถ้าเก็บไว้ด้วยกัน ใครได้ไฟล์สำรองไปก็เปิด token ได้ทั้งหมด

### เปลี่ยนกุญแจ

1. สร้างกุญแจใหม่ด้วย `python -m backend.utils.secret_box new-key`
2. ตั้งกุญแจใหม่เป็น `BOOKDOSE_SECRET_KEY` และย้ายกุญแจเดิมไปที่ `BOOKDOSE_SECRET_KEY_OLD`
3. เปิดระบบใหม่ ค่าที่อ่านด้วยกุญแจเก่าจะถูกเข้ารหัสใหม่ด้วยกุญแจปัจจุบันเอง

## กู้คืน

### กู้คืนจากคอนโซล

**คอนโซลระบบกลาง → ภาพรวมระบบ → การสำรองข้อมูล → กู้คืน**

1. เลือกไฟล์ที่คอนโซลเก็บไว้ หรืออัปโหลดจากเครื่อง
2. ระบบแสดงก่อนว่าจะเกิดอะไร องค์กรไหนถูกแทนที่ เพิ่ม หรือหายไป จำนวนเคสตอนนี้เทียบกับในไฟล์ ใครจะเข้าสู่ระบบได้หลังกู้คืน และเครื่องนี้มีกุญแจเปิดความลับในไฟล์หรือไม่
3. พิมพ์ชื่อไฟล์เพื่อยืนยัน
4. ระบบสำรองสภาพปัจจุบันไว้ก่อนเสมอ (ไฟล์ `bookdose-before-...zip` ไม่ถูกลบอัตโนมัติ) ถ้าเลือกไฟล์ผิด กู้คืนจากไฟล์นี้กลับได้
5. หลังกู้คืน ทุกคนรวมถึงผู้ดูแลต้องเข้าสู่ระบบใหม่

### กู้คืนจากคำสั่ง

กู้คืนไปยังโฟลเดอร์ข้อมูลที่ยังว่างเท่านั้น ระบบไม่เขียนทับข้อมูลเดิม

```sh
mkdir -p restored-data/keys
cp <ที่เก็บกุญแจ>/secret.key restored-data/keys/
BOOKDOSE_DATA=./restored-data python app.py --restore backups/bookdose-2026-09-26.zip
BOOKDOSE_DATA=./restored-data python app.py
```

ถ้าใช้ `BOOKDOSE_SECRET_KEY` ให้ตั้งค่าเดิมแทนการวางไฟล์กุญแจ บน Windows ใช้ `set BOOKDOSE_DATA=restored-data` ก่อนรันคำสั่ง

ถ้าเครื่องไม่มีกุญแจที่เปิดความลับในไฟล์ได้ การกู้คืนหยุดก่อนเขียนอะไรลงดิสก์ และบอกรหัสกุญแจที่ต้องใช้

### เมื่อกุญแจหาย

```sh
BOOKDOSE_DATA=./restored-data python app.py --restore <ไฟล์สำรอง> --new-key
```

กู้ข้อมูลได้ทั้งหมดยกเว้นความลับ หลังจากนั้นต้องกรอก token ของทุกช่องทาง อีเมลของแพลตฟอร์ม SMS และ API key ของ AI ใหม่ บัญชีที่ใช้แอปยืนยันสองขั้นตอนต้องใช้รหัสสำรอง หรือให้ผู้ดูแลเซิร์ฟเวอร์รีเซ็ต

## รีเซ็ตการยืนยันสองขั้นตอนของทีมงาน

สำหรับทีมงานที่ทำโทรศัพท์และรหัสสำรองหายทั้งคู่ ปกติทำจากคอนโซลได้ที่ จัดการองค์กร → หน้าขององค์กร → การยืนยันสองขั้นตอนของทีมงาน ระบบถามรหัสผ่านของผู้ดูแลซ้ำ บันทึกในประวัติแพลตฟอร์มและประวัติของบัญชีนั้น และส่งอีเมลแจ้งเจ้าของบัญชี ผู้ดูแลแพลตฟอร์มรีเซ็ตบัญชีของตัวเองไม่ได้

ถ้าเข้าคอนโซลไม่ได้เลย เช่น ผู้ดูแลแพลตฟอร์มคนเดียวทำโทรศัพท์หาย ให้รันบนเซิร์ฟเวอร์

```sh
python -m backend.modules.staff_security reset <อีเมล>
```

คำสั่งลบวิธียืนยันขั้นที่สองและ Passkey ทั้งหมดของบัญชีนั้น แล้วออกจากระบบทุกเครื่อง

ถ้าเป็นผู้ดูแลแพลตฟอร์มบนเซิร์ฟเวอร์ที่บังคับสองขั้นตอน เข้าสู่ระบบได้แต่เข้าคอนโซลไม่ได้ จนกว่าจะตั้งการยืนยันสองขั้นตอนหรือ Passkey ใหม่ที่ ตั้งค่าบัญชี → ความปลอดภัย

## อัปเดตรุ่น

1. หยุดระบบ
2. สำรองข้อมูลทั้งระบบ
3. ดึงโค้ดรุ่นใหม่ ติดตั้งแพ็กเกจใหม่ถ้า `requirements.txt` หรือ `frontend/package-lock.json` เปลี่ยน
4. build หน้าเว็บใหม่
5. เปิดระบบ

ตอนเปิด API ระบบปรับโครงสร้างฐานข้อมูลเอง การปรับเป็นแบบเพิ่มอย่างเดียว ไม่ลบตารางหรือข้อมูลเดิม ตารางของฟีเจอร์ที่เลิกใช้แล้วยังอยู่ในฐานข้อมูลเก่าโดยไม่ถูกแตะ

## งานเบื้องหลัง

งานเหล่านี้เริ่มพร้อม API ครั้งเดียวต่อ process

| ชื่อ | ทำอะไร |
|---|---|
| `bookdose-ai` | งานของ AI เช่น ร่างคำตอบ Chatbot อ่านอารมณ์ สรุป และแปลภาษา |
| `bookdose-channels` | ประมวลผลข้อความที่รับจาก LINE และส่งข้อความออกทุกช่องทาง |
| `bookdose-email` | ดึงอีเมลเข้าตามรอบ และตรวจว่าช่องทางยังทำงานอยู่ |
| `bookdose-automation` | SLA ยกระดับ แจ้งเตือน ปิดเคสเมื่อลูกค้าเงียบ ลบข้อมูลตามระยะเวลาเก็บ และล้างข้อมูลหมดอายุ |
| `bookdose-security` | ตรวจกฎแจ้งเตือนความปลอดภัยทุกนาที ล้างเหตุการณ์เก่า และแจ้งผู้ดูแลเมื่อเซิร์ฟเวอร์มีปัญหา |
| `bookdose-traps` | บันทึกเหตุการณ์กับดักใน thread แยก คำขอปกติจึงไม่ช้าลง |

ดูว่างานไหนทำงานรอบล่าสุดเมื่อไรได้ที่ **คอนโซลระบบกลาง → ภาพรวมระบบ**

## สิ่งที่ระบบแจ้งผู้ดูแลเอง

เมื่อตั้งอีเมลของแพลตฟอร์มแล้ว ระบบส่งอีเมลถึงผู้ดูแลแพลตฟอร์มเมื่อ

- งานเบื้องหลังหยุดทำงาน ดิสก์ใกล้เต็ม คำขอล้มเหลวผิดปกติ หรือสำรองข้อมูลครั้งล่าสุดไม่สำเร็จ (แจ้งซ้ำไม่เกินทุก 6 ชั่วโมงระหว่างที่ยังเป็นอยู่ และแจ้งใหม่ถ้าเกิดขึ้นอีกหลังกลับมาปกติ เรื่องสำรองข้อมูลถือว่าปกติเมื่อสำรองครั้งถัดไปสำเร็จ)
- มีการแจ้งเตือนความปลอดภัยระดับวิกฤต หรือกับดักถูกแตะ ดู [การเฝ้าระวังและกับดัก](security/monitoring-and-traps.md)
- พบช่องโหว่ระดับสูงหรือวิกฤตในไลบรารีที่เซิร์ฟเวอร์ใช้ ระบบตรวจกับ OSV.dev วันละครั้ง ส่งไปเพียงชื่อและรุ่นของแพ็กเกจ

ส่วนเจ้าขององค์กรได้อีเมลและแจ้งเตือนในกระดิ่งเมื่อช่องทางขององค์กรหยุดทำงานเกินช่วงผ่อนผัน ดู [ภาพรวมช่องทาง](features/channels/README.md)

## พื้นที่ดิสก์

- ผู้ดูแลแพลตฟอร์มตั้งเพดานพื้นที่ของแต่ละองค์กรได้ (ไฟล์แนบรวมกับไฟล์ฐานข้อมูล)
- เมื่อถึงเพดาน ระบบปฏิเสธเฉพาะการอัปโหลดใหม่ การอ่านและการตอบลูกค้ายังทำงานตามปกติ
- ภาพรวมระบบเตือนเมื่อดิสก์ทั้งเครื่องเหลือน้อยกว่า 10%
- องค์กรที่ไม่มีใครใช้และไม่มีเคสใหม่ 90 วัน แสดงในรายการ **องค์กรที่หลับ** ให้ผู้ดูแลติดต่อเจ้าของหรือระงับ
