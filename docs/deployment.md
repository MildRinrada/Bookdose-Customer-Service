# นำขึ้นเซิร์ฟเวอร์

เอกสารนี้สำหรับคนที่จะเปิดระบบให้ผู้ใช้จริงเข้าจากอินเทอร์เน็ต ถ้ายังไม่เคยเปิดระบบบนเครื่องตัวเอง อ่าน [วิธีรันโค้ด](getting-started.md) ก่อน

## สิ่งที่เซิร์ฟเวอร์ต้องมี

ระบบมี 2 บริการที่ต้องรันพร้อมกัน

| บริการ | ต้องการ |
|---|---|
| หน้าเว็บ (Next.js) | Node.js 20 ขึ้นไป เปิดสู่สาธารณะผ่าน HTTPS |
| API (Python) | process ที่รันค้างตลอดเวลา และดิสก์ถาวรสำหรับโฟลเดอร์ข้อมูล |

API ต้องเป็น **process เดียวที่รันค้าง** เพราะ

- ฐานข้อมูลเป็น SQLite เก็บเป็นไฟล์บนดิสก์
- งานเบื้องหลัง เช่น ส่งข้อความออก LINE รับอีเมล และ SLA ทำงานใน process ของ API
- การจำกัดคำขอและ WebSocket เก็บสถานะในหน่วยความจำ

โฮสต์แบบ serverless ที่ปลุก function ขึ้นมาเฉพาะตอนมีคำขอ และไม่มีดิสก์ถาวร (เช่น Vercel) จึงรันได้แค่หน้าเว็บ รัน API ตามโครงสร้างปัจจุบันไม่ได้ ถ้าจะใช้โฮสต์แบบนั้น ต้องย้ายฐานข้อมูลออกไปเป็นบริการภายนอกและแยกงานเบื้องหลังออกก่อน ซึ่งเป็นงานใหญ่

## ค่าที่ต้องตั้งบนเซิร์ฟเวอร์จริง

| ตัวแปร | ตั้งที่ | เหตุผล |
|---|---|---|
| `BOOKDOSE_SECRET_KEY` | API | กุญแจเข้ารหัส token ทุกช่องทาง ถ้าไม่ตั้ง กุญแจจะเป็นไฟล์อยู่ในโฟลเดอร์ข้อมูล ซึ่งติดไปกับทุกการคัดลอกข้อมูล |
| `BOOKDOSE_PROXY_SECRET` | ทั้งสองฝั่ง ค่าเดียวกัน | ให้ API เชื่อโดเมนและ IP ของผู้ใช้เฉพาะคำขอที่มาจากหน้าเว็บของเรา |
| `BOOKDOSE_SETUP_TOKEN` | API | กันคนอื่นสร้างผู้ดูแลแพลตฟอร์มก่อนคุณ |
| `BOOKDOSE_DATA` | API | ชี้ไปที่ดิสก์ถาวร |
| `BOOKDOSE_API_URL` | หน้าเว็บ ตอน build | ที่อยู่ของ API ค่านี้ถูกเขียนลงไฟล์ตอน `next build` |
| `BOOKDOSE_TRUST_FORWARDED_FOR` | หน้าเว็บ | ตั้งเป็น `1` เมื่อมี load balancer อยู่ด้านหน้า เพื่อให้การจำกัดคำขอนับแยกตามผู้ใช้ |

เปิด API ด้วย `--secure-cookies` เมื่อให้บริการผ่าน HTTPS

## build หน้าเว็บสำหรับใช้งานจริง

```sh
cd frontend
npm ci
npm run build
npm start
```

หรือใช้ผลลัพธ์แบบ standalone ใน `.next/standalone`

1. คัดลอก `.next/static` ไปที่ `.next/standalone/.next/static`
2. คัดลอก `public` ไปที่ `.next/standalone/public`
3. เปิดด้วย

```sh
cd .next/standalone
PORT=3000 HOSTNAME=0.0.0.0 node server.js
```

หน้าเว็บส่งต่อทั้งคำขอปกติและ WebSocket (`/api/realtime/*`, `/api/public/<org>/guest/realtime`) ไปที่ API เอง ไม่ต้องมีตัวห่อเพิ่ม แต่ reverse proxy หรือ load balancer ที่อยู่หน้า Next.js ต้องส่งต่อ header `Upgrade` และ `Connection` ของ WebSocket ด้วย

## HTTPS และโดเมน

- ผู้ใช้ต้องเข้าผ่าน HTTPS เท่านั้น
- API ต้องไม่เปิดสู่อินเทอร์เน็ตโดยตรง ให้รับเฉพาะคำขอจากหน้าเว็บ
- Webhook ของ LINE และ Meta รวมถึง Redirect URI ของ OAuth อีเมล ต้องเป็นโดเมน HTTPS สาธารณะของหน้าเว็บ ใช้ localhost ไม่ได้
- ตั้ง **คอนโซลระบบกลาง → ตั้งค่าระบบ → อีเมล** ให้ส่งได้จริง ไม่อย่างนั้นอีเมลยืนยันการสมัคร คำเชิญ ลืมรหัสผ่าน และการแจ้งเตือนความปลอดภัยจะไม่ถึงใคร

## เช็กลิสต์ก่อนเปิดให้ผู้ใช้จริง

- [ ] ตั้ง `BOOKDOSE_SECRET_KEY` และเก็บสำเนากุญแจไว้คนละที่กับไฟล์สำรอง
- [ ] ตั้ง `BOOKDOSE_PROXY_SECRET` ให้ตรงกันทั้งสองฝั่ง
- [ ] ให้บริการผ่าน HTTPS และเปิด API ด้วย `--secure-cookies`
- [ ] API รับคำขอจากหน้าเว็บเท่านั้น
- [ ] จำกัดสิทธิ์โฟลเดอร์ข้อมูลให้เฉพาะบัญชีที่รันเซิร์ฟเวอร์ (บน Windows ต้องตั้ง ACL เอง)
- [ ] ตั้งอีเมลของแพลตฟอร์มและทดลองส่งจริง
- [ ] เปิดการยืนยันสองขั้นตอนให้บัญชีผู้ดูแลแพลตฟอร์มทุกบัญชี
- [ ] เปิดสำรองข้อมูลอัตโนมัติ และทดลองกู้คืนอย่างน้อยหนึ่งครั้ง ดู [ดูแลระบบ](operations.md)
- [ ] เปิดหน้า **คอนโซลระบบกลาง → ความปลอดภัย → ตรวจสุขภาพ** แล้วแก้ทุกข้อที่เตือน

## นำขึ้น Render

โปรเจกต์มีไฟล์ `render.yaml` เตรียมไว้ 2 บริการในภูมิภาคสิงคโปร์

| บริการ | ชนิด | หน้าที่ |
|---|---|---|
| `bookdose-customer-service` | Web Service (Node.js, โฟลเดอร์ `frontend/`) | หน้าเว็บ เปิดสู่สาธารณะ |
| `bookdose-api` | Private Service (Python) | API และข้อมูล พร้อมดิสก์ถาวร 1 GB เข้าจากอินเทอร์เน็ตโดยตรงไม่ได้ |

ทั้งสองบริการใช้ `BOOKDOSE_PROXY_SECRET` ค่าเดียวกัน Render สุ่มให้ใน Environment Group `bookdose-proxy` ส่วน `BOOKDOSE_SETUP_TOKEN` Render สุ่มให้บริการ API

**ค่าใช้จ่าย:** ทั้งสองบริการใช้แผนแบบเสียเงิน (0.5 CPU, 512 MB) และดิสก์ถาวรต้องเสียเงิน ใช้แผนฟรีไม่ได้ เพราะแผนฟรีไม่มีดิสก์ถาวร ข้อมูลจะหายทุกครั้งที่ restart ตรวจราคาล่าสุดที่เว็บไซต์ของ Render ก่อนกดยืนยัน

### ขั้นตอน

1. ใน Render Dashboard เลือก **New → Blueprint** แล้วเลือก repository และ branch `main` Render จะอ่าน `render.yaml`
2. ตรวจรายการบริการและค่าใช้จ่ายก่อนกดยืนยัน
3. รอจนทั้งสองบริการขึ้นสถานะ **Live** แล้วเปิด URL HTTPS ของ `bookdose-customer-service`
4. ในบริการ `bookdose-api` เปิด **Environment** แล้วดูค่า `BOOKDOSE_SETUP_TOKEN`
5. เปิดเว็บไซต์ กรอกข้อมูลผู้ดูแลแพลตฟอร์ม และวางค่าดังกล่าวในช่อง **รหัสตั้งค่าระบบจากผู้ดูแลโฮสต์**
6. หลังสร้างบัญชีแรกแล้ว ขั้นตอนตั้งค่าครั้งแรกปิดเอง

บน Render ระบบไม่ยอมตั้งค่าครั้งแรกถ้า `BOOKDOSE_SETUP_TOKEN` ว่างหรือสั้นกว่า 32 ตัวอักษร

### ตรวจหลังนำขึ้น

- เข้าสู่ระบบผ่าน HTTPS สร้างเคสทดสอบ และลองรับส่งข้อความจากหน้าลูกค้า
- สั่ง restart บริการ `bookdose-api` แล้วตรวจว่าบัญชีและเคสทดสอบยังอยู่ `BOOKDOSE_DATA` ต้องเป็น `/var/data/bookdose` และดิสก์ต้อง mount ที่ `/var/data`
- Health check ของหน้าเว็บใช้ `/api/bootstrap` ซึ่งผ่านทั้งหน้าเว็บและ API จึงตรวจได้ทั้งการส่งต่อคำขอและการอ่านฐานข้อมูล

### อัปเดตรุ่น

Blueprint ปิด auto-deploy ไว้ หลัง push โค้ดรุ่นใหม่ ให้เลือก **Manual Deploy → Deploy latest commit** ทีละบริการ ข้อมูลบนดิสก์ถาวรยังอยู่ แต่อาจหยุดบริการสั้น ๆ ระหว่าง deploy บริการ API ต้องมี 1 instance เท่านั้น

ข้อมูลเคส ไฟล์แนบ และความลับอยู่บนดิสก์ถาวร ไม่อยู่ใน GitHub การลบบริการหรือดิสก์ทำให้ข้อมูลหาย ต้องสำรองก่อนทุกครั้ง
